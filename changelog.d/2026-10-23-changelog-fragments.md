- **A changelog entry is now one small file per pull request, rolled into the big list when it is safe (2026-10-23).** Every pull request used to append its entry at the top of `CHANGELOG.md` - one shared line, so two pull requests always conflicted and every merge to `main` dirtied the rest; a conflicted pull request gets no CI, and re-clearing one costs a fresh ~71-minute `frontend` run (one night lost six). Now a pull request writes ONE bullet file under `changelog.d/` (`YYYY-MM-DD-<slug>.md`) and never touches `CHANGELOG.md`; on a quiet `main`, `py -3 tools/roll_changelog.py` inserts the bullets newest first under "Not in a numbered version yet" and removes the fragment files, in ONE pull request with nothing else in it. `--check` validates a fragment's name and shape on every PR and never demands that it has already been rolled (that would fail the very pull requests the fragments exist for); `--dry-run` shows the insertion and writes nothing. The roll is deliberate, never automatic, and idempotent. Proven by `backend/test_roll_changelog.py` (20 checks: the good shape, every bad shape named one by one, newest-first insertion, existing entries kept, fragments removed only after the text is read back, a second roll is a no-op, dry-run writes nothing, the real exit codes).
