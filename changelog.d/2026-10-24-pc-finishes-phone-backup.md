- **The PC finishes a backup the phone started (2026-10-24).** The owner's decision was "let the PC finish a backup the phone started": the phone may still ask for one, and the write stays the PC's own act. Settings, Backups now shows "A backup was started from your phone" while a run is waiting - only while one is, never for an expired one - with a recovery-code field and a **Write it** button; the code it takes is the one the phone showed, and the write goes through the existing PC-only `POST /api/backup/commit`, so no new route, no approval card, and the 403 a phone gets is unchanged. `GET /api/backup` from this PC now carries `prepared: {at, expires_at}` - the two times and nothing else, never the code or the run id. Two fixes came with it: a run is claimed under the module's lock before the write, so two presses write ONE file (they used to write two with the same code, and the second could push an older backup out of the five kept), and the phone's words stop claiming a backup exists - its finish label says the PC finishes it, and a refusal points at Settings, Backups instead of telling him to ask again, which never worked. The phone's screen, live run and TalkBack wording are a field-test row, not a pass.
