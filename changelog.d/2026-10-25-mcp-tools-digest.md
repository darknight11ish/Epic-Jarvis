- **A changed MCP `tools/list` asks the owner again (2026-10-25).** Next to the existing start fingerprint, `jarvis_mcp.py` now remembers a 32-byte SHA-256 of each server's normalized `tools/list` result in `mcp-approved.json`, and a later list whose digest differs raises the same start card again (the server is stopped, the old yes is forgotten, and nothing new is written without a person's yes). Only the 64-character hex digest is stored - never the tools/list text, a tool name, a description or a schema - and tools are put in name order first, so a server that reorders the same list does not ask. A record with no digest or a malformed one is treated as unconfirmed and asks (fails safe), so an approval written before this check asks once and then records its digest. `backend/test_mcp_digest.py` proves the stored shape, the no-card unchanged path, the re-ask and refused-change path, and the missing/malformed digest fallback against the real fake server.
