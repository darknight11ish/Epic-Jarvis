- **A schedule job now remembers the private turn it was written in (2026-10-26).** A job, to-do, timer or reminder created or edited while Jarvis's private latch was on stores `source_taint = "read_outside"` in a new `jobs` column (added by the existing migration loop, so an old schedule.db opens exactly as before and its rows read as trusted). A snooze copy inherits the mark, a repeating job keeps it when it re-arms, and firing the row replays it through `jarvis_gate.latch_taint(why="scheduled_task:read_outside")` once, before anything the row can influence runs - so the taint is no longer lost when the latch's own 30 minutes expire. No `on_fire` callback in this checkout can start an agent turn or run a tool today, so this is defence in depth for a future one rather than a fix for a live exploit.
