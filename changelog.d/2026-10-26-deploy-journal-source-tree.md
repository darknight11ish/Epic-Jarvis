- **The backend deploy journal now names the tree it deployed (2026-10-26, tooling).** `tools/reconcile_live_backend.py --apply` writes `source_ref`, `source_commit_sha` and `source_tree_sha` (`git rev-parse <ref>^{tree}`) into the backup folder's `_journal.json` before the first live write, so the files on the owner's PC can be matched to the approved commit by tree hash alone: a tree hash is content-addressed, so a rebase, a squash or a merge that rewrites the commit SHA leaves it unchanged, and one command (`git rev-parse <candidate>^{tree}` against `source_tree_sha`) replaces trusting a note. The keys are additive - a version-1 journal written by the older tool has none of them and still loads and rolls back - and a ref git cannot peel is refused with nothing written rather than journaled without its proof. Measured: the 23 new checks in `backend/test_reconcile_live_backend.py` (334 in all) prove the recorded value is exactly `git rev-parse <ref>^{tree}` against a real temporary git repository, that a dry run writes no journal at all, and that a source-less old journal still restores.
