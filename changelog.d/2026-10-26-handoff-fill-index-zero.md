- **The owner-secret hand-off can fill a password field that is the first control in its window (2026-10-26).** Two comparison bugs in the fill path, found by the live field test one after the other: the stored walk index 0 was read as "missing", so a real password field was re-measured as "no longer password-masked" and the fill was voided with nothing typed; and the target's stored id was matched against the wrong part of the id, so the engine would have voided with "the focused input control changed". Both checks are fixed and pinned by tests, and the created-measurement refusals now carry the failing COM status (`winerror` when there is no `hresult`).
