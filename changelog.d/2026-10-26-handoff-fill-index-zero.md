- **The owner-secret hand-off can fill a password field that is the first control in its window (2026-10-26).** Two comparison bugs in the fill path, found by the live field test one after the other: the stored walk index 0 was read as "missing", so a real password field was re-measured as "no longer password-masked" and the fill was voided with nothing typed; and the target's stored id was matched against the wrong part of the id, so the engine would have voided with "the focused input control changed". Both checks are fixed and pinned by tests, and `UiaMeasurementError` now records the exception's `winerror` when it has no `hresult`, a value kept on the in-process error only - the create refusal still answers 409 with the same fixed `E_*` reason_code and a plain sentence, so the response is unchanged.
