- **A private chat can no longer pick up a stored "remind me next time" reminder, and the reminders that come due because you are at the PC now say which of them were written while the gate was tainted (2026-10-26, Ruling 2.3 residuals).** Two small backend fixes, no new route, setting, card or permission. First, `jarvis_schedule.due_active_reminders()` is a read-only polling getter, so it still latches nothing - but every reminder it returns now carries the row's own stored mark (`"source_taint": ""` for an ordinary row, `"read_outside"` for a row written while the gate taint was active), so a caller that ACTS on a reminder can latch at that moment instead of the getter guessing. Second, a private chat no longer works out a stored "remind me next time" reminder at all: the end-of-turn write was already skipped for private turns, but the note could still be dressed into the private prompt by a direct caller passing `private=True` with a `"typed"` provenance; that lookup is now gated on the private flag (fail-closed, empty answer, so every downstream use stays valid and ordinary turns are unchanged). Tests: `backend/test_schedule_taint.py` (41 passed: the key on every returned row, empty for an untainted row, `read_outside` for a row written while tainted, and the getter latched nothing) and `backend/test_private_chat.py` (130 passed: private + typed carries no stored next-time note and marks nothing brought up, while the ordinary turn still carries it and marks it once). Bite: the same tests run on the parent code fail exactly on the new checks (`every due reminder carries the source_taint key`, and `private turn: a stored next-time reminder is NOT carried into the prompt`). The two changed modules and their published-base copies are byte-identical; `backend/test_base_matches_repo.py` 119/0, `backend/test_base_regeneration.py` 39/0, `tools/check_stale_twins.py` clean. Honest limit: this is server-side plumbing only - the desktop and phone need no update, and a caller that acts on a due reminder must still latch itself (the getter deliberately cannot do it for them).
