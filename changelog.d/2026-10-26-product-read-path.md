- **The product check's READ half is built (2026-10-26).** Given the HTML of an Amazon product page captured from Jarvis's own browser session after the owner's one-time login, it reads the listing facts the page states (title, star rating, rating count, URL, ASIN) and each review's rating, date (the page's date text plus a parsed ISO date when it can be read), title, body, Verified Purchase badge, Vine label, helpful-vote count and variant line - all through the engine's own tolerant schema, so there is one schema in the project rather than a parallel one. It reports what it could not read as plain warnings (a CAPTCHA/sign-in/challenge page, a page that is not a product page, a missing listing title/rating/count, no reviews, a truncated page or review block, reviews with missing fields), and `assemble_report()` hands the records to PR #849's engine and returns its reasons report with the records kept for debugging - the "what Amazon chose to show" caveat and the quote validator stay intact. `capture_with_owner_browser()` is the named capture seam: it raises a documented `CaptureNeedsOwnerBrowser` error instead of pretending to fetch, because reading the page needs the owner's own session. Standard library only (`html.parser`, `re`, the engine module), no network, no browser import, no subprocess, no storage, no route/tool/card/app surface, nothing imports it yet. Tests: `backend/test_product_read.py` (62 checks, synthetic HTML fixtures only, every warning bite-proof, malformed/truncated markup tolerated, determinism, engine integration and quote bites, socket/urlopen network spy, AST import check).
