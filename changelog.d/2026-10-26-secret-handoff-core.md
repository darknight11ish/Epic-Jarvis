- **The owner-secret hand-off's rule engine (2026-10-26).** `backend/jarvis_secret_handoff.py` (+ byte-identical `jarvis-backend/` twin) is the state machine behind the one flow that can safely let Jarvis log in somewhere: the owner types the secret into a card the host draws, the engine refuses unless the caller's live snapshot still matches the card (same target, kind, focused control and password mask), marks a 15-minute read taint BEFORE the first character is typed, types through an injected function, and returns a receipt that names the target and never the value. Keys are canonicalised page addresses (scheme and host lower-cased, a default `:80`/`:443` dropped, `.`/`..` path segments resolved, a trailing slash dropped, query string, fragment and any `user:pass@` userinfo stripped) or pid+hwnd+window class, so a secret value can never be part of one; a caller that does not assert the card is being answered on this PC is refused, because `from_this_pc` has no safe default. No disk, database, log, clipboard, model context or tool result; the module imports no storage or logging library and its suite proves that from its own AST. The card shows the target separately from the agent's cleaned, explicitly-untrusted note, and voids with zero characters typed on any target/kind/control/password-mask change, an expired card, an empty or whitespace-only value, or an unproven caller. A typing failure is reported in the module's own fixed words, so the injected error cannot echo the value. `backend/test_secret_handoff.py`: 93 checks, 0 skipped, 0 failed, no GUI and no network. Nothing imports the module yet - the wiring into `jarvis_ui_control.py` / `jarvis_browser_control.py`, the host-only route and the HUD card are the next slice; `docs/DESIGN-SECRET-HANDOFF.md` records both halves and the honest limits that Python cannot wipe memory, that the snapshot is caller-supplied until the wiring measures it, and that the taint is in-memory only.
