- **Every Jarvis home-screen widget ends in words instead of a spinner, and the release-build defect that stopped it drawing at all is fixed (2026-10-27).** On the owner's Pixel and OnePlus all five widgets sat on a bare spinner for ever while the app itself was connected and drawing live PC data. The spinner was not the app's: it was the launcher's `initialLayout`, Glance's own `glance_default_loading_layout`, because no Glance worker could ever start in the release APK. R8 had stripped `androidx.work.OverwritingInputMerger`'s no-arg constructor; WorkManager instantiates that class **by name**, so every job failed with `Could not create Input Merger` and `provideGlance` never ran (proved on the connected phone: the logcat lines, and the shipped APK's own dex, which has the class and no `<init>` at all - `work-runtime-2.7.1`'s consumer rule `-keep class * extends androidx.work.InputMerger` keeps the class but not its constructors). `app/proguard-rules.pro` now keeps those constructors, the same class of fix as the `WorkDatabase` keep rule already beside it, one reflective call further along. So that this can never again look like "buffering", three more things changed: all five widgets' `initialLayout`/`previewLayout` now point at a new `res/layout/widget_initial.xml` that says "No update yet — open Jarvis to connect" instead of showing a ProgressBar; every widget draw is decided by one pure `WidgetStates` state machine with no loading state at all; and the only two waits a widget makes - the runtime starting up and `GET /api/widgets/show` - are bounded at 4 s and 8 s, so a slow Keystore or an unreachable PC draws "Jarvis could not start" or "Could not reach your PC" rather than an open-ended wait. App lock is unchanged and its "hide the card's words" rule is now a pure function (`ApprovalWidgetRules.cardTitle`/`cardDetail`) instead of logic inside the composable. `WidgetStatesTest` adds 13 JVM tests: every approvals/board/link combination lands in exactly one terminal state, a genuinely blocked wait still returns inside its budget, the timeout/error sentences, App lock hiding the card even when it has words, a real `/api/pending` row still decoding and reaching the card, and no widget XML naming Glance's spinner. **Not proven here:** the widgets on a phone - no APK built from this branch was installed, so the field-test step is the CI-built APK, add the five widgets, and expect terminal states.
