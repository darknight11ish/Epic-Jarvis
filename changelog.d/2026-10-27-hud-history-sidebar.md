- **The HUD's History column icon opens a DeepSeek-style conversation panel: Pinned, one section per project, then Untagged, with a search box, a sort, and Open/Pin/Move to project/Delete on every row (2026-10-27).** The owner asked for "a history tab with a column icon that opens up a menu that looks like all the coversations in the deepseek harness on desktop for the jarvis HUD ... both should have pinnable chats, project organization by chat, and more". The panel is ONE new module (`jarvis-desktop/src/hud-history.js`) plus the row-action table it shares with the Brain (`jarvis-desktop/src/history-actions.js`), loaded by the page with `<script type="module" src="hud-history.js">` - still ONE external file each, so this page's inline-script count and every CSP hash stay exactly as they were - and a `window.hudHistoryHost` object at the end of the page's own last script: the module adds its own `#rail-history` button to the left rail beside Presets and Live, its panel (`#history-sidebar`), its stylesheet and its row menu, and the page's own markup is not touched. Pinned chats sit first and are not repeated inside their tag; then one collapsible section per chat tag - the owner's tags ARE the projects, as `docs/CHAT-TAGS-DESIGN.md` defines them, and no second "project" concept was added - then the chats with no tag under the phone's own word, "Untagged". A section shows five rows and a `Show N more sessions` row; the search box filters by a chat's NAME only (what was SAID in a chat is still the Brain's search, section 71); the sort is newest-first or A to Z; the current chat is marked. **Pinning is the PC's record, not the window's:** a `pinned` column and its moment `pinned_at` in the same encrypted `chat-history.db` every other History fact lives in, set by `POST /api/history/pin {"id", "pinned"}` (new; metadata only, no approval card; `200 {"ok", "id", "pinned", "pinned_at"}`, `400` for a body that is not exactly `{"id", "pinned"}` or a `pinned` that is not a boolean or an id that is not a string / is empty / is over 128 characters, `404` with nothing written for a chat that is gone, `503` when the history will not open - JARVIS-API section 18.3) and read back as `pinned`/`pinned_at` on every list, open and search row, so a pin survives a restart and the phone reads the same flag. The Pinned group is drawn **`pinned_at DESC, updated_at DESC`**, and pinning twice keeps the FIRST moment, so a chat that gets a message never jumps above one pinned after it. **While App lock or "Hide memory lists and chat history" is on, the list withholds every row - the pinned ones included - and the pin route answers `423` for every id**, before it looks one up, so a locked PC cannot be asked whether a chat exists (no 200-versus-404 oracle); the server applies that withholding itself through `jarvis_private_view`, and the desktop keeps its own redaction on top. **The row words are ONE copy:** `history-actions.js` holds the action labels (the Brain's own History row now reads "Delete" from it), the three sentences of the are-you-sure, and the args/body a write sends; `history-view.js` re-exports the sentence it used to own, so the Brain says the same words from the same place instead of a second copy held equal by a test. On the PC side ONE Rust command `hud_history_act` (pin, file under a tag, delete ONE chat) shares `tag_chat_body`/`delete_body` with the Brain's own commands, is refused while the private lists are hidden, held on a stale link (rule 4), raises no card, has no delete-all - and the three History reads joined `hud_proxy.rs`'s fixed allow-list with their query parsed in one place (`brain/history.rs::history_read_path`). **The panel's keyboard and screen-reader behaviour is part of it:** a row is a `<div role="listitem">` with TWO SIBLING buttons (the chat, then its `...`), never a button inside a button; ages are real `<time datetime title>` and a clock ahead of the PC is clamped; group headers are `<button aria-expanded>` and toggling one keeps the keyboard on it; Escape returns the keyboard to the `...` and a second Escape to the left column's History icon; "Show N more" focuses the first chat it revealed; and the page's global Space push-to-talk bails for `#history-sidebar, input, textarea, button, [role="menu"]` and for an open sidebar. Tests: `jarvis-desktop/tests/hud-history.mjs` (37 checks, pure Node - grouping, pinned order, ages, the cap and the one-off expansion, search, sort, the three write shapes, the shared module being the only copy, the row markup and the focus rules, and the page/Rust/shiplist wiring) and `backend/test_chat_pins.py` (71 checks against the real encrypted store - persistence across a restart, `pinned_at` keeping its first moment, the exact 400/404 refusals with no ghost row, the 423/hidden-list rule, and an old history file migrated in place). **Not done here, said plainly:** nothing is deployed to the owner's live backend or app (that needs a rebuild, `apply-patches.ps1` and the HUD whitelist deploy), the phone's half is the next lane, and a real WebView2 painting of the panel was not driven on this PC - the pure suite and the Rust/Node wiring are what is proven, and Playwright is not installed here.
