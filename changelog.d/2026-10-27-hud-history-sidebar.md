- **The HUD's History column icon opens a DeepSeek-style conversation panel: Pinned, one section per project, then Untagged, with a search box, a sort, and Pin/Move to project/Open/Delete on every row (2026-10-27).** The owner asked for "a history tab with a column icon that opens up a menu that looks like all the coversations in the deepseek harness on desktop for the jarvis HUD ... both should have pinnable chats, project organization by chat, and more". The panel is ONE new file (`jarvis-desktop/src/hud-history.js`, a classic script the page loads with `defer`, so this page's inline-script count and every CSP hash stay exactly as they were) plus a `window.hudHistoryHost` object at the end of the page's own last script: the module adds its own `#rail-history` button to the left rail beside Presets and Live, its panel, its stylesheet and its row menu, and the page's own markup is not touched. Pinned chats sit first and are not repeated inside their tag; then one collapsible section per chat tag - the owner's tags ARE the projects, as `docs/CHAT-TAGS-DESIGN.md` defines them, and no second "project" concept was added - then the chats with no tag under the phone's own word, "Untagged". A section shows five rows and a `Show N more sessions` row; the search box filters by a chat's NAME only (what was SAID in a chat is still the Brain's search, section 71); the sort is newest-first or A to Z; the current chat is marked. **Pinning is the PC's record, not the window's:** a `pinned` column in the same encrypted `chat-history.db` every other History fact lives in, set by `POST /api/history/pin {"id", "pinned"}` (new; metadata only, no approval card, `400`/`404`/`503` as written in JARVIS-API section 18.3), and read back as `pinned` on every list, open and search row - so a pin survives a restart and the phone reads the same flag; the contract is written for the phone lane, which implements the client half. Delete keeps the Brain's own are-you-sure sentence word for word (a test holds the two copies equal) and deletes only that chat. **The desktop HUD holds no pairing token** (apps security audit M2), so the three History reads joined `hud_proxy.rs`'s fixed allow-list with their query checked in ONE place (`brain/history.rs::history_read_path`), one new command `hud_history_act` carries pin/tag/delete (refused while the private lists are hidden, held on a stale link, no card, no delete-all), and the lock takes the words out of `/api/history`, `/api/history/conversation` and `/api/history/tags` while App lock or "Hide memory lists" is on, using the Brain's own redaction. Tests: `jarvis-desktop/tests/hud-history.mjs` (29 checks, pure Node - grouping, ages, the cap and the one-off expansion, search, sort, the three write shapes, and the page/Rust wiring) and `backend/test_chat_pins.py` (44 checks against the real encrypted store - persistence across a restart, the exact refusals, an old history file migrated in place). **Not done here, said plainly:** nothing is deployed to the owner's live backend or app (that needs a rebuild, `apply-patches.ps1` and the whitelist deploy), the phone's half is the next lane, and a real WebView2 painting of the panel was not driven on this PC - CI's frontend shards run the pure suite today.
