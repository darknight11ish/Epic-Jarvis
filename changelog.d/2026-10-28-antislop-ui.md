- **An Anti-Slop filter, on a switch in Settings → How Jarvis talks, for both apps (2026-10-28).** The rules are the MIT-licensed `miqdadbadjuber/anti-slop` ruleset (v3.2.23), distilled on the PC to the few that fit a local model's prompt budget: no em-dashes in prose, no AI buzzwords (seamless, revolutionary, next-generation), no decorative comment banners in code, no dead buttons, WCAG AA contrast and a visible focus ring. The desktop card has a master switch, three scope pills (Copy & answers, Code comments, Web & UI design), a During/After mode radio, a switch for the four-block Delivery Gate on a finished screen, and the three Liveliness dials (Energy, Rhythm, Motion, 1–3 each). The phone has the master switch, the em-dash box and the During/After mode, in the same words, bound to the same `GET`/`POST /api/antislop` — it deliberately does not get the scopes, the gate switch or the dials: it is a settings mirror, not a second editor, and it grows no catalogue. It now also carries **Allow em-dashes (—)**, off by default, and the phone plate has the same box: Write Like Me's own em-dash habit already wins under the voiceprint rule whether it is ticked or not, and this box is the blanket “keep them everywhere” on top of it — one field (`allow_em_dashes`) on the same route, so ticking it resets nothing else. And the card says plainly what is really enforced: the filter guides generation, then checks a fixed list in code (em-dashes, buzzwords, comment banners, dead buttons, contrast, focus rings, glass and glow caps), while layout, taste and rendered sizes are guidance only. **Neither direction raises an approval card**, because the filter changes only how an answer is worded — it opens no way out of the PC, reads no folder and takes no action — and the desktop's two commands are not held on a stale link either (the phone's writes still are, at its own layer, like its other settings). A change applies on the very next turn, emits its own `antislop` event so an open Settings window or the phone's open plate repaints without a reload, and the card says in one line what OFF costs: **0 prompt tokens**, nothing added to a prompt and nothing rewritten. Honest limits: the desktop card is bespoke, so it is not one of the generated `SETTINGS_ROWS` toggles and its spoken switch is recorded as `planned` in the controls matrix for that reason; the phone's `net/Antislop.kt` is JVM-tested but **not compiled here** — there is no Android build in this container, so CI's `phone-unit-tests` job is the first compiler; and the two registry rows the typed phrases need (`antislop`, `antislop_mode`) live in the engine slice, so `tools/check_feature_controls.py` is green only with both halves together - measured in the merged tree: 142/142 features covered, 32/32 switches, 32/32 rows.
