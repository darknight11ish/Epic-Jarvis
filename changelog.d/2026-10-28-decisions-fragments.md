- **A new decision is now one small file per pull request, folded into `docs/DECISIONS.md` when it is safe (2026-10-28).** Every pull request that recorded an owner decision appended it at the end of one 3.2 MB file, so two such pull requests always conflicted - and a conflicted pull request gets no CI at all, while re-clearing one costs a fresh `frontend` run (about 62 minutes; PR #386 is the last crossing on record). A pull request now writes ONE dated bullet under `decisions.d/` (named `YYYY-MM-DD-<slug>.md`, the same prose that used to be appended) and never edits `docs/DECISIONS.md`; on a quiet `main`, `py -3 tools/roll_decisions.py` appends the bullets at the END of the record in date order (that file is chronological oldest-first, so it is not `CHANGELOG.md`'s newest-first), keeps every existing entry, re-anchors any `docs/CLAIMS.tsv` source that cited a fragment, and removes the fragment files. `--check` validates a fragment's name, its dated bullet, that the date in the name matches the date in the bullet and that the anchor heading is still in the record, on every pull request; the roll itself is deliberate and no workflow runs it. The checkers learned the same rule: a `grep:`/`absent:` that names the record reads BOTH places, so a decision is evidence the day it is written and an `absent:` notices when a sentence comes back as a fragment; a CLAIMS source may cite either place; and a promise's own words are found wherever the record keeps them. Proven by `backend/test_roll_decisions.py` (42 checks: every bad shape named one by one, appended at the end in date order, no lost entry, idempotent, dry-run writes nothing, the CLAIMS re-anchor landing on the entry's own line, and two branches' fragments changing no file in common), `backend/test_claims.py`, `backend/test_promise_guards.py` (130 passed) and the changelog, docs-map and records-encoding checks.
