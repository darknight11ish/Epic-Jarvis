- **The HUD's faces panel has a Face size - Small, Medium or Large - that belongs to this device (2026-10-28).** The owner asked that "in the jarvis faces in the left column of the hud there should also be a size option on desktop": the panel now opens with a `Face size` row above the 25 faces (three buttons in its own `.hud-presets-item` look, `aria-pressed` and a `role="group"` like the face rows, Tab/Shift+Tab and Enter/Space all work), Medium is the default and Small/Large are 0.75x/1.25x of whatever size the current shell gives the face. ONE `--face-scale` custom property feeds every existing `#reactor` width/height rule as `calc(base * var(--face-scale, 1))` - the 232px page default, the 150px narrow page, Cockpit's 220/96/88, Studio's 48, Ambient's 320/240/190 - so no shell needed a second rule, and it is width/height rather than `transform: scale()` so the wrap reserves the bigger box instead of the face covering the log; the 48px Studio dock and the 96px pinned core were driven at all three sizes, not just counted. The choice lands in this WebView's `localStorage` under `jarvis.face.size` (the same per-device road as `jarvis.theme`), and the HUD's head script reads it before first paint, so the first frame is already the chosen size and a restart keeps it. It is a look, not a preference the PC owns: it writes no other key, changes neither the theme nor which face is worn, calls no command, adds no route and raises no card. Proven by `jarvis-desktop/tests/hud.mjs` (four new checks: every `#reactor` rule keeps its own base and multiplies the saved scale, Medium pressed by default with Large at least 1.2x and Small at most 0.8x while only the one storage key is written, the 48px Studio dock and 96px pinned core at all three sizes plus keyboard activation, and the three HUD copies byte-identical), `node tests/themes-all.mjs`, `python -B backend/test_hud_static.py` (42), `python -B tools/check_stale_twins.py` and `python -B tools/check_invoke_grants.py`, all green at the desk. **Honest limit:** the page was driven in the test harness's Chromium, not in the installed WebView2, so the first real look still needs the rebuilt app; the phone has no HUD faces panel, so there is nothing to port and `tools/check_parity.py` classifies nothing new.
