- **The HUD now offers to start the local model when its own line says the model is not running (2026-10-28).** The owner opened Jarvis from scratch, saw the model was down, and asked for "a connect button next to these notifications saying its offline". Both offline lines in the HUD now carry one: the standing "The local model isn't running on your PC." row and the "Model not running" banner. It sends the Jarvis bar's own two commands (`read_model_lane` and `start_model_lane`, under a new narrow `hud-lane` grant), so it runs the owner's own Windows logon task for the lane the chat is on and raises no approval card - the same action the bar, the widget and the phone already offer, and it cannot turn the automatic restart on. Starting is not arriving: the button says "Starting…" and the warning clears only when the lane really answers; a refusal, or a lane that never comes up, is shown in the PC's own words with the warning left standing. The button is hidden when the PC has not said, and when the HUD cannot reach the PC at all. The second half of the same day's report - "why does a powershell open automatically?" - turned out not to be the app: its Python backend is already spawned with no window, and the visible window is the owner's own Ollama lane task, which Task Scheduler draws in his session. `scripts/hide-lane-window.ps1` is the one-command fix for that (it checks by default, backs the task up, adds `-WindowStyle Hidden` only when `-Apply` is given, and reads the task back); the lane's own output still goes to `%LOCALAPPDATA%\JarvisOllama\logs\main.log`, so nothing becomes undiagnosable. Tests: `jarvis-desktop/tests/hud-connect.mjs` (27 browser-free checks, including the HUD's start loop and `lane-start.js`'s agreeing scenario for scenario, and a regression pin for the browser probe's finding that the live stream's state must not hide the button), `backend/test_hide_lane_window.py` (33 checks) and a Rust source pin in `proctree.rs` for the app's no-console facts. Not field-tested: no press has been made on the owner's PC from this branch, and the lane-window fix has been run with `-Check` only - `-Apply` is the owner's one command.
