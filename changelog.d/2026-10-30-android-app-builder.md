- **Jarvis builds an Android app and sideloads it onto the phone, with one approval card for the build and one for the install (2026-10-30).** The owner asked *"can jarvis build android apps? that i can sideload into my phone? if not add them"*; the honest answer before this was no, because milestones C (run a command), F (native Android projects) and G (install the debug APK) of `docs/APP-BUILDER-DESIGN.md` were all unbuilt. `backend/jarvis_android_builder.py` now writes a FIXED minimal Android project into one app task's copy - the Gradle files, a manifest with **no permission at all**, one WebView activity, and the owner's own `index.html` / `app.js` / `app.css` - then runs exactly `<task copy>\gradlew.bat assembleDebug` and exactly `<sdk>\platform-tools\adb.exe install -r <the apk that build made>`, each behind its own risky `ask` card naming the exact command, folder and file (`app_build_android`, `app_install_android`). A model may only supply the three web files plus a validated app name and two `#rrggbb` colours: it writes no Gradle file, no Kotlin and no manifest, so it cannot add a permission, a dependency or a network address. The environment is `jarvis_child_env`'s allowlist plus three toolchain paths (a test proves a token, key or password in the parent's environment does not reach Gradle or adb), the build's output goes to a gitignored log with only its end kept, and no other adb subcommand exists in the module - a source scan fails the suite if one is added. Measured on the owner's PC on 2026-10-30: **one real build of exactly this template, 53.6 s, a 2,469,448-byte debug APK, `BUILD SUCCESSFUL`**, `aapt2 dump badging` showing no `uses-permission` line and `apksigner` showing the Android debug key. That was a WARM build - Gradle 9.6.0 and the Android Gradle plugin were already cached on this PC - so a truly cold first build (about 130 MB of Gradle plus the plugin) is **not** measured, and the card says a first build downloads them. Honest limits, on the card and in the docs: debug key only, sideload only and never the Play Store, no per-app icon yet, no test ever runs Gradle or adb (a CI runner has no Android SDK and no phone), and the routes are PC only because the SDK and the cable are on this PC - the two CARDS still reach both apps, so the owner can approve from the phone. Routes are JARVIS-API section 168; wiring is the drop-in folder `plugins/ready/android-builder` (so **no patch**), the gate rows in `jarvis-backend/jarvis_gate.py`, two tier lines in `backend/rebuilt/jarvis-framework.toml`, and Gradle's own two wrapper files carried as beside-files (Apache-2.0, credited). Tests: `backend/test_android_builder.py`.
