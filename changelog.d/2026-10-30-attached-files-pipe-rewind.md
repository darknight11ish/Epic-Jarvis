- **Attached PDFs and Office files are readable again: the first 16 KiB of every one was being lost in transit (2026-10-30).** MarkItDown, the part of Jarvis that turns a PDF, Word, Excel or PowerPoint file into text, guesses a file's type by reading its first 16 KiB and then rewinding. A file attached to a chat reaches it on a Windows pipe, and a pipe reports that it can rewind and then silently does not - so the parser was handed the file from byte 16,384 on. Every PDF tested (22 of 22) lost text, three came back with no words at all and were refused with "it has no words in it to read" about a file that had plenty, and every Word, Excel and PowerPoint file failed outright as "Jarvis could not read it (FileConversionException)"; a 25 KB Word file reproduced that exact sentence. The child now copies the pipe into memory before the converter sees it - never written to disk - so both reading paths convert the same complete bytes. The suite's one check on the real reading path asserted only that the answer HAD an `"ok"` field, on a 32-byte fixture, so it passed on a guaranteed failure; it now asserts the answer IS ok, on a real PDF and a real `.docx` bigger than 16 KiB, read through both paths.
