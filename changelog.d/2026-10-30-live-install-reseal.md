- **A reseal tool that puts a drifted live install back on the bytes this repository ships, and repairs the installer's record it can prove (2026-10-30, Gemini's Q3 `(b')`).** The owner's install still reports **93 FAIL** rows from `selftest.py --preflight`: `scripts/apply-patches.ps1` cannot replay its stack there, so the five patched base files sit on an older intermediate state, and `_jarvis-state.json` - the installer's own record beside the backend - still holds the hashes of that older state. `tools/reconcile_live_backend.py` can move the `$SHIPPED` files but must never write the record, so this is the smaller, separate tool Q3 asked for. Dry-run by default: it reads `$SHIPPED` and every module's bytes from `--ref` (`git show`), never the working tree, compares each entry with the live folder **by bytes**, and prints what it would write, which record rows it would re-hash, and the preflight rows it counts now and after - through `backend/selftest.py`'s own `patch_states` for the patch rows, and through the same four rules `pf_modules` uses for the module rows. `--apply` copies the repository's exact bytes, keeps every replaced file as `<name>.before-reseal-<stamp>` beside it, compiles the file that is **now in the folder** (bytecode to a temporary file, so none is left behind), purges stale `__pycache__/*.pyc`, and re-runs the same comparison as its convergence proof; a write or compile failure restores every file it wrote and removes every file it created. It then rewrites **only** the record rows it can prove: a row whose file this repository ships gets the repository's hash, while `written`, `patches`, `patchList` and every untouched row stay exactly as the installer left them, and a `resealed` key records the tool, the commit and the row names. A row for a file this repository does **not** ship (the five patched base files) is never re-hashed - it is printed with both hashes and the run exits 1 - and `--rebaseline-unprovable` records the folder's own bytes for exactly those rows, the patcher's own first-run baseline rule, off by default. **It cannot reach 0 FAIL on its own and says so:** the preflight's *patch* check is about `.patch` text in the five base files, and only the patcher (or #997's targeted repair, `tools/repair_live_backend_gaps.py`) moves those rows. `backend/test_reseal_live_install.py` proves 92 checks on synthetic live folders - dry run writes nothing, apply keeps a backup and copies the bytes exactly, a stale row is corrected only for a file the tool owns, an ambiguous or absent file is refused, an unshipped file is never touched, a second apply changes nothing, a corrupted live file is replaced and compiles, and the real `pf_modules` goes from three FAIL rows to one (the file the repository does not ship) with the tool's own mirror agreeing on both numbers.
