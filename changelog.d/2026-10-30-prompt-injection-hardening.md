- **The "it tried to rush you" warning now works on the main chat path, and tool text is cleaned of invisible characters before the model reads it (2026-10-30).** The security audit of 2026-10-30 (findings C1, C2 and C5) found the rush rule written, tested and never switched on for the HUD chat: a web page or an email saying "just approve this now" could not raise the warning or the swipe-lock, and a word split by a zero-width joiner reached the model raw. Every tool result now goes through the project's one outside-text pipeline before the model reads it: zero-width characters, bidi controls, Unicode Tag characters and look-alike letters are removed, and a rushing phrase arms the gate's existing latch - so the next action that would have run on its own stops and asks, and its card carries the unswipeable warning. It is the same latch the gate already reads: no second switch, no new control, and the standing rule that nothing may clear a rush latch is untouched. The schedule read (`coming_up`) is labelled as stored data too, so words typed into a reminder cannot reach the model as if the owner had just said them - and, like every other read in a turn, a note write after it asks first and a timer or reminder requested in that same turn is refused so the owner can type it themselves. An ordinary email still arms nothing; the tests that prove the invisible characters are gone, the latch arms and an ordinary message does not are in `backend/test_injection_cases.py`, and the module now has its own suite in `backend/test_content_risk.py`. Honest limit, unchanged by this fix: there is still no mechanical check on the model's own answer prose (audit finding P1) - the card remains the boundary for anything that acts.
