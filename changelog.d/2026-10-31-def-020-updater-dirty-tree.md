- **DEF-020: the updater no longer installs the signed release over uncommitted work - on either side of the release (fixed in code, machine-proven).** The route decision asked only about commits: a folder standing on the release's own commit answered "same" even with uncommitted work on top of it, so `update-jarvis.ps1` installed the signed release over that work and silently replaced it. The same shape existed one branch over: a folder BEHIND the release was installed over without looking at its working tree. `Get-LocalVsRelease` now asks `git status --porcelain --untracked-files=no` once, before the identity questions, and uses it wherever the signed release could be installed over uncommitted work: standing ON the release's commit with a tracked change (staged or not, or a deletion) answers **"dirty"**, and standing BEHIND the release with uncommitted work answers the new sixth answer **"release-ahead-dirty"** - both build the folder instead, and the caller says why in each shape ("this folder is behind the released code, but it has uncommitted changes - installing the release would replace those changes. Building this folder instead, so they are kept"). A CLEAN folder at the commit still installs the signed release, and a CLEAN folder behind it still installs it too - the ordinary update path is unchanged; a genuinely newer local build is still never downgraded. Untracked files are deliberately ignored on purpose (build output and scratch, and a build does not ship them), and a failing `git status` counts as dirty rather than assuming the tree is clean. Pinned in `scripts/test-update-jarvis.ps1` (21 -> 35 checks): throwaway repos at the release commit and behind it, each with a tracked change, with only a staged change, with an untracked file alone, and clean, must answer the right one of "dirty"/"release-ahead-dirty"/"same"/"release-ahead"; plus source pins that the caller branches on both new answers and says why. Measured with the same harness: against the pre-fix updater 31 passed / 4 failed for the behind half (the dirty-behind cases come back "release-ahead", exit 1); against this branch 35 passed / 0 failed, exit 0, in both pwsh 7.6.9 and Windows PowerShell 5.1.
