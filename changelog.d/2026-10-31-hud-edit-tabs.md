- **"Edit HUD" is simplified into tabs, and the cards' control rows are no longer all open at once (2026-10-31).** The owner: "the edit hud needs to be way more simplified with the options under menu tabs instead of everything all at once." Entering Edit HUD now shows a slim bar - title, one sentence ("Drag a card, or open its options."), and the same Undo / Reset to preset / Discard changes / Done - with four tabs: **Cards** (the default: a compact list of the on-screen cards; picking one, or clicking a card on the canvas, moves that card's OWN controls into one selected-card editor - the same buttons, disabled states and handlers, including "always visible" for cards that can never be hidden), **Presets** (the layout presets with the chosen one outlined using the same `is-chosen` state as the Presets menu; Apply is the existing reset-to-preset action), **Panels** (the existing move/order controls grouped by rail, in one place), and **Advanced** (hidden and folded cards with the existing Show/Expand actions, and the cards that can never be hidden). Nothing is dropped or re-implemented: drag-to-place, resizing, folding, hiding, the keyboard routes, Esc-to-exit and the undo/reset/discard semantics are unchanged, and there is no new route - the layout normalizer and persistence are untouched. Each card's own controls stay clickable on the canvas while editing (CI's layout and field tests drive them there); picking a card's body moves that SAME toolbar into the bar's editor, so the full row is not what greets you on entry and every control is reachable either way. Tests: a new browser-free pin (`tests/hud-edit-tabs.mjs`, 9/9 here) holds the slim bar, the four tabs in order, Cards as the default, the moved-same-toolbar rule, the `is-chosen` preset outline + existing Apply, the Panels/Advanced existing actions, no network call and the three-copy rule; the Playwright suites (`hud-edit-fieldtest.mjs`, `hud.mjs`) drive the real page, with their region/control waits adjusted for the tab layout. The tab branch matches a real role=tab button, not <body>, so Done/Discard/Reset keep working after the tabs rewrite (CI hud-edit-fieldtest persistence caught the earlier form, which swallowed those clicks as a tab switch).
