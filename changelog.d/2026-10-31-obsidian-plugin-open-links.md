- **The Obsidian plugin can now hand back a read-only `obsidian://open` link to the note you are reading (2026-10-31).** A tenth command, **Copy an Obsidian link to this note (read-only)**, puts an `obsidian://open?vault=<vault name>&file=<vault-relative path>` link on the clipboard (a `#Heading` can follow the file to jump to a section), so a person or a Jarvis answer can send the owner straight back to that exact note. The plugin builds **only the `open` action**: it never builds Obsidian's `new`/`daily`/`unique` actions or the `prepend`/`append` they take, because those write a note immediately and would bypass the one-card model, the File Guardian copy and Undo - and a unit test plus a source-text safety test now pin that (the URI builder is pure and tested for vault/path/heading encoding, and no URI write action may appear in `src/`). Version `0.1.2`; the wave-1/wave-2 behaviour, safety model, routes and UNTESTED list are unchanged. Honest limits: still never loaded by Obsidian (the app is installed on this PC but this work never opened it), the clipboard write and the copied link opening a real note are UNTESTED, and the desktop/chat direction of "Jarvis sends you back to a note" belongs to those lanes - this plugin only creates the link.
