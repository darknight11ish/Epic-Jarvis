- **Obsidian plugin packaging follows the binary rule: source, `manifest.json` and a committed `main.js`, with a build-drift check and no packaged zips in the tree (2026-10-31).** The committed `main.js` stays exactly where it is, on purpose, so the owner can copy `obsidian-plugin/` into a test vault without installing Node or running a build. `npm run check:build-drift` (a new script running `node tests/check-build-drift.mjs`) rebuilds the bundle with `node esbuild.config.mjs` and fails if `obsidian-plugin/main.js` changes at all - the zero-drift proof that the committed file is exactly the build of `src/` - and the exact step a CI lane could add to the informational `audit` job (`cd obsidian-plugin`, `npm ci --no-audit --no-fund`, `npm run check:build-drift`; Node 20 is enough and it takes seconds) is written in the README, although this change edits no workflow file. No packaged binaries are tracked: `*.zip` and `dist/` are in `obsidian-plugin/.gitignore`, packages are built into a scratch/release folder and never committed, and their sizes and SHA-256 values are recorded in `BUILD-VERIFICATION.txt` (0.1.3's exact size and SHA-256 are recorded there after the package is built; 0.1.2: 86,666 bytes, SHA-256 `7FA8BE04ADF83ED3BA50826C32D95F249B7164743D349D85F08479A5CB1EE5E6`; 0.1.1 kept for history: 80,765 bytes, SHA-256 `52504033CD3D6529129C868623109D013D17FABE40F2CB104F0AD03685146AB1`).
