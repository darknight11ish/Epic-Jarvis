- **An approved card is no longer forgotten when the app's stream dies while it waits (2026-11-01).** The owner's report - approve the card, hear "Approved. Carrying on.", and get an answer that clearly never used the thing that was approved - was measured on his own run at 15:44-15:47 that day. That sentence is the app's own fixed line for a real yes (`jarvis_card_words.VOICE`, `CARD_VOICE` in the HUD page), never the model's, so it proves only that the gate recorded the tap. What happened next is the bug: `jarvis_gate.decide()` consumed the tap and NULLed the card's prompt and detail, the turn then found `out.gone` (the phone had closed its stream while the card waited) and unwound through `ClientGone` without running the approved tool, and the app re-sent the same conversation 91 ms later with nothing on the PC remembering the yes - so the new turn made one model round, ran no tool and answered in 17 tokens. `jarvis_agent.py` now keeps that one approved step for that one conversation, in memory only, and runs it once at the start of the next turn for the same conversation through the same `prepare()`/`gate`/`execute()` contract, putting its result in the transcript the model answers from. It is keyed by the card's own id, so a client that re-sends twice runs it once; it is dropped after ten minutes, never crosses into another conversation, never survives a restart, and is never written for a denied, timed-out, expired or never-answered card (`owed_record()` asks `_a_person_said_yes()` for itself rather than trusting a caller). The gate contract is unchanged - one card per action, nothing runs before its yes - and the carried step raises no second card because it already has one; a carried step that fails says so in code's own words and never claims it ran. Both the record and the replay are in the audit log as `agent.owed` / `agent.owed_ran` (names and ids only, never the card's words or the question). `jarvis_agent.py` is a module this repository ships whole (it is in `$SHIPPED` and no patch targets it), so the change is delivered as the whole file in `backend/` and `jarvis-backend/`, not as a new patch. Proved headless by `backend/test_approval_continuity.py` - 55 checks, 0 failed, with the regression red without the fix (6 failing checks) and green with it, measured by switching the two halves off in the same tree - and by the agent and streaming suites that already guard this path: `test_agent.py` 279 passed and 1 skipped, `test_agent_plan_wiring.py` 60 passed and 1 skipped, `test_agent_retirement_wiring.py` and `test_chat_stream.py` 68 passed and 1 skipped, all 0 failed.
