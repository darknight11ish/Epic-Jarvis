- **The desktop HUD's calendar no longer reads an event an hour out on a daylight-saving day, and the README's stale deployment lines are true again (2026-11-01).** The HUD calendar built each event's moment as local midnight plus the clock time in absolute milliseconds; a daylight-saving day is 23 or 25 local hours long, so on a change day every event moved an hour - on 2026-11-01 an event at 12:14 was computed as 11:14 and read "past" five minutes after it started (the same arithmetic read it an hour late on the spring-forward day). It is now built from the date's own local components, so the clock time the owner reads is the time the event happens on every day; the past/now/upcoming rules are unchanged, the all-day and midnight-crossing cases are covered, and five new fixed-date cases in `jarvis-desktop/tests/hud-calendar.mjs` catch the whole family all year instead of only on the day the suite happens to run on a Pacific PC (CI runs in UTC, which has no daylight saving, so the old arithmetic could never fail there). The phone's calendar never had this bug: it keeps dates and times as local date strings and has no past/now/upcoming arithmetic at all.
