A model cannot call a tool it is not shown, so a spoken request could not reach most of what Jarvis can do - the owner's request of 2026-11-01 was that Live "reasonably do anything that jarvis can do through chat". Now a Live turn is shown exactly what a typed turn is shown for the same words: `jarvis_live.LIVE_TOOL_FLOOR` is typed chat's own diet size (8), `[live] tool_limit` can only raise it and never lower it, the full-list fallback is never trimmed, and the carried prefix-cache list uses the same cap. The switched-off persistent-stream path also marks its loopback message `provenance: "voice"` beside `live: true`, the shape both apps already send; without it the server did not treat that turn as Live at all. Proved by the new `backend/test_live_parity.py` (40 checks: tool-list equality for six kinds of question, the floor, the carried list, a whole Live turn raising the same card and running nothing first, the prompt's only difference, the server's marks, the fast path's identical PC-state answer, and the deliberate rules), plus updated assertions in `backend/test_live.py` and `backend/test_agent.py` that had pinned the old cap.
