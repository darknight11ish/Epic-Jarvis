That made ONE line the thing every API pull request edits: two PRs that each append a section conflict on it by construction, a conflicted PR gets no CI at all, and five open PRs were blocked or serialized by it on 2026-11-02. Gemini's ruling 1 removes the list and the hardcoded upper bound: the check now reads every `## N.` heading from 129 up, in document order, and fails on a duplicate number, on a number that does not strictly increase, and on more than three numbers missing between two sections — three may be missing because an in-flight sibling PR reserved that number and has not merged yet, and four is no longer one waiting sibling. The file keeps a fixture case for each part (a duplicate fails and names the number, out-of-order fails, three missing passes, four fails, and the order of the sections below 129 is not this rule's business), so the rule is proved to BITE and not only to pass; it is also run against the real document with `## 176.` appended, which the old contiguous rule failed and the new one accepts. Honest limit: the old list also caught a stale-branch merge that silently deleted sections 135 and 136, and with the list gone a middle gap of up to three — and a dropped tail — now passes. That is the trade the ruling makes deliberately, and the file says so where the rule lives instead of leaving it implied.
