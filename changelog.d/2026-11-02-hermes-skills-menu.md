- **A skills menu on the PC: install from a folder or a .zip, import from Hermes, turn a skill off and back on, and edit one behind the same card (2026-11-02).** Jarvis could always read a `SKILL.md`-in-a-folder skill, but no app could add one - the phone's own code said so ("there is deliberately no route that installs a skill, because installing runs the scanner and the approval gate on the PC"). Now Settings → Skills does, and it downloads nothing: the only sources are a folder or a `.zip` on this PC and `%USERPROFILE%\.hermes\skills`. Every install, turn-on and edit goes through the existing scanner and raises exactly ONE `modify_own_code` card, and a skill the scanner refuses is quarantined and never becomes a card at all - an "install this?" dialog for a curl-pipe-bash skill is the last step of the exploit, not a safeguard. A warning-level skill waits until a person has read the warnings. Turning a skill off moves its folder to `skills-off\` and drops its index row, so the model is no longer offered it and nothing is deleted; turning it on is the same scanner and the same card. A skill that ships a `scripts/` folder says so on its row and on its card, in the owner's words: "Imported SKILL.md instructions (N file(s) in scripts/ are kept inert and never run automatically)." Remove is unchanged and still the phone's too. No marketplace, no network, no auto-install, and no "install all": three skills are three cards.
