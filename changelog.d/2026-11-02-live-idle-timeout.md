- **How long Jarvis Live waits before it turns itself off is now a setting (2026-11-02).** The owner asked to change it by talking to Jarvis: *"also id likee to he able to tell jarvis to change the setting that turns off jarvos live by extending how long ot takestoo turn off when it doesntt hear anything"*. The 90-second silent window that used to be `jarvis_live.QUIET_S` is now `[live].quiet_s`, bound 30 seconds to 10 minutes with a 30-second step for the two apps' controls. Say "how long before Jarvis Live turns off when it hears nothing" and Jarvis answers with the value and the range; say "make Jarvis Live wait three minutes" (or "set the jarvis live timeout to five minutes") and it changes, then answers "Okay - Jarvis Live will now wait 3 minutes before turning off when it hears nothing. It can be anything from 30 seconds to 10 minutes". A length outside the range is refused in words that name the range, and nothing is written. It is in Settings on the PC ("Limits and frequency") and the phone (Limits) too, from the same one row, so both apps show the same label and range. No approval card in either direction: Live is already running and its microphone already open, and the sentence only decides when an idle session ends - it can never start Live, read, send or store anything. The default stays 90 seconds, so a PC that never touches the row behaves exactly as it did; a hand-edited nonsense value is clamped to the range by the engine itself.
