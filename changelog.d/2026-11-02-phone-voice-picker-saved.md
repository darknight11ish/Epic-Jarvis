- **The phone's voice picker marks the voice you chose, not the default that happens to be speaking (2026-11-02).** The owner's report: *"when I reset the jarvis Android app it changes the voice to the default. it doesn't seem to remember what I changed it to."* Part of that was the screen itself: `GET /api/voice/voices` answers `speaker.choice` (the voice that SPEAKS, which is the pack default whenever the saved voice cannot) plus `speaker.saved` (the voice the owner actually chose, `null` when he never chose one), and the phone read only `choice` - so the picker highlighted the default and the screen read as if his choice had been forgotten. It now reads `speaker.saved` and marks that row; `choice` keeps its meaning, so everything that names the sound (Live's "Voice: ..., from your PC") still names the voice he is hearing, and a PC too old to send `saved` behaves exactly as before. The PC's own note already says which one he chose and which one speaks whenever they differ, so that sentence is now true on screen instead of contradicting the highlight. Unit test: `CustomVoicesTest` - "the picker marks the voice the owner saved, not only the one that speaks" (with the old rule it fails, `expected:<bm_george> but was:<af_heart>`); the phone's JVM suite is 3,098 tests, 0 failures, 0 errors, 0 skipped. Not tested on a real phone - no APK was built from this branch - and this is the client half of PR #1076 (`fix/phone-reset-keeps-voice`), which must merge first for `speaker.saved` to exist.
