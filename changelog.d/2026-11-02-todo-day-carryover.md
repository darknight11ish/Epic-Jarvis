Every job row now carries an immutable `created_date` (YYYY-MM-DD, the PC's local day), written once when the item is created and never rewritten - not at midnight, not by an edit, not by the mode switch - and an existing `schedule.db` is migrated once, from each row's own `created` stamp, or today for a legacy row with no usable one. Full daily rollover is the default: today's list is every open item, each older one tagged by the PC itself (1 day "from yesterday", 2-6 days "from <Weekday> (<N>d ago)", 7+ "from <MMM D>"), so a 3-day-old item never says "from yesterday"; "Day by day" instead keeps each item on the day it was written, under that day's heading, and switching between the two is lossless by construction (the same rows, the same `created_date`, only drawn differently). It is changed in Settings on either app - the desktop's new "To-do list carry-over" card, the phone's control under Limits - or by asking ("set the to-do list mode to day by day"), all three ending at the same PC method, and no approval card either way because it moves no item and loosens no rule. The spoken read-out says the age too ("Your to-do list: renew the prescription (from Saturday (2d ago)), buy milk"). No new route: it rides the scheduler's existing `POST /api/schedule/act` as `{"do": "todo_mode"}`. `created_date` is additive, so an older app ignores it and a code rollback stays safe.
