- **Asking for a web-search grant in a chat now raises its one card, and Jarvis can no longer claim an approval it does not have.** The 2026-11-02 field test found this: two natural sentences ("Give me full approval to search the web for this conversation.", "Approve web search for this conversation, so you can search without asking me each time in this chat.") raised **no** `grant_web_search_conversation` card, and the model still answered "Understood. Search is approved for this conversation." - because the grant tool was never offered. It was a Settings, Tools, "Safety and sharing" switch that was off, so the model had no tool to call and no card could exist. Now the ask and its instant stop ride with web search (`jarvis_agent.GRANT_ASK_TOOLS`): offered on an ordinary turn whenever `web_search` is, no longer a Settings row, and switched off with web search. Offering the ask grants nothing - one card, a person's yes, search only, all unchanged. Two honesty fixes come with it: the rules block now says an approval is not the model's to give or assume and may not be claimed unless a tool result in that conversation said one is in force; while a grant really is live the prompt carries a line read from the store (`_grant_prompt_line`), and an answer that claims one the store does not hold gets the same plain `(Correction - ...)` postscript as a claimed-but-unrun search (`_grant_claim_line`). Pinned by `backend/test_web_search_grant.py` (127 checks, including the field test's own two sentences and the false-claim rule) and the new offered lists in `test_tool_defaults.py` / `test_tool_contract.py`.
