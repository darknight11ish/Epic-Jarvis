- **Scheduled tasks can run any job in the owner's own words, and never as two cards (2026-11-03).** A reminder's `run-task` action may now carry `job` - a phrase in the owner's words, up to 240 characters - instead of only the closed `briefing`/`backup` names (which are unchanged). The phrase is resolved through the same `jarvis_quick.match` path chat uses when it is saved (an unresolvable phrase, or one asking for a shell/command/script, is refused in one plain sentence) and again at fire time (a phrase that no longer resolves raises no card and runs nothing). A phrase that resolves to an intent raising its OWN approval card (`forget_range`, `update_start`, a carded setting change, a repeating briefing, "read this link", …) is refused when the reminder is saved, in one honest sentence saying it needs the owner's approval each time, naming what the phrase matched and saying it was not saved - so one scheduled task can never put a second card on screen; a stored row that resolves to one later is refused at fire time too (no card, nothing runs, `needs_approval` in the audit, and the row says why). Every intent the resolver can return is classified, and an unclassified one is refused conservatively. At fire time a cardless job raises exactly ONE `schedule_action` card, tier ask, naming the action in plain words and saying nothing happens before a yes; denial/timeout runs nothing. Approved, it runs through `jarvis_quick.run` - the same executor chat uses - so the module adds no shell, no command line and no second interpreter. The owner's words never reach the audit log or the card's `detail`. Both apps' Reminders screens still send only the closed name; that one-sided gap is recorded in `docs/ARCHITECTURE.md` §8 as a follow-up.
