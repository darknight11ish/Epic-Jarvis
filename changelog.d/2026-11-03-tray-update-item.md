- **The tray offers "Update Jarvis to <version>" only while an update exists, and pressing it installs that version (2026-11-03).** The owner asked for a right-click row that "appears if there is an update to jarvis". It used to sit in the "More…" submenu permanently, reading "Jarvis Desktop 0.2.0" and disabled when there was nothing newer; now `tray.rs`'s `update_row` is the whole presence rule (no update means the row is *absent*, not greyed out) and `on_update_status` adds or removes the row from the menu, because Tauri 2.12's `MenuItem` has no `set_visible`. The label names the version the check found (`Update Jarvis to 0.2.411`) or falls back to `Update Jarvis`. Pressing it runs the same `update::install_update` the Settings Install button runs - never a second updater and never anything automatic - after turning the row into "Updating Jarvis to <version>…" so a second press cannot start a second download, with a toast carrying the "Jarvis closes while this installs" sentence the Settings card shows. On Windows a successful install ends the process and the next launch starts with no row; a failure re-reads the real state and rebuilds the row from it. Availability is the existing check's own answer (`update::available_version`, read from `UpdateState`), not a second network path. No App-lock gate is added: `lock::may_open` gates *opening a covered window* and its unlock path opens one, while the update commands themselves never ask App lock - the same rule the tray's Quit, Stop everything and backend rows already follow.
