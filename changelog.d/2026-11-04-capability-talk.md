- **Jarvis can now hold a real conversation about any of its own tools, from a code-verified dossier (2026-11-04).** The dossier module landed first; this is the wiring that makes it reachable. In chat, a sentence that names a tool *as a tool* - the word "tool", or the tool's own code name typed with its underscore - is answered deterministically from the dossier's own words: what the thing is in beginner words, what it really lets the owner do, what it refuses, what it pairs with and how to switch it on, in `quick: tool_profile`, `where: local`, `lane: "no AI model"`, so both apps show it with no client change and it costs no model turn. "tell me about the github tool" and "what does browser_control do" used to fall through to the model, or to the feature guide's prose for a different thing; they now answer from the dossier. Everything else naming a tool - an opinion, a comparison, "would it help me with X" - stays the model's, which is now handed the same page as a bounded system note: at most 1,200 characters of dossier plus one fixed line, held out of the room like every other injected note, and **absent entirely on a turn that names no tool**, so an ordinary prompt keeps exactly the bytes it had. A follow-up ("would that let you fill in a form?") looks back at most two earlier user messages, which is what turns one answer into a discussion. It adds **no new model tool and no new HTTP route**: a tool would cost five mandatory registrations and ship switched off in the owner's own settings file for facts that fit in 400 prompt tokens, and a route would be a third copy of what `/api/reach` and `/api/self` already serve. Features stay the feature guide's and drop-in plug-ins stay `plugin_list`'s - the two vocabularies are kept apart by an explicit marker, because 42 of the catalogue's 175 feature titles open with a tool's own words. `backend/test_tool_profiles_chat.py` pins it all, including a byte-identical-prompt check and a 175-row guard that no feature title is hijacked.
