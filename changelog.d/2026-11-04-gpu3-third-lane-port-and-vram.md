- **The third graphics card's lane no longer wants the everyday lane's port, and the preset screen shows real card sizes (2026-11-04).** Two defects measured against `origin/main` at `30c64e40e`, both fixed with the third card still OFF by default. **A:** `jarvis_second_card.DEFAULT_THIRD_PORT` was `11436` (chosen 2026-09-28) and `_third_port()`'s guard only checked `11434`/`11435`, but the owner's everyday lane moved onto `11436` on 2026-10-16 (PR #440) - so switching the third-card feature on would either fail to bind or steal the assistant's own port. It is now `11438` (`11437` is the screen-picture lane's), the guard checks every lane port the repo names (`11434`, `11435`, `11436`, `11437`, `11450`) instead of two, and a colliding default raises `RuntimeError` at import rather than being silently stepped over. **B:** the preset hardware block reported the card count with every card's `vram_gib` null, because `jarvis_presets._detect_cards()` read `vram_gib`/`memory_gib`/`vram` while `jarvis_hardware.detect()` fills `total_gib` - so the desktop preset screen showed two cards with blank sizes. It now reads `total_gib` too, and a two-card fixture (the 2026-11-04 nvidia-smi sample: 12,288 MiB + 8,192 MiB) asserts `[12.0, 8.0]` GiB and a 20.0 GiB total instead of only field names.
