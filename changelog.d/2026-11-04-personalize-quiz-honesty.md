- **"Personalize Jarvis" no longer says it is finished when it is not, and its chat reminder obeys its own switch (2026-11-04).** Two defects from the 2026-11-04 audit (DEF-043, DEF-044). First, pressing Apply after answering only SOME of the 25 questions wrote `completed_version = QUIZ_VERSION` anyway: the first-open offer, the HUD banner and the every-turn chat line all stopped while the card still read "1 of 25 answered", and nothing offered the card again until a version bump. Completion now means every current question has an answer - the same `answered_count()` both apps and the HUD read - so a partial apply saves its answers and counts its run but leaves the offer, banner and chat line running, while an apply with all 25 answered still marks the set finished; "Keep current settings" remains the one press that finishes it without answering anything, and a retake still keeps every earlier answer. Second, the eighth notification switch's promise ("Say when Personalize Jarvis is unfinished") gated only the launch toast: turning it off still left the chat line reminding the owner every turn. The line now reads that one value through `jarvis_notify_prefs.read()` - the same reader both apps' Notifications cards and the toast use - so OFF means no line and ON (the default) restores it. This fragment is also the record check for the audit's bookkeeping note: PR #1135's own bullet was already on `main` before that PR merged (`changelog.d/2026-11-03-personalize-jarvis.md`), so this PR adds this fix's record and repairs no missing one.
