- **The Tools page can turn OFF any tool that is on, including one the settings file switched on (2026-11-04).** The owner's D4 reversed the old limit that answered **403** ("not offered in-app by this slice" / "does not know a tool by that name") for anything outside the 21 in-app switches. Every tool that is ON is now listed in the "Let the AI use this" section, including a tool enabled in `[tools].enabled` that the page has no switch row for - a Tier C tool, one of the "not this slice" tools, or a name this PC does not know at all - with its real state and the PC's own plain reason under it. Those rows are OFF switches only: turning one off is instant from either app with no card, exactly like every other tool switch, and it removes that one line from the settings file the same careful way (the owner's file is edited, never overwritten). After the OFF the row stays and says OFF truthfully, with the file named so it can be put back by hand; turning an unlisted tool ON is deliberately **not** widened and still answers the old 403. `GET /api/asks_first` carries the new rows as `tools.extra` (the phone ignores it, so its read-only page is unchanged), and Rust no longer refuses the OFF direction before sending it. New tests: `backend/test_asks_first.py` drives the route and the extra rows end to end, and `jarvis-desktop/tests/tools-off.mjs` holds the page's rows and verb wiring on plain Node.
