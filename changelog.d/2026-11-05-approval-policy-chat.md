- **What needs a card, a second yes, or Windows Hello can now be changed by talking to Jarvis (2026-11-05).** The owner asked for "the ability to change what gets an approval card through chat, including if something gets a double confirmation, or a fingerprint/windows hello". One new model tool, `approval_policy` (`backend/jarvis_agent.py`), backed by the new shipped module `backend/jarvis_approval_policy.py`, changes ONE named action and ONE thing at a time in three independent dimensions: whether it raises a card (`[autonomy.tiers]`, the table every part of Jarvis already reads, through `jarvis_asks_first.request_tier`), how many yeses it takes (`[autonomy.confirmations]`, `<action> = 2`), and whether a yes must also meet Windows Hello on the PC (`[autonomy.windows_hello]`, `<action> = true`). More asking - a card where there was none, a second yes, Windows Hello - is instant and cardless, like every "turn it off" switch in both apps. Less asking raises ONE card, on the PC, that needs Windows Hello to approve and is refused from any other device; the card's words say exactly what stops being asked, in the owner's words, and nothing is written until a person approves. No bulk form: a body naming two dimensions is refused before anything is read or raised, and it is never a plan step. An unknown action is refused before any card in one sentence naming the nearest real actions. Nothing is auto-approved: the policy only decides whether a card is RAISED, and actions whose own module refuses anything but a yes keep their card. The second yes and the Windows Hello requirement are enforced where every real approval already passes - `jarvis_owner_check.approve_check`, a shipped module `owner-check.patch` already installs - so this needs no new patch on the owner's `jarvis_gate.py`: the first yes runs every check and then approves nothing (no stamp, so the gate still waits), and only the second yes stamps the approval the gate believes. Windows Hello for that action is asked on every yes, even for a card that would otherwise skip the prompt, and a two-yes card is approved on the PC only because the phone's one-tap signed approval cannot carry a second yes. Both apps' "What asks first" pages stay read-only and show the extra answers in the row's existing note field; `docs/ARCHITECTURE.md` section 8 records why, and why there is no model-free fast-path grammar for these sentences.
