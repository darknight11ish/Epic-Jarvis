- **Packs, phase 1: add and remove a skill from a folder or a `.zip`, with the whole scan on the card (2026-11-05).** Four chat tools (`pack_list`, `pack_inspect`, `pack_install`, `pack_remove`) over a new `backend/jarvis_packs.py`: a full pre-install scan (safety, compatibility, effectiveness) computed before anything lands, shown on ONE `modify_own_code` card and saved as a receipt, a `jarvis-packs.json` ledger recording every file it wrote with its sha256, and a removal that deletes exactly those files and keeps anything the owner made. Nothing is enabled by installing it - the pack is moved to `skills-off` at once. Honest limits: **prompt-only skills only** (a pack holding `.py`, `.pyc`, `.ps1`, `.bat`, `.cmd`, `.sh`, `.exe`, `.dll`, `.so`, `.pyd`, `.js`, `.ts`, `.wasm` or any binary is refused in one sentence, before any card, and a folder holding a symlink or junction is refused too) and **local sources only** (a folder or a `.zip`; no git, URL or marketplace, so nothing opens a socket). An installed pack is **immutable**: every file's SHA-256 is pinned in `jarvis-packs.json` and re-checked on every load - the pack list, the skill hub's offered list and its manual reads, the Skills menu, the pack manager's own load door, and `jarvis_skills.load()` through the one core patch `backend/packs-tamper-on-load.patch` - and a file changed behind Jarvis's back is refused and the pack marked `tampered`. There is **no update command**: installing a name the ledger already holds is a **replacement** - a full new scan plus a unified diff against the installed files on one NEW card - and nothing is swapped until that card is answered. The card goes through the existing `modify_own_code` action; PC-only + Windows Hello is deliberately not added here, because it would need a new gate action or would take every skill install and the phone's plugin switch with it - the decision fragments say so.
