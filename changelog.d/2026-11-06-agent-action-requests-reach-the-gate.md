- **An explicit action request now reaches its gating tool instead of a refusal or a false claim (2026-11-06).** The measured run: six action requests in chat - *forget this fact*, *delete my note called Welcome*, *write and send an email*, *turn on reading remembered-fact answers aloud on my phone*, *turn on cloud escalation*, *install this plugin from a URL* - and `POST /api/pending` stayed `[]` after every one, with answers that refused in words or pointed at Windows settings. Three things were wrong and all three are fixed. (1) The rules told the model "you do not send email, edit files, or run commands yourself", which a 9B model reads as *I cannot*; they now say to CALL the tool for anything a tool does, that the tool raises its own card, that the card is the only thing that allows a change, and that a tool result is the only proof - and the settings tool says plainly that the model never changes a setting itself because "my change_setting tool changes a setting directly whenever I hear the request" is exactly what the pass-3 run got. The Modelfile's SYSTEM block carries the same words. (2) Chat had no door to the standing cloud escalation switch at all - it is a Presets row with no settings-registry row - so `cloud_escalation` is new: ON raises the same ONE `change_own_config` card `jarvis_presets.cloud_escalate()` already raises for the Presets menu, OFF is instant, no service chosen refuses before any card, and it rides with `change_setting` rather than being a Settings switch the turn would ignore. (3) The three requests with no card to raise now answer with the real door and raise nothing: a single saved fact is forgotten on the Memory screen's own Forget, the phone's "Read out answers that use what Jarvis remembers" is a phone-only switch, and a plugin or skill pack is a file on this PC - never a URL. Where a real tool ships switched off (sending email, skill packs) the answer names the Settings -> Tools switch instead of saying Jarvis cannot. The false claims are corrected deterministically: "I have asked this PC to open listening when I say hey Jarvis" and "I've turned that on for you" now get the "Nothing was actually done" line when no action tool ran (`jarvis_claims.CLAIMS_DELEGATED`), and the settings-mechanism sentence gets its own correction. `backend/test_action_requests_reach_the_gate.py` drives the real turn loop with a scripted model and a recording gate for all six probes and the two measured sentences - 53 checks, no network, no real card. Not driven live: this branch was not deployed, so the six probes have not been re-asked on the owner's PC.
