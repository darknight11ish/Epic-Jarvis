- **Every tool switch can be switched by asking, typed or in Jarvis Live, and Live answers that a settings change works the same way it is typed (2026-11-07).** The feature-awareness audit measured two gaps: `jarvis_asks_first.TOOLS_SWITCHABLE` lists 60 tools and Settings draws a row for each, but `jarvis_settings_registry._TOOL_TARGETS` named only the four reading tools, so 56 of the 60 could not be switched by asking at all - measured, "Turn on the browser control tool." went to the model in typed chat and got an outside-text refusal in Jarvis Live. That table is now generated from `TOOLS_SWITCHABLE` by `tools/gen_tool_targets.py` (with a `--check` drift mode), and two sentence shapes resolve through it: the existing "let the AI model read <name>" and the owner's own "turn on the browser control tool" / "switch the calculator tool off" (the word "tool" plus a whole known alias is the closed-world rule, so "turn off the kitchen light" and "turn off the timer" still fall through to their own features). The card rule is untouched: ON is the PC only, ONE approval card plus Windows Hello; OFF is instant; nothing is auto-approved. In a Live turn a carded tool switch now gets the same ONE calm spoken line a carded setting gets ("A card is waiting to offer ... to the AI model, so approve it on your phone or PC and it changes") instead of reading the setter's card sentence aloud. A spoken sentence also now keeps its polite lead-ins ("hey jarvis", "go ahead and", "i'd like to", "um,") and spoken punctuation out of the way before the settings grammars see it, while typed sentences resolve exactly as before. Asked *"Can you change your own settings by voice through Jarvis Live?"*, Jarvis now answers from the code instead of the model's guess: yes, the same sentence, the same approval card and the same effect, with some settings PC-only for safety and their card tapped, never said. `backend/test_live_settings_parity.py` (932 checks) derives every option from `jarvis_settings_registry.capability_keys()` - 38 switches, 10 choices, 1 number, 7 asks-first actions and all 60 tool switches - drives each sentence typed and as a Live turn against a recorder standing in for the setter, and fails if a future setting is added without both doors; it also checks the real files for Anti-Slop and humour, the carded sensitive-topic switch, the real tool list, the spoken pre-pass and the fallback tool menu. The same pass investigated the audit's Live-only refusal and found it is not specific to Live: the route hands the answering turn a request that contains the PC's own recalled-facts system message, which the settings guard reads as "the app sent extra text", so a model-issued `change_setting` is refused whenever memory recall fired; that is reported, not silently changed.
