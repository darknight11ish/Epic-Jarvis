- **The Models screen's GPU warning reads the chat lane, not a stale address (2026-11-08).** `jarvis_models.offload_status()` read the module's fixed `OLLAMA` address instead of the lane the chat actually uses, so on the owner's PC it described a stale duplicate of the coder model on port 11436 at 74% in video memory while the chat lane on port 11450 held the same model at 100% across all three cards - and after that duplicate was unloaded the same read would have said 'no model is loaded' while the chat lane was busy. The check now resolves its address through `jarvis_hud.active_ollama_url()` (the one resolver `presets.patch` introduced for the active lane), asks that lane's `/api/ps` and nothing else, says plainly when the chat lane is not answering rather than falling back to another server's numbers, and says 'no model is loaded on the chat lane' when that lane is empty; it stays read-only, four-second-bounded and never raises. No live file, process or setting was touched.
