- **The desktop companion says what it is, and it is not the drawing (2026-11-12):** the Roamies-style companion arrives as one shipped module (`backend/jarvis_companion.py` and its `jarvis-backend/` twin), a saved-preferences file and seven chat answers - and every one of those answers now says plainly that the visual and screen half is **NOT BUILT** in this build. Removed from the product's own voice, because none of the code existed: "non-blocking UI Automation with batch subtree caching", "native Windows Runtime OCR (WinRT) with zero external downloads", and a "strict hands-off security perimeter blocking terminals, password vaults, and destructive actions". The four companion switches now ship OFF, a saved switch is reported as a saved preference ("Saved the holographic avatar switch as on. This build does not draw the companion yet, so nothing changes on screen."), and a save that fails says so instead of reporting a success that did not happen. **The second, weaker blacklist is gone:** the module kept its own eight-name terminal and vault list that nothing called and that allowed `C:\Windows\System32\cmd.exe`, `wt.exe`, `1Password.exe`, `bitwarden.exe` and `keepass.exe`; `jarvis_companion.denied_app_reason()` now asks the ONE enforced desktop hard denylist (`jarvis_ui_control.denied_process_refusal`), reduces a full path to the program's own name first, and refuses when the list cannot be read. The ten-word "risky action" list went the same way: nothing consulted it, so it is no longer presented as a guard. **A private chat can no longer change a companion setting:** `companion_toggle` and `companion_set_style` sat on the private-chat read whitelist while both write a settings file, so a private chat saved instead of refusing; both are off it now and answer with the one private refusal, proved end to end with the file on disk unchanged. The preference file also moved out of `~/.jarvis/` into Jarvis's own settings folder (`OPENJARVIS_HOME`, else `~/.openjarvis`), so the suite no longer writes the owner's real profile. The new `backend/test_companion.py` proves each of those with a check that fails on the old code: a full-path `cmd.exe` refused, every dropped claim absent from every answer, a failed save reported as a failure, and a private "turn off avatar" refused with the settings file byte-identical. No drawing, screen reading, text recognition or input control was added. `docs/JARVIS-API.md` section 216 and `docs/ARCHITECTURE.md` section 8 now say the same in the docs.
