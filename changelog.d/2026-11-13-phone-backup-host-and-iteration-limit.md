- **A restored phone keeps its own desktop address, and a backup file cannot pick a huge password-hashing cost (2026-11-13).** The phone's settings backup no longer carries the desktop's address (`host`): the pairing token stays behind the Android Keystore, so a restore that wrote an address would send a credential the phone already holds to whatever desktop the file named - and a backup made before this change, or a crafted one, has its address dropped when read rather than applied. The address is typed again when the phone pairs, exactly as after a reinstall. Two sentences that promised more than the code could keep are corrected with it: a restore that fails while writing a preferences file now says that some settings may already have been restored and the rest were not (the files are written one at a time), and a backup file may no longer ask for more PBKDF2 rounds than this app writes (210,000), so a small crafted header cannot make the phone run millions of rounds before the first tag check fails. `docs/JARVIS-API.md` section 220 now says which failures share the "damaged" sentence and that only authentication is all-or-nothing.
