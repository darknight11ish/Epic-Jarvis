- **An approved GitHub card now merges, or says in code's words why it did not (2026-11-15).** Last night an approved `github_merge_pr` card for pull request #1261 executed nothing, and the explanation the owner got was invented. The model had echoed a head commit from an earlier scan, so the card pinned a commit that was not the pull request's head; the run correctly refused it, said "the pull request moved since you looked" (false - its head had not moved), and the only account that reached the owner was the model's own, which described a duplicate-call rule that does not exist. Three things change. `github_merge_pr` can be called with just the repository and the pull request number: Jarvis then reads the pull request itself, pins the head commit GitHub reports, and the card shows that exact commit - approve it and it merges, with the pin still re-checked at run time. A `head_sha` that IS supplied but is not the pull request's head is refused before any card is raised, in plain words naming both commits, instead of becoming an approval that cannot merge. And when an approved GitHub write's run fails, Jarvis puts the module's own reason into the answer itself, so the owner reads the real cause and not only the model's account of it. Nothing is auto-approved, there is still one card per action, and the merge is still pinned to one exact 40-character commit.
