- **The GitHub fix-flow cards say what they will do, and refuse a pull request they cannot push to (2026-11-15).** Two of the nine defects the fix-flow field test measured were the kind that cannot be seen until they happen: the push card did not say which host the saved key reaches, and a marker branch that is not a valid ref could reach a push card at all. The prepare, write and push cards now name both hosts in plain words - `api.github.com` for GitHub's API, `github.com` for the clone, fetch and push - so the two the key reaches are the two the card states. A pull request that is already merged or closed is refused before the clone, and a branch name that is not a valid ref is refused before a push card exists. The git timeout is raised to 900 s after measured clones of 257-297 s, a failed copy is retried and, if it is still there, named for the owner to delete; and checks that had not finished when the folder was prepared are now named as unfinished instead of being reported as no failures, which is the difference between "nothing failed" and "nobody knows yet". The write and push cards also carry the pull request's title and base branch, the exact push command with `HEAD` and `refs/heads` said in plain words, and how to abandon the change.
