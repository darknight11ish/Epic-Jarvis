- **The History sidebar's per-chat menu draws at normal size again, and every chat can now be exported as Markdown or copied as plain text (2026-11-15).** The owner photographed that menu: each icon was enormous and every label was clipped to two or three characters ("O…", "Pin …", "Move t…", "Arc…"). The measured cause was CSS, not the markup - `hud-history.js` builds every menu icon through one `icon()` helper that sets only `class="glyph"`, `viewBox` and no width or height, and the `.hh-menu` rules had no `.glyph` rule at all, so each SVG fell back to the replaced-element default of 300x150 and flex-shrank until the label had a few pixels. Every other glyph on the page already has its own size (`.hh-head .glyph{width:13px;height:13px}`, `.history-open .glyph{...}`); the fix is the missing rule, `.hh-menu .glyph{width:16px;height:16px;flex:0 0 auto;}`, in the same stylesheet block as the other `.hh-menu` rules, so the row menu, the "Move to project" submenu, the delete confirmation rows and the archived list's menu all read as icon + label again. The same menu now offers **Export as Markdown** and **Copy transcript** on every chat, on the live list and on the archived one (an archived chat can still be read out): Export writes ONE Markdown file into the owner's Downloads folder and says its full path in the panel's own status line, numbering a repeat (" (2)", " (3)") rather than overwriting, handling a title of Windows-forbidden characters (`\ / : * ? " < > |`) and a chat with no messages; Copy puts the same transcript on the clipboard as plain text through `navigator.writeText` - the same call the answer menu's "Copy answer" makes - so there is no HTML flavour and no dialog. Both actions read the chat through the **same** `/api/history/conversation?id=` request Open already makes and change nothing on screen; the words are only ever written to Downloads (one new narrow command, `hud_history_export`, granted in the HUD's existing `hud-history` set, no new capability set, no route, no network request, no approval card) and it is refused while "Hide memory lists" or App lock is on. The labels live in `history-actions.js`'s one `ACTION_LABELS` table, and the menu's height clamp moved from 280 to 360 so the two extra rows stay on screen. The Brain's History tab and the phone deliberately get neither item - the Brain builds its own row actions from a different path and the phone has no such panel, so there is nothing to wire (ARCHITECTURE.md §8; `tools/check_parity.py` clean) - and a plain browser, served by the backend, has no file writer, so Export there says it needs the desktop app while Copy still works. Proved by 52 checks in `jarvis-desktop/tests/hud-history.mjs` (the new menu items on both lists, the filename rule for every forbidden character, the empty-chat export, the copied text carrying no markup, the reused read, and the Rust command's presence in the handler, the manifest and the HUD's set) plus three Rust unit tests for the name rule and the numbering; the drawing itself is CI's Playwright `hud.mjs`, which cannot run here (no Playwright installed).
