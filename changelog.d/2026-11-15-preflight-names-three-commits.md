- **The preflight now says which commit the desktop, the backend and `main` each came from, in one row (2026-11-15).** Three pieces of this program can be at three different commits — the desktop app, the live backend folder and the branch every release is built from — and until now nothing said so out loud: a deploy could land half of a change and every check would still read green. The new preflight row is *"Which commit did each piece come from?"* and it prints the three short ids on one line: identical ids are a PASS, and ids that disagree are a WARN that names which piece is behind rather than just failing. It reads only the refs already on the PC (`git rev-parse`, so an offline PC answers and nothing is fetched), and a folder that is not a git checkout, or a PC with no git at all, says so instead of naming a guessed sha. Nine lines of `docs/ARCHITECTURE.md` §5 say the same. Proved by `backend/test_selftest_preflight.py`, which drives the row three ways: all three agree, the backend is behind, and the ref cannot be read.
