- **A background job that ends now tells you, in both apps (2026-11-16).** The owner asked for a notification when a long task he started finishes. The PC already published a `job` event carrying the smallest honest copy — the job's label and its state, never the result and never the params — and its durable outbox already re-announced a completion that a crash had interrupted; what was missing was a client that listened. The phone dropped the event as "unhandled", and the desktop's own Windows toasts had no kind for it. Now one notification (phone) and one toast (desktop) say only the job's label and that it ended, deduplicated by the job id so a replay replaces its own notice, and tapping either opens the Work pane or Work tab where the answer already is. The event's failure text is gone as well: `_finish` used to put `error[:120]` into the frame's `note`, which is arbitrary handler text and in the suite's own probe was the result itself. The phone and desktop halves are NOT-TESTED on real hardware until CI builds and the owner installs them.
