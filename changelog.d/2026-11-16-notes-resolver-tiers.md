- **One resolver for every note tool, and the vault's daily-note settings (2026-11-16).** The architect's Wave 1 ruling kept `jarvis_notes_edit.py` as the SOLE vault writer and moved resolution to `backend/jarvis_notes.py`, where `resolve_note(name)` is now the one place every note tool routes through. Its tier order is adapted, as a pattern, from Vinzent03/obsidian-advanced-uri (MIT): the exact vault path the owner named, then the file name matched case-insensitively, then an exact value of the note's own YAML `aliases:` list, then a refusal that lists the candidates. There is no daily-note fallback in any tier - the resolver has no branch that knows what a daily note is - and an explicit test asserts it cannot return one. `jarvis_notes_edit.find_name()` is now a thin `(row, why, matches)` compatibility shape over that resolver, so the chat read/append/tag/rename/move doors and the editor share one implementation. The refusal vocabulary is adapted, as patterns, from cyanheads/obsidian-mcp-server (Apache-2.0) and coddingtonbear/obsidian-local-rest-api (MIT): `case_variant_exists` (the Windows case-collision trap, naming the file that differs only by capital letters), `content_preexists`, `ambiguous_section` with a `candidates` list, and `not_found` with near candidates. The two options those projects expose as request headers - `create_target_if_missing` and `reject_if_content_preexists` - are boolean arguments on `jarvis_notes.create_target()` and on `POST /api/notes/create`, never a second HTTP surface; Epic Jarvis still never overwrites, so False only allows filling an EMPTY existing note. Separately, `jarvis_note_capture.py` now reads `.obsidian/daily-notes.json` for `folder`, `format` and `template` and applies a configured template to a NEW daily note (the note follows the template's bytes), following the behaviour, as a pattern, of liamcain/obsidian-daily-notes-interface (MIT) `settings.ts`/`createDailyNote`. A vault with no `daily-notes.json` - the owner's vault today - behaves exactly as before: `YYYY-MM-DD` in the top folder, a new note holding just the owner's words, the card saying no template is set, and no settings file invented. `docs/JARVIS-API.md` §170.13 records all of it, and `THIRD-PARTY-NOTICES.txt` carries the four credit lines. `backend/test_notes_resolve.py` (69 checks) pins each tier separately, the two-match refusal naming its candidates, the case collision, the create options, no daily-note fallback, and the absent/present/broken settings cases; `backend/test_notes_create_find_append.py` grows the chat-level no-fallback assertion (102 checks).
