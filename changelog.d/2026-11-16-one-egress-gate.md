- **One gate decides whether anything leaves this PC, and closed means refused (2026-11-16).** Jarvis is local-first, not local-only: six named cloud services can carry a request off this machine, and until now each of the four senders decided for itself whether it was allowed to. That decision now lives in ONE place - `backend/jarvis_egress_gate.py`, asked through `check_egress(caller, target_url, payload, surface, local_only=None)`, which never raises and opens no socket. The order is the order a person would ask: a loopback address (this PC talking to itself) is always allowed and reads no setting; then `local_only=True` refuses something that must stay here, which is how rule 1 (email, files, credentials, stored memory) is carried; then Lockdown; then the standing cloud switch (`escalate-cloud.json`); then the service's monthly money cap in `chatbot/api-money.json`. Closed means REFUSED: an absent, unreadable or corrupt switch is off, a damaged Lockdown file is on, and an unreadable money file, a service with no limit, or a host this PC has no settings for all refuse - a cap that cannot be read cannot be a yes. The chatbot's API adapter and the quiz's "Grade this better" send now ask it about the exact URL their socket is about to open (`request_url()` is the one place that builds it), and a refusal ends the conversation or the quiz as `egress_blocked` in the gate's own words with nothing sent. Review found one real bug in the first version: `_money_refusal` was called with `target` twice, the `TypeError` was caught by the gate's own never-raise belt, and every non-loopback request refused as `config_unreadable` - a gate that refuses everything is exactly as wrong as one that allows everything, so two suites now prove both directions (a refusal sends nothing, and a loopback send really goes). The published-base twin had been left at that pre-fix version and is byte-identical again. Two senders remain and are deliberately NOT wired in this change - the web search in `jarvis_search.py` and the HUD - and `tools/check_egress_gate.py`, now run by CI's `audit` job, lists them with that reason so a second lane cannot miss them; the same checker fails if any file under `backend/`, `jarvis-backend/` or `tools/` names one of the six hosts without asking the gate or being on its allow-list with a written reason.
