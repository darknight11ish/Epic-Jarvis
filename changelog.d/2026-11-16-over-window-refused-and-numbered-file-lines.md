- **An over-window prompt is refused instead of sent, and a long file is read as numbered lines with the range to ask for next (2026-11-16).** Two ways text was silently lost are closed. (1) When the prompt estimator said a pooled-lane prompt was over the window, `jarvis_agent.py` announced a warning and sent it anyway, so Ollama dropped the FRONT - Jarvis's rules and the earliest turns. Measured before the change at origin/main `7c3c58736`: an 8,192-token window, an 11,328-token prompt, the warning line, a request to `/api/chat` and the answer "ok". The branch now runs ONE aggressive re-trim (every tool result but the newest stubbed, `fit_messages` to 60% of the window) and, if the prompt plus the offered schemas still does not fit, refuses with one plain sentence before any request ("Prompt exceeds the 8,192-token local window ... Shorten the input, chunk the file, or escalate to DeepSeek"); the old warn-and-send line is gone. `max_tokens` is clamped to `min(client value, n_ctx // 4, 8192)` so an app cannot collapse the prompt budget. (2) `file_read` used to return up to 200,000 bytes from the front of a file, and the 8,000-character tool-content cap kept the first and last 1,500 characters OF THAT SLICE - for a file longer than the cap the model never saw the real end, and the tool had no argument to ask for the rest. Measured before the change on a real 1,020,029-character file: 200,000 characters returned, the real last line absent, 3,436 characters handed to the model, `file_read` arguments `['path']`. It now returns numbered line slices ("1: ...") with `start_line`, `end_line`, `total_lines`, `truncated` and a `more` footer naming the next range, and takes optional `start_line`/`lines` with the same names and defaults as `project_read` (400 lines, at most 2,000), so the model can ask for the exact next slice. The slice is capped at 6,000 characters so the footer survives the tool-content cap. The saved tool-schema fixture (`tools/tool_eval/jarvis_tools.json`) moves with the new schema, and `test_tool_text.py`'s measured-tools budget moves 2,970 → 3,050 (measured 3,023).
