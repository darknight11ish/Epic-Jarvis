- **The Python half of `THIRD-PARTY-NOTICES.txt` is generated and checked now, so it can no longer go stale silently (`tools/gen_notices.py --python`, 2026-11-16).** This closes problem 3 of `docs/DEEP-AUDITS-2026-10-05.md` — *"Add a Python package, a model or a Maven library and nothing fails"* — for the Python packages: the Rust half already had a generator, and this extends it rather than adding a second convention. `--python` rewrites section 3 alone, from `backend/requirements.lock`: all **78 pinned releases**, each row carrying the licence that release's **own published metadata declares for exactly that version**, read from PyPI's JSON API (the same stdlib reader `tools/check_python_advisories.py` already uses, name and version only, generic User-Agent). It needs no cargo and no installed backend, which is why `--check --python` — which exits non-zero and **names every package that differs** — now runs as its own step in the **informational `audit` job**, not in a required one, on purpose. Nothing is guessed: `espeakng-loader` states no licence at all and reads **`unknown`**, and the 9 packages that declare only a vague statement (`"BSD"`, `"BSD License"`, `"Dual License"`, `"Apache Software License"`, `"Apache licensed, as found in the LICENSE file"`, or two licences at once) keep their own words and are listed again at the end of the section for a person to resolve — a licence never becomes MIT by inference. `pip-licenses` (MIT) is the second reader: it is pinned in a new **`tools/requirements-dev.txt`**, never in `requirements.lock` and never a Jarvis runtime dependency, and the generator prints a NOTE for any package where it describes the licence differently (it reads the *installed* set, which drifts from the lock — five of the 78 pins on this PC were installed at another version — so it cross-checks, it does not author the rows). Proved: three consecutive runs produce **byte-identical files** (sha256 `61F52676…50B5A720`), and a run with `pip-licenses` installed produces the **same bytes** as one without it; a planted wrong licence for one package makes `--check --python` exit 1 naming `cobble 0.1.4: the file says "MIT", the release says "BSD License"`; both `--check` and `--check --python` exit 0 against the committed file. **No existing licence row changed** — the only edits to existing text are the header's list and the section numbers (Apache-2.0 NOTICE files 3→4, licence texts 4→5). `--diff` now reads the Rust section only, so Python rows cannot be reported as removed crates.
