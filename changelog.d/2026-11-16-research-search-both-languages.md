- **GitHub research now sends one repository search per language, because the single query it used to send was answered with zero repositories every time (2026-11-16).** `backend/jarvis_research.py`'s `plan()` built `<words> language:kotlin OR language:java`, and GitHub's repository search has no `OR` operator, so the audit behind the `github_search` tool was silently empty for every idea - the live audit of 2026-11-16 reported it "always empty". Measured by hand the same day with `gh api "search/repositories?q=..."&per_page=1`: the old form `jarvis language:kotlin OR language:java` answered `total_count` **0**, while `jarvis language:kotlin` answered **1,592** and `jarvis language:java` answered **1,283**. `plan()` now emits one `Query` per (capability x language) - Kotlin and Java - each with its own URL and its own `why` line naming the language; `sort=stars&order=desc&per_page=10` and the URL quoting are unchanged, and the words sent are still the locally derived `terms()`, so nothing new leaves the machine. **The approval card deliberately got bigger:** it prints both URLs in full and its count line reads "2 request(s)" per capability, because two outbound requests are exactly what the owner is being asked to allow - no URL is merged or elided. Tests are in the existing `backend/test_research.py` (no new suite, because a new `backend/test_*.py` file would move every later suite into a different CI shard): the new checks assert two queries per capability, no `OR`, exactly one language filter per query, only the locally derived words, and both URLs on the card. **They bite:** against the old module the suite reads 47 passed, 2 skipped, 9 failed, every failure on the query shape, and with the fix 61 passed, 2 skipped, 0 failed. Those two runs stub the token lookup to the environment variable only, because this PC has a real GitHub token in Windows Credential Manager and six pre-existing token-disclosure checks therefore fail locally before and after this change alike (55 passed, 2 skipped, 6 failed as-is). The twin `jarvis-backend/jarvis_research.py` is byte-identical.
