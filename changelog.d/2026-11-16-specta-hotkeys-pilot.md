- **A pilot that makes one Rust command's JavaScript binding generated instead of hand-written (2026-11-16).** `set_hotkeys` is the one command: `specta` + `tauri-specta` v2 now export it from its own Rust signature through `cargo run --bin export_bindings` into `jarvis-desktop/src/bindings.js`, and the Settings page calls that instead of `invoke("set_hotkeys", { bindings })`. A second command, `npm run typecheck:bindings`, runs `tsc` over the generated file and the one module that calls it, so a page that disagrees with the Rust signature fails instead of failing at runtime on the owner's PC. It is a PILOT on purpose - the other ~593 calls are untouched, and the two checks are not yet wired into CI. Three things were measured and are worth knowing before any migration: a pure RENAME of a Rust argument does not break the page (the generated wrapper takes the value positionally, so the page never spells the IPC key at all - the old `valid_to`/`option_id` class of bug becomes impossible); a struct field with its own doc comment makes the JSDoc exporter emit invalid JavaScript, so `Bound`'s two field comments moved into the type's own doc; and the exporter cannot be a `#[test]`, because a test binary gets no Windows manifest and dies before `main` with STATUS_ENTRYPOINT_NOT_FOUND once it links enough of tauri to import `comctl32!TaskDialogIndirect`. The exporter therefore ships as a normal dependency and is credited in `THIRD-PARTY-NOTICES.txt`.
