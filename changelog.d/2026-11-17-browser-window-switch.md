That suite has no `.click(` of its own - the click is in the module it drives, `backend/jarvis_chatbot_web.py:914` (`box.click()`, the message box) and `:933` (`btn.click()`, the send button) - which is why a plain grep for `.click(` found only `test_browser_engine.py` and looked like the wrong suite. So "is Playwright installed?" - the only browser-half gate each suite had - became TRUE in a required job, while `run_suites.py`'s skip-by-name layer was already disarmed by the opt-in, and all four suites really drove Chromium there. Honest limits: no CI run was triggered for this change, and the browser halves were deliberately not executed - the code-only halves were run on this PC with Playwright's browser path emptied (`test_chatbot_sites` 291, `test_chatbot_gemini` 26, `test_handoff` 108, `test_support_widget` 10 passed), with three pre-existing `%TEMP%` access-denied failures that reproduce in three lines on unmodified code. **The other half, later the same day: the browser install itself is gone from the required job.** Giving the window its own switch stopped a *window*, but it left a Playwright *browser* installed in a REQUIRED job, so a required check could still launch one, and "nothing sets the switch" was a promise rather than a mechanism.
