- **A note's "is it pinned" question can now take the folder it was asked about (2026-11-17).** Field-tested on the live install at SOURCE-COMMIT `02332ecc514c` (`FIELD-TEST-ALL-2026-11-17`, Step 4 row 6): `is my workout log note pinned` was refused with *"That name matches 2 notes … so nothing was changed - say the note's folder and name"* - false about a read, which changes nothing by definition - and the sentence that refusal recommends, `is my Workout Log note in Private & Shared/Workout pinned`, reached **no intent at all**, so the 8B model answered that it could not see the owner's notes. The folder is now an optional part of `_NOTE_FLAG_QUESTION`, and the intent uses it: the name is resolved by the one resolver and the folder then **chooses among that name's own candidates**, matching case-insensitively, accepting the folder's last segment ("in Workout") and any folder under the one named. Resolution deliberately no longer goes through the exact-path tier by way of a `folder/name` string, because that tier compares byte-for-byte and a folder typed in other capitals fell back to the basename tier, which cannot see a folder at all - so the reply's own suggested sentence asked for itself for ever. An ambiguous name is answered in READ words from the resolver's own candidate list, each note's title beside its folder and then *"Say the folder and the note's name, so one is chosen."*, instead of the write lane's *"nothing was changed"* and its write-shaped example; a folder that holds no such note is said plainly rather than ignored, and a yes/no question is never answered by reading a note's body. Three more repairs came out of the review of that path, all in the same read: front matter that never closes is now **unreadable** rather than *"Yes, pinned"* (`_note_flag_state` returned the value before checking the closing `---`, although its own docstring promised otherwise); a possessive or the flag word itself is no longer read as the note's name, so `is my note in the inbox pinned` asks *"Which note?"* instead of *"No note in your vault is called \"my\""*; and a missing notes editor is reported as itself rather than as an unreadable vault. Read-only throughout: no card, no write, no route, no setting and no tier changed, and every sentence that matched before matches as it did.
