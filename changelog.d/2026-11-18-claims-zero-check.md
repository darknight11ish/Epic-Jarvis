- **A claimed suite that passed nothing is no longer a pass (2026-11-18).** The claims register could still be fooled one way: `tools/check_claims.py` read the skips a suite PRINTS, so a suite that exited 0 having executed zero checks - a loop over an empty list, a guard that can never be true, a `main()` that returns before the first check - printed no skip to read and was indistinguishable from one that had verified the claim. It now holds `backend/run_suites.py`'s own zero-check rule, using the runner's own count parser (`run_suites.counts`, imported, not copied): a `test:` row is withheld when its suite exited 0 with `passed == 0`, and the failure names the suite, its counts and the two legitimate fixes - make the suite run a check, or record the environment skip with its reason and the date under `ENVIRONMENT_SKIPS`. That entry is the one exemption, and it needs the suite to have really printed the skip it covers: an entry records why a skip happened, it cannot document a skip that never happened. A printed skip is still never a pass, and a skip beside checks that really ran is unchanged. The plain register run now also reports how many checks the `test:` rows watched, so a green run cannot be read as one that watched nothing.
