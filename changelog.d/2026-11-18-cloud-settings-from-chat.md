- **The hybrid/cloud settings can be asked about and changed from chat, and every answer names the file it read (2026-11-18).** The owner's request: from the phone's chat, ask what the provider and escalation settings are and change them. The questions are answered by the fast path in a second, with no model, from THIS PC's own files - `cloud-choice.json` for the chosen service, `escalate-cloud.json` for the standing switch, `chatbot\api-money.json` for the monthly cap and the month's ledger - and each sentence says which file it read and when it was last saved ("Read from chatbot\api-money.json (saved 31 Oct 2026)"). A missing file says "not set up" in plain words and what that means (no cloud path at all; no switch has been saved; no cap means the service is not used, not unlimited). "What does escalation actually do?" carries the refusal list: email, files, notes, credentials, stored memory, a picture, the screen, a private question, a pasted secret and a conversation that has already read outside text never go, and Lockdown, every privacy check and the monthly cap still stop a turn. The changes reuse the doors that already exist and add no route and no file writer: the service through `jarvis_presets.apply_cloud`, the switch through `jarvis_presets.cloud_escalate` (ON is ONE `change_own_config` card and writes nothing before the yes; OFF is instant and cardless, the existing rule), and the monthly cap through `jarvis_chatbot_limits.change` - the same door behind `POST /api/chatbot/money`, which is why the cap IS changeable from chat: an amount above today's cap raises ONE `raise_api_limit` card (tier ask, Windows Hello or the asking phone's own fingerprint) and writes nothing before the yes, while lowering it is cardless. A provider name the PC does not know is refused with the list read from `jarvis_chatbot_api.PRESETS`, never guessed at, and a known name keeps the older cloud-provider door so two doors never compete for one sentence. No key is read, shown or logged: the module never calls `key_saved` or Windows Credential Manager. Both apps need no client change - the answers and cards ride `/api/chat`. Tests: `backend/test_cloud_settings_chat.py` (101 checks over a temporary settings folder: every shape in every file state, the older doors keeping their sentences, the switch card writing nothing when denied, the cap card writing nothing when denied and the lowering cardless, the unknown-name refusal, and the module's code read to prove it reaches no key store).
