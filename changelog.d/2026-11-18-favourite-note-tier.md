- **"Add this to my favourite note" now picks a note, because the favourite flag is a resolver tier (2026-11-18).** A note's `favorite: true` front matter was real and persisted - a create writes it, and a carded `set_property` edit writes it - but nothing read it for anything except the one yes/no question "is my X note favourited?", so "especially if I made them my favorite" meant nothing. `jarvis_notes`' ONE resolver now has a fourth tier: `path -> basename -> alias -> favourite`. It sits LAST on purpose, because a favourite is a quality of a note and not its name, so an explicit path, file name or `aliases:` value always wins; and it fires only when the owner's words ARE a favourite word ("favourite"/"favorite"/"favourites", see `_FAVOURITE_WORDS`), so "garden bucket" keeps refusing. The three answers are: **one** flagged note resolves at the `favourite` tier and its result carries a `said` sentence naming the note it picked ("Using "Workout Log", the only note in your vault marked as a favourite."); **two or more** is the resolver's existing `ambiguous_section` refusal with every candidate listed and nothing chosen ("2 notes in your vault are marked as favourites, so "my favourite note" could be any of them: Gym.md; Workout Log.md. Say the folder and the note's name, so one is chosen."); **none** is an honest `not_found` that names what it looked for ("No note in your vault is marked as a favourite, so "my favourite note" names no note: nothing was chosen and nothing was created."), never a fuzzy pick. `create_target` learned the same lesson: a create shaped lookup of the favourite words comes back refused rather than proposing a new note called `favourite.md`. Read-only throughout - it reads the same first bytes of each note the `aliases:` tier reads, honours the hidden-folder and "Protected from Jarvis" rules because the rows come from the one vault walk, opens no socket, writes nothing, adds no route and no card, and changes no plate. A hand-written British `favourite:` key counts exactly like Jarvis's US one, and a `favorite:` line in a front matter that never closes does not count at all (Obsidian reads it as body text).
