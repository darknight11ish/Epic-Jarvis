- **The lane launcher that decides a GPU lane's cards is now in the repository, checked against the live machine, and a lane table the machine cannot honour can no longer deploy or pass CI silently (2026-11-18).** On 2026-11-18 the worst confusion of the night was structural: the script that pins an Ollama lane's graphics card(s) lives at `%LOCALAPPDATA%\JarvisOllama\start-lane.ps1`, outside this repository, and two of its lines (`$env:CUDA_VISIBLE_DEVICES = $GpuUuid` and `OLLAMA_MAX_LOADED_MODELS = '1'`) decide how every preset behaves. A pull request changed the repo's lane table to say the everyday lane on 11436 runs across all three cards; CI was green, and the machine could not do it - its logon task passes ONE `-GpuUuid`, and a measured load grew the RTX 2060 by 3,713 MiB and the other two cards by 0 MiB each. Now: `scripts/start-lane.ps1` is a tracked copy of the live launcher whose header says it is a copy, where the live file lives, and that editing it alone changes nothing on the machine, and whose TASK/GPU rows record the two logon tasks' exact `-GpuUuid` values and the three card UUIDs. `tools/check_lane_launcher.py` compares that copy with the live file and FAILS naming both paths, both line numbers and both differing lines (one changed character is enough); it also compares the tracked task table with Task Scheduler, the tracked cards with `nvidia-smi -L`, and the repo's `jarvis_presets.LANES` card claims with the cards the tracked tasks grant - printing "2-step deploy: update the lane task" with the exact task and the exact `-GpuUuid` value it should carry. An absent live launcher prints, in those exact words, "not checked: no live launcher on this machine" and exits 3 - never a pass. `tools/reconcile_live_backend.py` runs the same preflight before it plans and refuses a one-step deploy (exit 2 in the dry run too) when the repo and the machine disagree; `--allow-lane-launcher-mismatch` is the explicit override, and CI's audit job runs the repository-only half. `backend/test_check_lane_launcher.py` (67 checks, fixtures only) proves the comparison catches the changed `CUDA_VISIBLE_DEVICES` character, a changed port, a changed `-GpuUuid`, a changed card list, the three-card lane claim and the two-step wording; `backend/test_reconcile_live_backend.py` (754 checks) proves the deploy refuses on a disagreement, does not refuse on "not checked", and passes the override through. No live file, task, lane or model was changed: this makes the disagreement visible.
