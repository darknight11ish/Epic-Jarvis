- **A package install can no longer scatter its temporary folders into the repository, and a checker now finds the folders if one does (2026-11-18).** On 2026-11-18 a delegated agent ran `pip` with the repository root as its working directory and TMP/TEMP inside the tree; pip left seventeen `pip-metadata-*` and `pip-unpack-*` folders at the root, untracked and one `git add -A` from being committed, until somebody noticed by accident. Two guards close it. `tools/check_package_install_context.py` refuses a `pip` OR `uv` install whose working directory is the repository root or whose TMP/TEMP (or `PIP_CACHE_DIR` / `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `UV_TOOL_DIR`) resolves inside the repository, naming the offending folder and saying "run the install from a scratch directory, or set TMP/TEMP outside the repo"; a context it cannot judge - an unknown manager, a platform that is neither Windows nor POSIX - prints "not checked: <why>" and exits 3, never passing. `--run -- <command>` wraps an install and refuses before the command starts; the audit job's own `python3 -m pip install` step now goes through it as a preflight, so the job cannot install after a working directory or TMP regression. `tools/check_package_manager_temp_artifacts.py` is the second half: it fails on a tracked or untracked top-level path matching pip's temp folders, a root `*.dist-info` or a TRACKED root `node_modules`, names every path and prints the `Remove-Item` / `rm -rf` / `git rm -r --cached` commands that remove it, and does not fire on a `pip-*` name inside a test fixture, under the ignored `.dsh-scratch/` or on an untracked `node_modules` (`.gitignore` line 36 already covers it). `backend/test_package_install_guards.py` (71 checks) proves both can fail on a real fixture repository it makes and removes, that the refusals carry the folder and the fix, that the wrapper never runs a refused command, and that both are clean on this tree; both guards are wired into the `audit` job.
