- **The phone can ask Jarvis to update itself, and ONE card decides (2026-11-18).** The owner's ask: "the desktop program can update itself, but only at the PC, and only after Windows Hello there. I want the phone to be able to ask for that same update, with the phone's own fingerprint." Two routes (`GET /api/update/status`, `POST /api/update/request`) raise the SAME card the chat already raises - action `desktop_update`, tier "ask" - through the gate; nothing is downloaded, installed or changed before the owner's yes, and the request body cannot carry a command, a path or a version. The card is answered on the PC with Windows Hello as before, and now also on the phone with that phone's own fingerprint or PIN over a one-use challenge (`desktop_update` left `PC_ONLY_ACTIONS`, exactly as `raise_api_limit` did on 2026-10-11). After a phone's yes the PC runs `scripts/update-jarvis.ps1` in a detached helper that holds the shared `update-in-progress.lock`, so the desktop's own updater and this one cannot patch the machine at once. The phone's own screen for it is the next lane, recorded in `docs/ARCHITECTURE.md` section 8 as one-sided on purpose for now, and no real phone has driven the card yet - that field test is owed and JARVIS-API section 226.5 says so.
