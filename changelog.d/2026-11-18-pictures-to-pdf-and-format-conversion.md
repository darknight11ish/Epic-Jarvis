- **Pictures into ONE PDF, and one picture into another format (2026-11-18).** The `my_files` tool learns a `convert` action: one or more pictures become one PDF in the order given, or one picture becomes PNG, JPEG, WebP, AVIF or TIFF. Each conversion writes ONE new file and asks ONE approval card (its own action, `convert_images`, tier "ask"); a taken name gets a numbered sibling like `photo (2).pdf` and the card says so, a path the caller named that exists is refused, and the destination is opened with `O_EXCL` so nothing that exists can ever be replaced. The PDF half uses **img2pdf**, so a JPEG's own compressed bytes go into the PDF unchanged - the suite looks for the input bytes inside the output rather than trusting the claim - instead of Pillow's PDF writer, which re-encodes RGB through its JPEG encoder and defaults the page to 72 dpi. The picture half uses Pillow and tells the truth about quality: PNG and TIFF are lossless, JPEG/WebP/AVIF are **lossy** and the sentence says the copy is "not identical", and a picture with transparency saved as JPEG is flattened onto WHITE in those words. Sources are checked by sniffed content (a text file called `photo.png` is refused) and are never modified; the conversion runs in a bounded child program with a scrubbed environment. New dependencies `img2pdf` (LGPL-3.0) and `pikepdf` (MPL-2.0) are in `backend/requirements.txt` and the hash-pinned `backend/requirements.lock`, `THIRD-PARTY-NOTICES.txt` gains those two credits plus the missing **FFmpeg** one (required, never bundled), and the feature is rowed in `features/features.json`. Honest limits: HEIC is not read, a PDF's page size follows each picture's own DPI, and this is chat-only (no new route, so both apps can ask).
