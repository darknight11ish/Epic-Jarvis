- **An unknown lane name no longer becomes a cloud request (2026-11-18).** `jarvis_chatbot_api.lane_service()` mapped any lane name it did not recognise to DEFAULT_LANE or the chosen cloud provider, so `lane_service("qwen3.5:9b")` answered `("deepseek_api", "deepseek-flash")`: a lane field holding a local model's name could have sent a private turn to a cloud service. It now fails closed - only a name in `CLOUD_LANES` names a service, and everything else (the empty local name included) returns `("", "")`. `cloud_lane`, `lane_key` and `lane_state` answer with no address, no key and no model for such a name, so the HUD's request builder can only choose the local endpoint; `lane_status`'s fallback still names the PC's cloud default, not an unknown name. Tests: `backend/test_chatbot_api.py` (unknown name, empty name, every real lane, and a private turn cannot obtain a cloud URL from an unknown name) and `backend/test_options_understanding.py`.
