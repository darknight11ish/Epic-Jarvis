- **The app's update proof is bounded, and a deploy-managed install is recognised before it starts (2026-11-21).** The in-app "Update everything" press and the automatic finish both run `tools/update_backend.py`, and both used to run the full ~48-65-minute CI suite list as their proof (measured 2026-11-21: the desktop's bound ended a healthy run at 48m 10s). The default proof is now a bounded post-update subset of 9 checks in 4 phases - `py_compile` + imports for every shipped module from the live folder, the live HUD's answers to `/api/version`, `/api/status` and `/api/presets`, the egress census, the gate/egress/reconcile/projects smoke suites, and look-spec + config agreement - reported as `PROOF: Step N/4 - <phase> - x of y` with the five-minute heartbeat kept for quiet stretches. The full sweep is a developer run only (`--full-proof`), and a bounded pass ends "proven by the bounded checks (9 of 9): a subset, not the full suite", never claiming the full check. The backend half's route is also detected up front: a deploy-managed install (evidence: `SOURCE-COMMIT` beside `VERSION`, and/or `_jarvis-deploy-backup-tool-*` backup folders) goes straight to `tools/reconcile_live_backend.py --apply`, skipping the measured 51-hunk patch-stack refusal, while a legacy patch-only install still starts with `scripts/apply-patches.ps1`; a deploy refusal is reported verbatim and "both or neither" is untouched.
