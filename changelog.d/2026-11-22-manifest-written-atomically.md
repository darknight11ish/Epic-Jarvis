- **The deploy manifest is renamed into place, so a killed write can never leave a truncated record (2026-11-22).** `tools/reconcile_live_backend.py --apply` used to write `DEPLOY-MANIFEST` in one `write_bytes` call; a kill during that write could leave half a JSON document, and the updater then refuses the install in the corrupt marker's own words. `apply_deploy_manifest` now writes the same bytes to a sibling `DEPLOY-MANIFEST.tmp` in the live folder and `os.replace`s it over the target, so a crash leaves either the old valid record or the new valid record - never a partial one, and never a guessed seal. Success is byte-for-byte unchanged: the same deterministic JSON, the same `manifest_sha256`, the same backup of the old record, the same read-back proof, no new option and no new output line. A failed rename is reported as `DEPLOY-MANIFEST could not be written (...)` with the old record untouched; only a sibling temp file can be left behind, and the next run overwrites it. `backend/test_reconcile_live_backend.py`'s new `t_a_manifest_write_killed_before_the_rename_keeps_the_old_valid_record` monkeypatches `os.replace` to raise between the temp write and the rename, proves the temp file held the complete new record, and asserts the previous manifest is still byte-identical and still parses and validates; the suite is 894 checks, 0 failed. The same test fails on the tree before the change, where the old `write_bytes` path replaced the record and returned `{"ok": True}` without ever calling a rename.
