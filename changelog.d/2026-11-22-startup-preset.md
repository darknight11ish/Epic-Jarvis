- **The General preset loads by itself when Atlas starts, and you can set which preset that is (2026-11-22).** A new setting, `~/.openjarvis/startup-preset.json` (`{"preset": "<id>"}`, absent means none), picks ONE local preset to load every time Atlas starts. It is set through a new route, `POST /api/work/startup-preset`, or by asking in chat ("load the General preset when you start", "make General my default preset on startup", "stop loading a preset when you start"). Setting one raises ONE `change_own_config` card whose words say what happens at the next start; clearing is instant. The start-up load takes the ROUTE's own road (`POST /api/work/apply`'s `_apply_body(..., owner_ui=True)`), so the lane, the model switch and the persisted lane are the same code a click runs, and it raises no second card. It asks Ollama for `keep_alive: -1` through that same loader, so the idle timer cannot evict an eager preload five minutes later - bounded by the one-preset-at-a-time rule and by your own rest hours, which are respected at start. It runs in its own thread, so a 26B cold load never delays the HUD's first request. The old restart reconcile still runs when the configured preset cannot load, and `restart_reconcile` now says which happened - never a silently forgotten choice. `GET /api/work` carries a read-only `startup_preset` block. No new gate row (`change_own_config` already covers it), no phone route, and the desktop Settings page is untouched by this change. The route is wired by `jarvis_presets.install()` - the module `presets.patch` installs - so no patch dispatches it and no patch was changed; a test builds the HUD from the real patch stack and proves the path reaches the writer through every wrapper installed after it.
