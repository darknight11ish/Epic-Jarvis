- **The GitHub re-run tool's description fits the per-tool token ceiling again (2026-11-23).** The previous feature commit added the "name it by pull request plus check" form to `github_rerun_workflow` and took its model-facing schema from 262 to 447 tokens, against `backend/test_tool_text.py`'s `PER_TOOL = 300` ceiling; it also left `tools/tool_eval/jarvis_tools.json`, the saved fallback copy of the tool list, describing the schema from before that commit. Both are fixed here, with no test deleted, no assertion loosened and no ceiling raised. The description keeps what the tool does and when to use it - ask GitHub to run an existing workflow run again, named by its run id or by a pull request number plus the check's name ("face-shots") - and keeps the approval-card sentence and "changes no code or setting and never merges, pushes, commits, closes or deletes anything". What went is repetition and mechanism: "with the same code and settings it ran with before" is what a re-run already is and is restated by "changes no code or setting", the head-commit-check resolution is how the tool finds the run rather than something the model must do, and each parameter description now says only what the argument is. Measured with the suite's own 3-characters-a-token rule: 447 -> 297 tokens. The saved fallback has no generator in this repository, so it was regenerated from the live list the way the eval tool reads it (`AG.TOOLS[n].schema()` for every tool but `browser_control`, `json.dumps(..., indent=1, ensure_ascii=False)`); only the `github_rerun_workflow` entry changed. `backend/jarvis_agent.py` and `jarvis-backend/jarvis_agent.py` stay byte-identical, and the tool's name, arguments, required list, gate action, approval card and run-time behaviour are unchanged.
