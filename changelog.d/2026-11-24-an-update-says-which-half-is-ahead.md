- **An update now says which half is ahead, instead of only that the two differ (2026-11-24).** Measured on the owner's PC that evening, in his own words: "Jarvis Desktop is now 0.2.502; it was 0.2.495 when the Windows installer started. The backend half had already finished before the installer ran, so both halves are done. Backend at b0926662ec0b, app at 18ffc17611fe; they differ." "Both halves are done" and "they differ" cannot both be true, and the machine was in the benign state: git proves the app's commit `18ffc17611fe` is an ANCESTOR of the backend's `b0926662ec0b`, so the backend was one commit AHEAD - newer, not stale - which is normal, because a desktop release is only built when `jarvis-desktop/**` changes while the backend follows `main`. The version numbers could not tell them apart, because a desktop version is a CI run number: two different trees both said 0.2.502. Two clauses were wrong and both are fixed. `update.rs`'s `backend_finished_sentence` ended "so both halves are done" from the backend half's own state alone, and the commit sentence was appended after it; `ending_words` now says that clause only when the two commits are the SAME release, and the state sentence says only what the backend half did. `backend_update.rs`'s `halves_line` could say only "match" or "differ"; it now classifies through git's own ancestry answer - `Same`, `BackendAhead` (newer, said as not a failure, "the next desktop update catches up to it"), `AppAhead` (the one direction that is a problem, naming "Update everything"), `Unrelated` (two divergent lines, "do not guess, read the update log") and `Unknown` (a commit or git could not be read). "They differ" is four different machines and the owner needs the one he has. Nothing is guessed: an unreadable answer is `Unknown`, never `Same`, so a missing git can never read as a match. Held by 51 `backend_update` tests and 109 `update` tests - including the new `one_release_is_the_only_thing_that_may_say_both_halves_are_done`, and a rewritten assertion that would have caught the card the owner read.
