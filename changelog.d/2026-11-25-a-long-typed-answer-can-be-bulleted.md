- **A long typed answer can be bullet points, adjusted in Settings or through chat (2026-11-25).** The owner asked: *"if atlas has a long response can it be put with bullet points"*, and *"make sure I can adjust it in the settings and adjust it through chat if i want to"*. `jarvis_answer_style.py` keeps one setting beside `manner.json` with three styles - `auto` (a plain sentence first, then a bullet per part once an answer has three or more parts), `bullets` (any answer with more than one part), and `prose` (never a bullet, and **no prompt note at all**, so turning it off restores exactly the bytes the model had before). `jarvis_agent.with_style_note` now puts that note into the request **after the Jarvis rules and before the newest user message**, on a TYPED turn only: a spoken turn keeps `SPOKEN_NOTE`, which forbids lists because it is read aloud, and a conversation's first question is unchanged byte for byte (the note starts with the first follow-up, which is what keeps `backend/test_agent.py`'s five leading-message pins green without editing them). A chat sentence changes the same value ("use bullet points", "no bullet points", "plain paragraphs", "bullet points when it helps", each also after "from now on ..."), and the desktop's Settings -> How Jarvis talks -> **Long answers** is a three-choice picker whose labels and reasons are the PC's own (`GET/POST /api/answer-style`, installed by the ready plug-in `plugins/ready/answer-style`, so no patch was added). A question that merely mentions bullet points is not a command and still reaches the model. The phone changes the same setting through chat; a phone-side picker is the remaining screen slice.
