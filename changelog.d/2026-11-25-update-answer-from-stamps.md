Nothing is asked of the 8B model, which cannot know any of it - on 2026-11-24 it invented "both halves are done ... The two commits are compared with git's own ancestry answer, so the reply says the update is done and names the commit only when both halves really are on the same commit, calls the benign case (the backend ahead of the app) "one step behind ... nothing is missing" rather than a failure, and names "Update everything" only when the app is ahead or the two lines have diverged. A version number is never used to prove a match, because `VERSION` is a CI run number two different trees can share - both halves said 0.2.502 on that day while holding different code - and a read that fails is named as unreadable instead of guessed past.
