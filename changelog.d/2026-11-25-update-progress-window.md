- **An update now opens its own window with a bar built from real numbers (2026-11-25).** The owner asked on 2026-11-24, verbatim: *"when i update jarvis there should be a pop up with a progress bar"* - before this, a nine-minute run was one sentence in Settings with no position, and a failed run was four paragraphs of prose in a log file afterwards. The window is opened from `update_both` itself, so all three doors (the Settings button, the tray row and an approved `desktop_update` card) get the same one, and no page can open one on its own. Its bar is the backend tool's own `fraction` (or its done/total counts when a legacy run gives no fraction) and the desktop package's own bytes; before the first real number the bar stays hidden and the line says nothing has been measured yet, and 100% is only ever the tool's clean verdict - never a timer, never a fraction event, and never a run with problems. On failure the window keeps the failing file names and the tool's own reasons on screen and stays open until the owner closes it. The installer phase is the one thing it cannot draw - on Windows the installer ends the process that owns the window - so at that point it says what is about to happen (Atlas closes and starts again) and stops the bar, and the next launch's existing reconcile of the pending record says how it ended. Closing the window does not stop the run, and the page says so in words. Settings' own bar is unchanged, and the window holds no command.
