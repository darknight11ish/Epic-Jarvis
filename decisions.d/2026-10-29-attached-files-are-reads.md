- **2026-10-29 — An attached file is a READ, it is cardless unless reading files asks, and it never goes to a cloud lane:** the owner chose "file attachment in chat" for both apps at once, with the design's recommended defaults (a 2,500,000-byte raw cap, 12,000 characters of text to the model, nothing kept on the PC). Three rules follow, and they are the feature. **It is a read, not a write and not a grant:** the PC reads one file, in the one turn it arrived with, and adds no folder to "Folders Jarvis may look in" - so the turn counts as having read outside text, a card raised afterwards says "Proposed after Jarvis read: the file you attached", a later web search or note write in that chat still asks, and `jarvis_gate.latch_taint` latches the conversation private. **It is cardless because picking the file IS the decision a card would ask for** - the same precedent pictures set on 2026-09-29 - and the switch that already exists decides the one case a card belongs to: `read_files_readonly`, so a PC whose owner set "Ask me first" for reading files will card the attachment too (name and size only, never the contents). A second switch for the same act would be the duplicate the audit rules call out, so there is none, in either app. **It never goes to a cloud lane:** `jarvis_router.choose(has_file=True)` answers gate "file" before the private check, the budget, the complexity check and the offer, the manual cloud pick comes through that same call and is refused with it, and `_open()` strips the `attachment` field off every relay request on every hop - the gate is the brace and the strip is the belt, because `cloud-one-turn.patch` keeps exactly the newest user turn and that is where a file's words would ride. **And it leaves nothing behind:** no upload folder, no temporary file (the converter reads a stream through its new `-` stdin mode), no history row, no log line, no memory fact and no learner input, because the file's words live only in the request they arrived in and are never written into `content`. Deliberately not built, now or later: an upload endpoint, a resumable or chunked transfer, a document preview, a second image path, and any "attach anything" share target on the phone.
