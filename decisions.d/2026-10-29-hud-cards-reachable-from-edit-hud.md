- **2026-10-29 — A new HUD card must be reachable from Edit HUD, including for an owner who already saved a layout:** The salvaged HUD slice had deliberately kept the calendar out of the layout registry, with a written reason: `contract/hud-presets.json` mirrors every preset's cards and belongs to another slice, so a registry row no preset carried would list a control Edit HUD could never place. The owner then made it a standing rule: "every easily-accessible feature must be addable to the main screen from Edit HUD". So the card is a real card - `calendar` in `CARD_REGISTRY`, in `MOVABLE_IDS`, in `CARD_DOM`, in all seven built-in presets, and the contract regenerated from the module. The other half is the one that makes the rule true for HIM rather than only for a fresh install: his own Studio layout was saved before this card existed, and a saved layout document is a closed list, so a card it does not name gets no shell and is listed nowhere. `hud-edit.js`'s `withRegistryCards` therefore puts back any movable registry card a saved document is missing, IN MEMORY only - opening the HUD is not an edit, and the first real change he makes saves the document that by then carries the card. It repairs what is missing and nothing else: a card he hid on purpose is still in the document, so it stays hidden. Recorded because it is the general answer, not a calendar detail: any card added later needs a registry row, a preset row, a contract row and this repair, or the owner cannot reach it.
