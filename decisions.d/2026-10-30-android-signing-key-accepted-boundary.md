- **2026-10-30 — The phone keeps the shared debug signing key while it is sideloaded only, and that boundary is accepted on purpose:** Gemini's Q4 ruling on the 2026-10-30 12-hour review put the choice plainly - rotate the shared debug signing key now, or keep it and write down what is being accepted. **Keep it now.** The app is signed with one shared debug key that lives only in the `DEBUG_KEYSTORE_B64` repository secret (`keystore/README.md`), it is sideloaded onto the owner's own phone and is never listed on Play (rule 5 in `CLAUDE.md`), and its only update path is the in-app check and download from this repository's own `client-latest` release over https, with the APK's certificate checked against `UpdateCheck.SIGNER_SHA256` before Android's installer is offered anything (`docs/ARCHITECTURE.md`). This is a recorded boundary, not a claim that one shared debug key is a good release key. **Rotating it is not a one-line change:** Android refuses a build signed with a different certificate over an installed app (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), so the only way through is `adb uninstall com.jarvis.client`, which deletes the app's data - the pairing token and the device id it carries (`TokenStore`, Keystore alias `jarvis_token_key`), the fingerprint/PIN approval key (`ApprovalKey`, alias `jarvis_approval_key_v1`), the three home-screen widget slots' saved choices (`home_widget_*` in the `jarvis_client` preferences), the captured-notifications key, and every local preference - and then the phone has to be paired again with the token from the PC. That is the re-pair ceremony, and it is why the 2026-10-18 decision ("Android signing-key rotation: later, after the current feature work") still stands instead of being quietly dropped. **The boundary must be revisited when any of these becomes true:** the APK is distributed publicly or handed to anyone other than the owner; this repository is made public with its release assets; or the key or the `DEBUG_KEYSTORE_B64` secret leaks - a leaked key is not made harmless by the certificate pin, because an APK signed with the same key carries the same pin. **The rotation path is now one command, and it never fires by itself:** `powershell -ExecutionPolicy Bypass -File .\scripts\rotate-android-signing-key.ps1 -Rotate` makes a new keystore OUTSIDE the repository (default `%USERPROFILE%\.jarvis\keys`), refuses to run without that flag, refuses to overwrite an existing key, reads the alias and password from `jarvis-client/app/build.gradle.kts` instead of carrying them (so no password is written into the repository or printed), prints the new certificate's SHA-256 fingerprint and the exact remaining steps, and changes nothing else - no secret, no CI, no phone, no publish. `docs/DEPLOY.md` section 5 is the same ceremony in writing, with what the uninstall deletes and what only the owner's phone can prove.
