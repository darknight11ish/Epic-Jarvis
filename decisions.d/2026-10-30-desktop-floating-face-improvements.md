- **2026-10-30 — The floating face gets a size choice, opens on the cursor's screen, and is clamped fully on-screen; the size lives in the tray, not a new Settings row:** the owner asked, *"can you improve the PC version as well? do research if necessary for picture-in-picture mode on desktop"*. Decided, after reading the existing desktop picture-in-picture window and researching Tauri 2's and Windows' always-on-top/floating behaviour: the face gains four remembered sizes (160/200/240/300 logical px, default 200) stepped by two tray rows under More… ("Floating face: bigger/smaller"), it opens centred on the monitor **under the cursor** instead of always on the primary display, and a saved position is clamped **fully** inside the monitor it overlaps most (nearest monitor when that one is gone) so a monitor change cannot leave it half off-screen. The size choice deliberately does **not** become a Settings toggle: every toggle in Settings is generated from `backend/jarvis_settings_registry.py` and mirrored in both apps' contract fixtures, so a new row would be a cross-app contract change for a desktop-only cosmetic window — the tray is where the face's own on/off row already lives, and this keeps the change to one crate, two menu rows, no new command, permission, route or approval card. This does not change the window's standing promises: always-on-top by default, never takes the keyboard, no visible text box or button, clicks pass through everything except the animal (click-through remains a separate, unchanged switch), and nothing is decided or approved from it. The phone's own "Floating Jarvis" bubble is a different control and is unchanged; no parity entry is needed because the surface is already desktop-only by design (ARCHITECTURE §8). Deliberately left out of this slice, named so the next pass can pick them up: opacity/"solid" variants of the transparent window (would change the window's transparency promise and likely need a compositor-level effect), snap-to-edge (a drag-end decision that needs a window-move listener and a preference), and double-click-to-hide (the window has no command grant of its own by design; hiding stays on the tray, the hotkey and Settings, which are already reachable).
