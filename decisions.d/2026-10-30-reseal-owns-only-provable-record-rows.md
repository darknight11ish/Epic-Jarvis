- **2026-10-30 — The reseal tool may write the installer's record, but only the rows this repository can prove:** Gemini's Q3 ruling chose `(b')` - put a drifted live install back on `backend/rebuilt/*` plus `$SHIPPED` directly - and that means one tool has to touch `_jarvis-state.json`, which until now only `scripts/apply-patches.ps1` wrote. The decision, recorded because it is a new writer for the thing the whole preflight trusts: **`tools/reseal_live_install.py` owns a record row only when the file it names is one this repository ships**, because then the new hash is `sha256` of a blob in the commit being deployed - a fact, not a guess - and every other key the installer wrote (`written`, `patches`, `patchList`, every row it did not touch) is kept byte for byte, with a `resealed` key added so the record says which tool wrote which rows, for which commit. **A row this repository cannot prove is never rewritten.** The five patched base files (`jarvis_hud.py`, `jarvis_gate.py`, `jarvis_extract.py`, `jarvis_models.py`, `jarvis_skills.py`) are produced by the patch stack, no copy in this repository is their bytes, and writing today's hash there would bless whatever a hand edit or a half-applied patch left - exactly the silence `apply-patches.ps1`'s drift check exists to break. Those rows are printed with both hashes and the run exits 1. `--rebaseline-unprovable` is the explicit way to record them anyway: it is the patcher's own rule for a run with no usable record ("take the current files as the baseline, hashes only", the owner's answer of 2026-10-09), it is off by default, and every row it touches is printed. Two smaller calls ride with it: the tool refuses to run from a checkout at another commit only where it must (every byte comes from `--ref`, so unlike the deploy it needs no worktree guard, and it is run from the branch that carries it until merged), and it reads no `jarvis-backend/` copy of a patched file - that folder is an older snapshot of the same live folder, so copying it would move the file backwards. What this deliberately does not do: repair a patch, run the patcher, restart Jarvis, probe a route, or claim the preflight reaches 0 FAIL on its own - the patch rows move only when the patcher runs.
