- **2026-10-30 — A widget's arrangement is one of four fixed layouts, and that list can only grow in a new app build:** The owner asked whether Jarvis could build him custom Android widgets (2026-10-30). The content half already exists ("widgets you describe", §86, 2026-09-28); the look half is limited by Android, not by Jarvis. So a described widget now carries `layout`, one of `stack` (the default, and what every widget made before this date gets), `big`, `list` or `compact`; the PC's own AI model picks it from the owner's words, plain code checks it, and both the desktop widget window and the phone's home-screen widgets draw it by one rule shared through `tools/gen_widget_cases.py`'s generated `widget-cases.json`. The decision worth recording is the LIMIT: Android fixes a widget's layout when the APK is built - the provider is manifest XML and the drawing is `RemoteViews` over the app's own resources - so no route, setting or model instruction can add a fifth arrangement, and "Jarvis, make it look however I describe" is not a feature that can be half-promised. What can change is this list, in an app build; a value off the list is refused by the PC and drawn as `stack` by the apps, so a newer PC's word never blanks a widget. It deliberately does NOT touch the palette, fonts, images, grids or per-widget accent and transparency: those are the separate queued owner decision recorded in this file ("per-widget transparency, accent, high contrast and a live preview"), and half-building them here would have made that queue's own line untrue. Nothing new is approved: same blocks, same sources, the same five Quick Settings tile actions, the same App-lock hiding and the same stale-link gate, and no new route.
