- **2026-10-31 — Jarvis knows which app the owner is talking from:** The owner's requirement: "Jarvis must know whether the owner is talking from the Android app or the desktop program, and tailor its answers/features accordingly — and this must work by default (no setup)." Measured before this change: the phone still sent only the legacy `X-Jarvis-Client: hud`, so the PC could not tell the two apps apart and no answer named the app. Decided: both clients add one additive header, `X-Jarvis-Surface: phone` / `desktop`, beside the unchanged client header (which the origin and cloud-escalation rules still read); the shipped origin gate reads it once per request; the deterministic quick answers, the feature guide's own `surface`/`where` fields and one model system sentence use it; no setting, no opt-in, no first-run step; a missing header is `unknown` and behaves exactly as before; the header is not authentication, never logged, and adds no route or card. Implemented and proved in this repository (backend `test_surface.py`, phone `SurfaceHeaderTest`, Rust `surface_header_tests`), docs/JARVIS-API.md section 173.
