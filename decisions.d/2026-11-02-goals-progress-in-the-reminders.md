- **2026-11-02 — The reminder area's goals are the existing goals, with a progress log added to them:** The owner asked, 2026-11-02: *"add a goals section in the reminder area and a way for me to record progress there along with talking to jarvis."* `jarvis_goals.py` already keeps the owner's goals, their plans and a weekly check-in (the 2026-09-27 "Goals with one card per step" feature, JARVIS-API §59), and both apps already show them, so the progress log, the `paused` state, done/remove and the four model tools were added to that module and its `/api/goals` routes rather than built as a second "goals" feature. Decided: one store and one route set, because two goals features would be exactly the duplicate CLAUDE.md's fit rule forbids and the owner would have two places holding goals that could disagree. Recording progress is a personal-data write, so it follows the closest analogue exactly rather than inventing a gate: it is cardless like ticking off a to-do item or accepting a goal, the four tools resolve under the existing `_TOOL_ACTIONS` `"todo_add": "auto"` line (no new action, tier, patch or card wording - the same pattern `feature_guide` uses with `skill_list`), and the page that promises every action, `jarvis_asks_first`'s `fixed:goals` row, was extended to say so. The progress log is append-only: no function updates or deletes one line, the only delete is the owner's own Remove of a whole goal (which takes its log), and no model tool can remove or forget anything - so "talking to Jarvis" can add but never throw away what the owner wrote. In a turn shaped by outside text the three write tools are refused (a page or an email cannot invent a goal), while `goals_list` is allowed there and its result is marked as outside text like `coming_up`'s. `create(start=True)` makes a goal open at once with no weekly check-in, which is what the reminder area's Add uses; the §59 draft/accept path is untouched. Two new columns are added to an existing `goals.db` by a guarded `ALTER TABLE` on open, and progress lives in a second table in the same file, not a second file. Evidence: `backend/test_goals_progress.py` (90 checks: origin/token refusals with the store unchanged, list/add/progress/done/pause/resume/remove, append-only, the four tools and the shaped-turn refusal) and `backend/test_goals.py` (142 checks, unchanged); `backend/test_pictures.py` holds the new §182, and `backend/test_gate_tool_actions.py` proves the tools resolve under the existing cardless action with no patch added.
