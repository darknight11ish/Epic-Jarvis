- **2026-11-02 — Habit and mood data are excluded from learning entirely, not merely card-gated:** The second of the life-coach owner decisions (`.dsh-scratch/LIFE-COACH-RESEARCH-2026-11-02/OWNER-DECISIONS.md`, D2). Habit names, the words typed on a tick, mood values and mood words **never become learned facts at all**; the rejected weaker option was the project's existing sensitive-category rule, where a candidate fact is proposed and waits for the owner's yes, which `jarvis_sensitive.py` already applies to health and money. The reason a card is not enough is written in `jarvis_intake.mood_rule`'s own docstring: a card can arrive in the review queue "possibly minutes after a hard moment", which turns a private tap into a question about it. So the exclusion is by construction rather than by permission: `backend/jarvis_habits.py` and `backend/jarvis_mood.py` import no learner and name no fact store, no learner module imports or names either one, and neither holds SQL against the facts table - proven in both directions by `backend/test_learning_exclusion.py`, which also proves that writing a habit and a mood creates `habits.db`/`mood.db` and **no fact store at all**, and that a sentinel written into each lives in that one file and in no other SQLite file in the folder. This is deliberately stronger than the existing rule and does not replace it: `jarvis_intake`'s mood rule ("Moods ... is not a fact. Do not propose it.") stays exactly where it is, so the model is still told not to propose a mood in ordinary chat, and this decision covers the two stores. Neither module imports `jarvis_sensitive` or `jarvis_gate`, so the mechanism cannot be mistaken for a card-gated one later; a test pins both absences. What this does **not** claim: that a model cannot write a fact about the owner in ordinary chat from his own words - that is the existing learning path with its existing rules, and it is not what is being excluded here.
