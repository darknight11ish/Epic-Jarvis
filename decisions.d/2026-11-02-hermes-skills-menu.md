- **2026-11-02 — The skills menu installs only through the existing scanner and ONE card, imports only from this PC, and keeps a skill's scripts inert:** the owner chose scope B of the Hermes-skills research (`.dsh-scratch/OWNER-QUEUE-2026-11-02/HERMES-SKILLS-RESEARCH.md`): a PC skills menu that installs from a folder or a `.zip`, turns a skill off and on, edits it, and imports what is already in `%USERPROFILE%\.hermes\skills` - and **no marketplace and no network install**, so there is nothing to browse and nothing to download. Four rulings are recorded with it. **(1) The install card is the existing one, given one more line.** `jarvis_skills.install()` vets first and then raises ONE `modify_own_code` card; the menu passes the card a sentence (`note=`) saying what is being imported and that a bundled `scripts/` folder is kept inert. `backend/skill-install-note.patch` is additive: with no note the card's words are unchanged. **(2) `install()` now re-checks the gate's TIER, as `refine()` already did.** `jarvis_gate.check` returns `allowed=True` on `notify` and `auto` - nobody asked - so a config that listed `modify_own_code` that way would have installed a skill with no person in the loop. A skill is instructions the agent follows, so the card has to be a real card; `notify`/`auto` install nothing and say why. **(3) Turning a skill off is immediate and deletes nothing; turning it on is a card.** Off MOVES the folder to `skills-off\` and takes its row out of `.index.json`, which is the list `cards()` hands the model - so the skill stops being offered and `load()` cannot find it either - and it does not raise a card, like every other switch that takes an ability away. On is the same scanner and the same ONE card as installing it, because it re-adds instructions the model will follow; a skill that changed while it was off is re-scanned and refused if it now fails. **(4) One request is one card, and import is one card per skill - the owner's brief said "one card" for the import and this deliberately reads it as one per folder.** A single card that installs several skills at once is bulk approval, which `CLAUDE.md` forbids outright, so the Hermes scan is a READ-ONLY list (it copies and installs nothing and raises no card) and each folder the owner picks is installed by its own request and its own card. Hermes-only metadata (`platforms`, `metadata.hermes.*`, `required_environment_variables`) is kept and does nothing here, and a skill's `scripts/` never runs - both said plainly on the card and in `docs/JARVIS-API.md` §178. The phone keeps exactly what it had (the list and Remove); install, turn-on and edit are the PC's alone and `tools/check_parity.py` records why (`docs/ARCHITECTURE.md` §8).
