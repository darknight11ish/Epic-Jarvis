- **2026-11-02 — The phone's generated feature directory is checked against the PC contract, not against counts typed into its test:** The Settings "All features and abilities" list is generated from `contract/feature-controls.json`, and the test that pins its shape counted rows per label with numbers typed by hand (42/2/15/71/12). Those numbers were last corrected on 2026-10-28; six days later the contract held 168 features and the checked-in directory still held 142, and every assertion passed because the test agreed with the stale artifact rather than with the source. Decided: the test READS the contract (its `feature_count` and `label_counts`) and compares the generated rows against it, so regeneration drift fails the test; the typed counts are gone. This is the same rule the repo already applies to twins and to generated fixtures - a generated file is proven against the file it is generated from, not against a number a person remembered to update - and it is why the miss surfaced only when a separate lane regenerated the directory for an unrelated wording fix. Two consequences are recorded deliberately rather than hidden: (a) the regenerated prose quotes the PC's own words, and two rows now name `/api/receipts` and `/api/notion/preview`, which the phone cannot call - `tools/check_parity.py` gained `PHONE_TEXT_ONLY`, a text-only exemption that applies to that one generated file and is void if its GENERATED header ever disappears, so a hand-written file naming routes is still a caller; (b) the directory itself is regenerated by its own tool in this change; no desktop file changed and no owner-visible surface was switched on or off.
