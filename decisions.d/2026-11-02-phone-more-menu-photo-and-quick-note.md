- **2026-11-02 — The phone's Photo row is gone in favour of one Attach a file row that also takes a photo, and Quick note must open where it is pressed:** The owner's words, 2026-11-02: *"in the screenshot remove the photo option because ATTach a file on my Android phone will bring up the option to add a photo"* and *"the quick note button doesn't do anything and I don't even know what it was for in the first place"*. Decided: the phone has ONE row for sending something with a question, "Attach a file", and it opens the system picker filtered for the eight documents the PC already reads plus an image type wildcard while the PC's Pictures feature works - so the picker itself is where a photo is chosen, which is what the owner said his Android file picker already does. A picked image is routed by the pure `AttachFile.goesToPicture(name, mime)` to the existing picture path (`ChatPicture` and `PictureEncoder`: vision, and secrets covered with black boxes before any model sees it) and is NEVER read down the document path; a name whose extension is one of the eight documents wins over a provider's image type, so a mislabelled PDF cannot be swallowed. The Photo row's gate is kept: with `HomeState.pictureOffered` false the picker offers no images, and an image that still arrives is refused with `AttachFile.photoNeedsPictures` in plain words rather than read as a document. The More menu is four rows (New chat, Attach a file, Modes, Quick note) plus Close, and the `MoreMenuWords.PHOTO` constant is removed with the row. Quick note is a real feature - it files the owner's own words into Logseq, Joplin or Obsidian through `POST /api/notes/capture` (`backend/note-capture.patch`) - and the reason it looked dead is that its plate was a `LazyColumn` item inside `ConversationList`: full screen composes no conversation list at all, and in the chat the item sat at the very end where it could open below the fold. Decided: it is a `Dialog` sheet drawn once above both layouts, next to the More menu, with the same words and the same Close, and its dead closed-state `Quiet("Quick note…")` branch is removed with the parameter that kept it alive. Nothing in the backend changes - no route, no approval behaviour, no capability - and the desktop keeps its own photo and note surfaces, so this is a phone-only UI change, not a half-shipped feature. Stated limits: compiled and unit-tested only, no device built or driven from this branch, so the box's fit at 360dp, the keyboard's Send key and the sheet on screen are NOT field-tested (BLOCKED, never a pass).
