- **2026-11-02 — Reminders may ask a question with three of the owner's buttons, and answering is a cardless log:** The owner asked for reminders he can shape himself - *"tell Jarvis exactly how I want the reminder to appear and what interactive elements there are"* - and then, asked how much flexibility, *"as much flexibility or options as I want"*. Decided and built in one lane: a reminder's action gains a fifth kind, `ask`, carrying his own question, up to three buttons in his own words (each doing exactly one of record / done / snooze N), and per-reminder recording destinations (its own history, today's Obsidian note, a goal's progress, a habit tick). Three ceilings are deliberate and were not negotiable: three buttons, because Android draws three notification actions; no button that runs a command, a script or a webhook; and no approval card for an answer, because an answer is a log line, cardless like ticking a to-do, and the phone takes one only while unlocked since it writes a personal record. The schedule grammar grew every N days, every N weeks, several times in a day, a first occurrence and an optional end date, all on the existing rule object so a plain rule is byte for byte what it was. The one thing REFUSED, with its reason in the UI and the docs, is a button that opens a saved file or a page: the desktop's single opener opens a reminder's own action and takes the job id only, so a per-button target needs a second opener in Rust, which is a security surface this lane does not own. Two seams were left deliberately unfinished and say so out loud rather than pretending: goal progress (PR #1105's log) and habit ticks (the life-coach lane) each answer "not set up on this PC yet" and keep the answer.
