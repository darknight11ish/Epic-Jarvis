- **2026-11-02 — The conversation web-search grant ASK rides with web search and is not a Settings switch, and an approval may never be claimed from the owner's words:** The field test of 2026-11-02 asked for the grant in two natural sentences and got NO card, with the model answering "Understood. Search is approved for this conversation." The cause was design, not wording: the two tools shipped as "Safety and sharing" switches that were off, so the model was never offered the grant tool and no card could be raised. Decided: the ask and its instant stop are not switches at all - `jarvis_agent.GRANT_ASK_TOOLS` is offered whenever `web_search` is offered, and switching web search off in Settings takes both with it. Offering the ask grants nothing: the store is still written only after a person answers the card, the action is still tier `ask` and in `NEEDS_A_PERSON`, the scope is still one conversation and `search_the_web` only, the stop is still instant with no card, and nothing is written to disk. The alternative - leaving them as switches and asking the owner to switch them on first - was rejected because it is what made the feature dead on the owner's own PC while telling him it had worked. The second decision is the honesty half: an approval is real only when a real state read says so. The rules block now says an approval is not the model's to give or assume and may not be claimed unless a tool result in that conversation said one is in force; while a grant is live the prompt carries `_grant_prompt_line`'s line read from `web_search_grant` (the same function the search consults), and an answer that claims an approval the store does not hold is corrected in plain words (`_grant_claim_line`, through `postscript_lines`, for both the local and the cloud lane). A wrong correction after a true sentence is worse than a missed one, so an honest denial and a conditional are never touched. No new gate action, tier or `_RISK` row; no bulk or automatic approval; the conversation id is still never written down.
