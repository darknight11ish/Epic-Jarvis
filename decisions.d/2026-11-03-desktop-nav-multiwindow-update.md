- **2026-11-03 — Desktop navigation rides the per-answer route field, a chat window is a HUD page with its own conversation, and one Update press moves both halves:** decided while building the F6 desktop slice. (1) Navigation is the EXISTING `X-Jarvis-Route` path extended with `open_area`/`open_anchor` - one table in `hud_nav.rs` maps an area id to the HUD view/tab, the History sidebar, the Presets menu, Settings at a card, the Brain at a place, Faces, the feature list or a new chat window, and the injected chrome performs the page switch. There is deliberately no `ui.navigate` stream listener: the backend kept navigation on the route field (the F6 research correction, RESEARCH.md F3/F5) and publishes no such event, so a listener would be a doorbell into an empty room. If a navigation frame is ever added it must be label-filtered and its client handler must ship with the publisher, never a broadcast - Tauri event payloads are outside the ACL. (2) An extra chat window is the SAME vendored HUD page with its own conversation id, not a reduced surface: the capability's `windows` now carries `chat-*`, the eight labels are a fixed `&'static str` set so `lock.rs`'s capture sweep and hide loop and `window_memory.rs`'s tracked list can include them without widening their types, and the same conversation in two windows is a focus of the existing window, never a second copy on one transcript. The HUD page is a byte-identical twin of the backend's copy, so its controls are injected by the shell bootstrap rather than forked into it. (3) The Settings Update press runs `update_both` (backend first, desktop second) for the owner's "both are always updated at the same time"; the desktop-only `install_update` survives ONLY for a PC whose backend half cannot run, and that path says in words that the backend was not updated and where to finish it. A read-back handshake compares this executable's version with `GET /api/self`'s `version.app_version` and may say "IN SYNC" only when both sides name the same version; a different numbering scheme is reported as incomparable rather than guessed at. `/api/self` and `/api/conversations` were added to `hud_proxy.rs`'s fixed read allowlist because the HUD page cannot read any route that is not on it.
