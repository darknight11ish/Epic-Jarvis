- **2026-11-04 — "Personalize Jarvis" is finished only when every question has an answer:** This reverses the 2026-11-03 sentence *"A partial retake still marks the question set complete (`completed_version = QUIZ_VERSION`) because the owner has seen the new questions by then"*. The 2026-11-04 audit (DEF-043) measured what that rule did on the merged tree: `apply()` wrote `completed_version = QUIZ_VERSION` after ANY accepted answer while `answered_count()` still reported e.g. 1 of 25, so the first-open offer, the HUD banner and the every-turn chat line all stopped and nothing offered the card again until a version bump - the card's own "show only new/unanswered" filter then had 24 items and no door. `apply()` now sets `completed_version = QUIZ_VERSION` only when `answered_count()` of the document it is about to save equals `len(QUESTIONS)`; a partial apply saves its answers, clears its draft and counts its run, but leaves completion where it was (a file that had completed an older version keeps that version). The merge-on-retake behaviour is untouched: submitted answers still win and every answer the run did not ask about survives. `{"keep_current": true}` remains the one explicit "I am happy as I am" that moves completion without answering anything. The same change makes the every-turn chat line obey the "Personalize Jarvis" notification switch (`jarvis_notify_prefs.read()["setup"]`), because that switch is the owner saying they do not want to be reminded and a chat line is a reminder (DEF-044).
