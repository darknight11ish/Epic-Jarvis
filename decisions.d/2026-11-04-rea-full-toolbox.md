- **2026-11-04 — REA is the full toolbox, behind one card per action:** Asked how far reverse engineering should go, the owner chose "Also install the full REA toolbox" - *"debug and patch, not just read: attach a debugger, watch a running program, use Frida and patch files - the real toolkit, all local"* - plus REA's own package installed by Jarvis and all of its actions exposed through the one `rea_investigate` tool. This replaces the 2026-10-20 static-only slice: `backend/jarvis_rea.py`'s action table is 200 actions (one per REA tool in the pinned `rea-agents@6.7.0` catalog, whose 207 names and catalog digest were measured from the real server on this PC on 2026-11-04, plus `doctor`, `install` and the seven names the first slice shipped), and debugger, Frida, live capture, process-memory, session, export, ADB-read and install actions are all available. The five non-negotiables are unchanged and are why anything is still refused: one approval card per call (so even `doctor` and `install` ask), nothing leaves this PC (a URL, `host:port`, network share or remote endpoint in any setting is refused unless it is loopback), keys are never passed (the child environment stays an allow-list, with REA's own `REA_TOKEN` deliberately absent), and the MIT package stays MIT. The one by-name refusal left is the six ADB device mutators, and it is cross-module ownership rather than a core rule: phone changes already belong to `control_phone` / `[phone_apps]`, so REA keeps every ADB read and capture and none of those six. The nanny restrictions the static-only slice added - debuggers, Frida, runtime capture, export, `close_binary` - are gone, along with `debug_with_gdb`, a name no REA tool ever answered to. Jarvis installs the pinned package itself after its own card and refuses to treat a package as ready if it carries an install lifecycle script or names a known analytics or telemetry service; the four-point audit's static egress scan did not exist in code before this and is now real. What this deliberately does not do: no HTTP route, no gate action, tier or switch change (the gate mapping `rea_investigate` -> `run_shell_on_host` at tier `ask` is untouched), and no claim that a file was patched when only a session's memory changed - REA 6.7.0 has no patch-a-file tool. The ruling's other three guardrails are enforced in the same module rather than left as a residual: a credential store (LSASS, Windows Credential Manager, a browser's saved-login files) is refused as a target by process name, file name and path; a debugger or Frida command that can write is refused unless it aims at a NEW `.patched` copy, with Windows, Windows Defender and Jarvis's own programs never a patch target and a before/after SHA-256 receipt recorded for an allowed write; and every live session carries `duration_limit_sec` (60 by default, 300 at most) on its one card, caps its own call, and is detached in a `finally`. Real REA analysis stays NOT-TESTABLE on CI (no engines, no pinned install) and is not claimed as tested; `backend/test_rea.py` (328 checks) covers the table, the refusals, the three guardrails against fakes and a fake clock, the install and the scans.
