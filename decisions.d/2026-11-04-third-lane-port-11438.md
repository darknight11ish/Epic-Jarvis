- **2026-11-04 — The third card's lane gets port 11438, and no lane port may ever be shared by default:** `jarvis_second_card.DEFAULT_THIRD_PORT` becomes `11438`. It was `11436` from 2026-09-28, but the owner's everyday lane moved onto `11436` on 2026-10-16 (PR #440) and `_third_port()`'s guard only compared against `11434` and `11435`, so the shipped default collided with a running lane and nothing noticed. `11437` was the obvious next number and is **not** free - it is `jarvis_screen_picture.DEFAULT_PORT`, its own Ollama copy - so the first genuinely free port is `11438`. The rule this records is the general one, not the number: a lane port is a constant that another lane's default may not claim, so `jarvis_second_card.LANE_PORTS` now names every lane port this repo uses (`11434`, `11435`, `11436`, `11437`, `11450`), `_third_port()` misses all of them under any configuration, and a shipped default that lands on one of them raises `RuntimeError` at import instead of being quietly stepped past - a silent step-up would have hidden this defect for as long as it hid. The numbers are literals in `jarvis_second_card` (importing the lane modules from there would be a new cycle) and `backend/test_second_card.py`'s `t_third_port_is_disjoint_from_every_lane_port` reads each owning module's own constant, so a lane moving again fails a test rather than a lane. `jarvis_screen_picture._TAKEN_PORTS` still lists only `11434`-`11436`, so a hand-written `[screen_picture] port = 11438` could still collide with the third lane; that stays a Lead decision because it means a second module and its own test.
