- **2026-11-04 — VoiceStudio joins Jarvis as an EXTERNAL loopback sidecar, never as code in this repository, and the measured verdict makes it demand-only and serialised:** The owner's Q3/Q4/Q5, forwarded 2026-11-04, decided five things, and each one is a promise rather than an implementation note. (1) **Separate program, over a socket.** VoiceStudio is AGPL-3.0-only and this repository is MIT, so the only arrangement kept is the one the licence lane called clean: the owner installs and runs the unmodified program on this PC, outside this repository, and Jarvis sends it HTTP requests on `127.0.0.1:11439` and reads audio back. No file, module or weight of it is copied, imported or bundled - importing its package into Jarvis's process would make one combined work and would make this tree's MIT label false, and copying its source into a published MIT repository is conveying. `THIRD-PARTY-NOTICES.txt` names it as an external program for exactly that reason, and `backend/test_voicestudio.py` proves the client's imports are the standard library plus this repository's own modules. (2) **On demand, never resident.** The measured verdict is CONTENTION: beside Jarvis's own two resident models the 8 GB card had 382 MiB free at its peak, the driver paged ~1.9 GB into system RAM, and the private memory went from 1,698 MB idle to 6,721 MB with a model resident. So there is no boot task, no service and no logon entry; the program is started when it is needed by `tools/voicestudio_sidecar.ps1 -Start` and released again with `-Stop` (or by its own 900 s idle unload), and the launcher refuses to start below a measured 5,200 MiB free on that card rather than repeat the contention. (3) **The 2080 SUPER only, pinned by UUID; the 2060 and its lane are never touched.** The launcher reads `nvidia-smi -L`, pins the one card whose name contains `2080` by UUID because indices can reorder, refuses when it cannot find exactly one, and never falls back to the other card. The 11436 lane (the RTX 2060, the everyday model) is never queried, never unloaded and never named in a command the launcher prints. When a Jarvis model is in the way it names the 11435 lane's own model and prints the one exact line that unloads it, for the OWNER to run: the launcher never unloads anything itself, and `tools/measure_voicestudio.py` refuses unloads too. (4) **Weights are personal, non-commercial use only, and never shipped.** The model licences are not the AGPL: `k2-fsa/OmniVoice` is CC-BY-NC (plus Higgs Audio 2 and Meta Llama 3 terms) and `eustlb/higgs-audio-v2-tokenizer` has no licence in its metadata. Rule 5 makes non-commercial acceptable for this build and removes nothing else: nothing is redistributed, Jarvis never downloads a weight, and every engine and voice dossier the client returns carries `license_class` of either `commercial_ok` or `personal_non_commercial_only` - with no engine `commercial_ok` today, on purpose, because VoiceStudio's own inventory says no model record makes that claim. (5) **The first-run licence gate is the owner's yes, once, in VoiceStudio's own terms.** Until both are accepted every speech request answers 403 `model_licence_required`; the client recognises that answer and returns plain words naming both repositories with the exact two commands and the fingerprint read from the server - and never sends the acceptance itself, because a program that clicked yes to someone else's terms for the owner would be the one thing this feature must not do. The feature ships OFF behind `[voicestudio] enabled = false`, because a second-card/optional-model feature keeps its own switch off until the owner turns it on, and this slice adds no route and no card: the read-only questions answer, speaking does not, and `jarvis_speech.py` does not import the client yet. The next slice wires the speaking voice and adds the one-card Settings switch; only then does ON mean "Jarvis may speak with it".
