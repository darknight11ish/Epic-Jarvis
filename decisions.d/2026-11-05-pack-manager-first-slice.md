- **2026-11-05 — Packs, first slice: the recommended defaults, and the one the owner can still overrule.** Built to the owner's recommended answers in `Needs Owner.md`: **D1** one combined scan report on ONE install card plus a saved receipt (not a separate inspect step, not a summary line), **D2** a folder or a `.zip` on this PC first (no curated index, no git commit), **D3** prompt-only skills first - a code pack is refused in one sentence before any card - and **D4** an unsigned pack may be installed with `NOT VERIFIED - unsigned` written on the card and in the receipt, because this repository has no signing key and "signed only" would install nothing. Each of those four is a default, not a ruling: the owner can choose 2 or 3 for any of them and the change is the source list or the refusal rule, not a rewrite. Two things are recorded here rather than hidden. **(a) Installing and enabling stayed two acts, and nothing is enabled implicitly:** the copy lands, then the existing off move puts it in `skills-off`, so the model is never offered a pack the owner has not turned on - the one-card install approves the FILES, and the existing ON card approves the reading. **(b) PC-only with Windows Hello is NOT added by this slice**, though the brief asked for it: this feature was built to need no new gate action and no patch, and the only two ways to get it are a new action name (a gate patch) or adding `modify_own_code` to `jarvis_owner_check.PC_ONLY_ACTIONS`, which would also make the phone's `plugin_switch` ON and every skill install and edit refuse from anywhere but this PC. That is a real loosening of what the phone can do, so it is put to the owner as a choice instead of taken: say "make installing a pack PC-only with Windows Hello" and it becomes its own action plus one patch; leave it and the card stays the ordinary `modify_own_code` card the Skills screen already raises.
