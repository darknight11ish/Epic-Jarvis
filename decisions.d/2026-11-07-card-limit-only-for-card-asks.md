- **2026-11-07 — A card limit may refuse only a call that asks for a card, and a "nothing ran" correction must be true of the turn:** The #1209 follow-up audit measured seven ways the new action-request answers could still be false, wrong or needlessly refused, and the two general rules matter beyond the seven. **First: the per-answer card limit is a limit about cards, so it may only refuse a call that would RAISE one.** `CARDS_PER_TURN` was read before the action in the cloud-escalation tool, so a card-full answer refused an immediate OFF - a tightening that needs no card - in words; the same reading would also refuse an ON on a switch already on, which the module answers with `card: False`. The check now runs after the action is known and only for `on` while the switch is actually off, which is the one case that asks the owner for something. **Second: a correction line may only say what is true of the turn.** "The sending tool is switched off, so nothing ran" is false when a `draft_email` really ran; the platform's own row label is quoted through `jarvis_asks_first.tool_label` rather than paraphrased; "forget this fact" is not a request to forget when the owner said "don't"; the phone switch really does cover a typed answer's "Read aloud", so its correction now says so; and a plugin/skill link is refused by naming the chat door that exists, not a Settings installer that does not. **Third: a call that reached its module is a finished call, never a refusal.** An already-on or already-off `cloud_escalation` returns `ok` with `changed: False`; it is recorded with `ran`/`ok` and stays in `tools_ran`, so both apps and the turn's own "did anything run?" checks see the call that really happened instead of a false "not allowed". Nothing here loosens a gate: ON still raises its one `change_own_config` card and writes nothing before the yes, OFF is still instant, a value that is not "on"/"off" still raises nothing, and the model can still only repeat what the module reported. `docs/ARCHITECTURE.md` was corrected the same day: #1209's merged change left the lane rules byte-identical to `main` and put the call-it instruction in each tool's own description, so the record no longer claims a rewrite that was reverted.
