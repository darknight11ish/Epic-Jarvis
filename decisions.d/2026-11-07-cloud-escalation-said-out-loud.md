- **2026-11-07 — The standing cloud-escalation switch is said out loud in chat, deterministically, instead of hoping a 9B model calls the tool:** The 2026-11-06 decision made an explicit action request reach its gating tool, and PR #1209 gave chat a `cloud_escalation` tool that calls `jarvis_presets.cloud_escalate()` - the same call the Presets menu's Cloud row makes. Measured on live build 0.2.437, that was not enough: asked "turn on cloud escalation" in chat, the local 9B model answered "I've turned on cloud escalation" while the switch stayed OFF and the self-awareness row failed "no NEW card appeared within 25s" in two passes; worse, the feature guide answered the sentence with "There is no fixed sentence for it", which is false about a switch the Presets menu really has and a card that really can be raised, so the sentence never reached the model or the card at all. The rule from here: **a sentence that is unambiguously a request to change a switch Jarvis really has must not depend on the model choosing a tool.** So `jarvis_quick` gained a deterministic matcher and runner for the switch's own words ("turn on/off cloud escalation", "enable/disable", "escalate my/hard questions to the cloud", "stop escalating to the cloud", and a bare "turn it on/off" ONLY inside a sentence that also names cloud escalation), placed before the feature guide that used to swallow the sentence. **It adds no rule and loosens no gate:** the runner calls `jarvis_presets.cloud_escalate` and nothing else, so ON is still the same ONE `change_own_config` card that writes nothing before the owner's yes, OFF is still instant, ON with no cloud provider chosen still refuses BEFORE a card, and nothing there approves a card. The model tool is not replaced - both doors end at the same module, and the deterministic one wins when it matches because it cannot be mis-called. **A question stays a question** ("is cloud escalation on?" keeps the guide's read), a sentence that names no escalation is never read as one, and the pronoun form requires the sentence to name the switch: without that, "cloud escalation is on but do not turn it off" would be read as OFF and change the very thing the owner asked to leave alone. The answer is the body's own sentence rather than a filled-in "Done", because a switch that can spend money must not claim a change it did not make; a card still waiting is reported as waiting. The proof is `backend/test_cloud_escalate_setting.py` - 130 checks over the matcher's twelve cases and the runner's four outcome paths, not a live chat, because this branch was not deployed.
