- **2026-11-07 — Jarvis's knowledge of its own code is a generated map shipped beside the backend, not a code reader and not a model tool:** The owner's requirement was "jarvis should understand every major part of its own code that can be viewed on the jarvis github main branch". Three existing things came close and none of them was it: `jarvis_repomap.py` maps a folder the owner names and deliberately keeps no index, `jarvis_self_portrait.py` knows measured facts (version, tools, cards) but not the codebase, and the feature catalogue knows what features do, not which module implements them. So the source of truth is the deployed tree itself: the live overlay is built from this repository at the merge commit, which is exactly what the owner can see on `main`, and `tools/gen_self_code_map.py` turns that tree into `backend/jarvis-self-code.json` at deploy time — the same beside-file pattern `requirements.lock` and the HUD files already use, with the same twin rule (`jarvis-backend/` carries the same bytes). The map is generated, never typed: paths, key-module docstring summaries, VERSION, the commit and its own date, and the newest twenty subjects all come from the tree, so `--check` can compare the committed file byte for byte and fail on drift. Completeness is a checked property rather than a claim — one table assigns every tracked file to exactly one subsystem, and the generator refuses a tree where a file belongs to none or to two, while generated, binary and vendored files are named and counted rather than dropped. The reader shipped whole (`jarvis_self_code.py`) never runs git, never opens a socket, never writes and never imports code to look at it; it reads the JSON beside itself and answers in plain words, and the absence of that file is an honest answer rather than an error. Phase 1 deliberately adds NO model tool and NO route: the four deterministic chat intents in the shipped `jarvis_quick.py` cover the owner's four question shapes, a miss says "not in the map I was built with" and names the two nearest parts, and the answers state their own limit — the map knows nothing newer than the deploy that installed it and holds no code bodies. A model-facing `self_code_lookup` tool and a clone-refresh path are phase 2, after this is live and measured.
