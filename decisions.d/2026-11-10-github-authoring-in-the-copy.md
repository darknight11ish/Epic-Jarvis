- **2026-11-10 — Jarvis writes the fix itself, one file per card, inside the isolated copy only:** Wave 16B builds the item the 2026-11-10 GitHub record deferred in its own words - the scratch-scoped code-authoring tool that lets fix-and-push write its own fix. The shape is deliberately the smallest one that closes the gap: **no new tool and no new switch** (the surface stays the ten switched-off GitHub tools, and the one switch that already governs the fix flow governs this), and `github_fix_and_push` gains `stage="read"` and `stage="write"` beside `prepare` and `push`. `read` raises **no approval card**, because it opens one file inside the copy, sends nothing to GitHub, uses no token and changes nothing on this PC - the same rule every local read follows - and it is reachable only through the same path resolver the write uses, so it is not a way to read arbitrary disk. `write` is its own action, **`github_fix_write`**, `"ask"` in both shipped `[autonomy.tiers]` files and in `jarvis_agent.NEEDS_A_PERSON`, so a loosened tier still raises its card; it changes **ONE file** inside the prepared copy and makes **ONE local commit** there, and its card shows the pull request, the folder, the file's path, the exact change as a **real unified diff** and the commit message, and says plainly that no token is used and nothing is sent. The confinement is the module's own, never a prompt's: the folder must resolve under `JARVIS_GITHUB_SCRATCH_ROOT` and carry the prepare stage's `.git` note naming the **same repository and pull request**, so the owner's live checkout and another pull request's copy are unreachable; the path is relative, and `..`, an absolute path, a drive letter, a UNC address, a NUL, a symlink and a Windows junction are refused; `.git` and every file on the **push stage's own credential denylist** are refused; a delete/rename/move/chmod argument is refused rather than ignored; only plain UTF-8 text is changed, and a binary or over-1-MB file is refused; a change too big to show in full on one card (the gate caps a card at 4,000 characters) is refused before a card exists, never shown cut; and `run()` re-reads the file immediately before writing and refuses if it changed since the card was shown - the same TOCTOU pin the merge has. The commit identity travels in git's own `GIT_AUTHOR_*`/`GIT_COMMITTER_*` environment variables (never argv, never a file), and a failed commit puts the file back and unstages it so the copy is never left dirty. **No ban was loosened:** `NEVER` lost only `edit_file` and `write_file`, which are no longer true because one file inside the copy can now be written, while `NEVER_WORDS` and every other ban (force-push, squash/rebase merge, admin bypass, auto-merge, bypassing a required check, pushing to main, deleting or closing anything, approving a pull request, workflow dispatch, gists) are untouched, and the push still happens only on its own card, still showing the real commits, files and command.
