- **2026-11-10 — Two read-only pre-push gates, cardless by construction:** the owner's "full parity with DeepSeek on GitHub" order named two abilities Jarvis had only as a person's habit: a review packet before a push and a repository record check. Both are now product surfaces - the model tools `review_changes` and `check_records`, and the deterministic chat sentences "review my branch" and "check the records before I push" - and they are deliberately NOT carded, because a card asks permission for a change and these make none. The decision, in four parts. First, they are LOCAL: they read one git checkout on this PC through fixed read-only git commands and this repository's own twelve checkers, never fetch, open no socket, and never touch the GitHub token, so `JARVIS_REVIEW_REPO` (or the tool's own `path`) is what names the folder, and a stale `origin/main` is reported as stale rather than updated. Second, they are decided under `file_read`'s existing action, `read_files_readonly` at tier "auto" - the same line `project_read` sits on - so no gate action and no approval card were added, and both names sit in `jarvis_asks_first.TOOLS_SWITCHABLE` with neither in the shipped `[tools].enabled`, which is what "off by default, one switch each" means here; the chat sentence names the switch when it is off instead of running anyway. Third, they are NOT rows of `jarvis_github.CAPABILITIES`: every row there is an action that sends the token and therefore asks, and these send nothing - so they are their own pair (`jarvis_agent.LOCAL_REVIEW_TOOLS`) in the same `github` tool group, and the one inventory stays truthful. Fourth, the record check reads the strict rule the owner's order names - ONE `changelog.d/` fragment, ONE decision record, no `CHANGELOG.md` or `docs/DECISIONS.md` rewrite, the docs count when a document was added, every changed `backend/<file>` carried to `jarvis-backend/<file>`, well-shaped claims and defect rows - and a checker that cannot run is NOT-RUN, TIMEOUT or FAIL, never a pass, which is the same rule every field test in this project follows.
