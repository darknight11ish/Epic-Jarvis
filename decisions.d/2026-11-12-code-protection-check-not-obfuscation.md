- **2026-11-12 — Code obfuscation is a tool CHECK, and the run is deliberately not built:** PR #1228 asked for a multi-language obfuscation and hardening engine behind one Ask-First card. What it actually shipped was a stack scanner, a plan builder, an executor with no production caller, and six "toolchains" that copied the source files and reported success without running anything; the one JavaScript branch was never called, the "verification" only counted files, and the chat reply told the owner an approval card was waiting when no card had been raised. The salvage keeps only what was true and useful: a read-only check that reports which of the seven known code-protection programs (`javascript-obfuscator`, `terser`, `pyarmor`, `python-minifier`, `r8`, `strip`, `garble`) are installed on this PC, each one's own version line, and the install command when it is missing; and one fixed sentence that says this build cannot obfuscate or harden code, so nothing is run, no card is raised and no file is changed. Every register the fake action had reached is removed with it - the `project_obfuscate` line in both shipped `[autonomy.tiers]` tables, `MUST_ASK`, `HARD_LIMITS`, the asks-first groups, the card-word tables and the four generated contract fixtures - because an action that can never be raised must not appear on "What asks first" or in a card. Two parts of the old design are worth keeping if the run is ever built, and this record is where they are written down rather than lost: source files are never obfuscated in place (the output is an isolated folder), and the owner sees the exact tool, flags and destination on ONE card before anything runs. When that is built it must come back through the real gates - a `jarvis_agent.TOOLS` entry, a `jarvis_gate._TOOL_ACTIONS` mapping and a `_RISK` row, ONE `ask` card through `jarvis_gate.check()`, and a verification that the tool really produced the output rather than counting copied files - not through a plan builder with no caller. Until then the languages are covered by the CHECK only: JavaScript and TypeScript, Python, Android, Rust and Go are named as checkable, and none of them is obfuscated by this build. The version probe is given `jarvis_child_env.inherited()`, the repository's allowlist, and is not started at all when that allowlist cannot be built; the old probe handed the backend's whole environment, including `HUD_TOKEN`, `JARVIS_TOKEN` and every `*_KEY`, to each third-party binary it found, which is the exact leak `jarvis_child_env.py` exists to stop.
