- **2026-11-13 — The required `backend` job is sharded instead of one 90-minute sweep:** The job ran `python backend/run_suites.py` once over every `backend/test_*.py` (75,829 tests), and by 2026-11-13 that step had grown to the job's whole 90-minute cap - measured on a passing run (43549014566, job 132306898351), which took 79m20s with 75m54s in the suite step (618 suites reporting 4,550.8 s), and on PR #1241's run 43547214198, CANCELLED at 90m16s with 88m41s in that same step. Raising the cap to 120 (PR #1247, open) buys headroom but not one minute less per run, so this splits the work: `run_suites.py --shard I/N` slices its own sorted suite list by position (`position % N == I - 1`), the shards fan into the one required check named `backend`, and a shard that selects no suite is a FAILURE rather than an empty green. The shard count has ONE definition - the `matrix.shard` list in `.github/workflows/ci.yml`; the job name and the runner's total both read `strategy.job-total`. It deliberately does NOT change which suites exist, which are skipped by name, the `backend-windows` job, or any other job, and with no `--shard` the runner behaves exactly as it did before (same suites, same order, same exit rule).
