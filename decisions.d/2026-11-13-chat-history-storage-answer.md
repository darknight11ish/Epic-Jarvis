- **2026-11-13 — A storage self-fact is answered from the code or refused, never composed by the model:** the owner asked Jarvis "where are the chat backups stored?" and it answered "Chat backups aren't stored anywhere by default on this PC - conversations live only in the app's memory until you close it or clear them. If you want a permanent record, I can help you copy important chats to a file or set up a reminder to do that regularly." Every clause is false, and false in the direction that matters most: it told him his private history was throwaway while `jarvis_chat_log.py` has kept it on this PC, encrypted, unchanged since his own decision of 2026-09-24 (that module's header: *"chat history, including what is said to Jarvis by voice, is kept on the PC by default, encrypted, with a switch to turn it off"*). The architect's ruling (Gemini, 2026-11-13 22:30 PT, section 5.6) is that a self-fact about **storage, history, privacy or settings** must be answered deterministically from the code, or refused - never composed by the model - and this lane is the `chat_history_storage` part of it. Decided: `jarvis_quick.py` gets one narrow, read-only intent that answers where the chats are kept and what is true right now, from `jarvis_chat_log`'s own `settings()` and its own database path, because a fixed sentence would be a lie the moment the switch is off or the file cannot be read. It names the default, the encryption (AES-256-GCM, key in Windows Credential Manager), the file (`chat-history.db` in `.openjarvis` in the user folder - named without the Windows account name, because the same reply reaches the phone and `docs/ARCHITECTURE.md`'s kept-off-a-phone table says a folder that names the account stays off it), the voice transcripts (the words are kept as ordinary encrypted turns; the recording is not), the retention window, and the switch exactly as each app draws it. It is `settings()` and not `status()` on purpose, so answering mints no key and writes nothing. Off is said as off, an unreadable settings file as "cannot keep anything right now", an unopenable file as "cannot say what is in it", and a backup TIMETABLE - which the product does not have - as no such thing, rather than smoothed into the default sentence. One documented shape moved: *"where are my chats stored"* used to be `history_purge`'s (`docs/JARVIS-API.md` section 189.8), which answered it with the measured file path and a paragraph about clearing; the storage questions now get the answer that names the switch, and every clearing, size and expiry shape stays with `history_purge`. What this deliberately does NOT do: it does not answer "is my chat history private" or any other question outside this one subject, it is not added to `_PRIVATE_DETERMINISTIC_READS` (a private chat hands read-only intents to the model, and its sibling `self_knowledge` is not there either), and it changes no route, no card and no app.
