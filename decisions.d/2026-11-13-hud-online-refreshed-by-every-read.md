- **2026-11-13 — The HUD's "can I talk to Jarvis" boolean is refreshed by every landed status read:** `S.online` stays the one value the face and Send read, and `paintHost` now writes it from a landed `/api/status` read; the alternative - pointing every reader at `S.ollama` and leaving `S.online` as a compatibility field - was rejected because the chip and the face are painted only by `reactor.set`, so that shape would leave the face showing "offline"/asleep until the next turn while the model was already back. Two guards keep that from repainting twice: only a real boolean moves it (a landed read that does not mention the model is not a verdict, and a failed read still says nothing), and it repaints only when the value changed, so boot's own read and the beat's read cannot paint the chip twice for one truth. `S.online` now starts null, because a page that has not had a successful read has not been told the model is down: null reads as not-yet-known in the face state, the offline ring, the chip label and the Send gate (Send tries the PC for real instead of writing a "Jarvis is not connected" sample on a guess), while `S.ollama` remains the PC's field as reported, also used by the one status row and the standing lane warning.
