- **2026-11-13 — A settings restore never re-points the pairing token:** the phone's settings backup no longer carries the desktop's address (`host` is excluded from the `jarvis_client` file, and the reader drops it from an older or crafted snapshot too). The reason is a credential, not tidiness: the pairing token lives in `jarvis_secure`, which no backup touches, so restoring an address over the stored one would send a token the phone already holds to whatever desktop the backup named. A restored phone therefore pairs again and the address is typed again, exactly as after a reinstall. The same pass caps the PBKDF2 iteration count a backup file may ask for at the 210,000 rounds this app writes - the count sits in the plaintext header, and the key is derived before the first tag can be checked, so a crafted file must not be able to choose a slower key derivation than the app itself - and corrects two sentences that claimed every failure has its own words and that no partial restore exists: authentication is all-or-nothing, but preferences are written one file at a time, so a write that fails partway may already have restored some settings and now says so.
