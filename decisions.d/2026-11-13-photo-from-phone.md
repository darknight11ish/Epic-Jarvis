- **2026-11-13 — A photo from the phone now lands in "From my phone" unchanged, as a plain file that no model sees on that path:** The owner's report: on his phone he asked Jarvis to "send this file which was a photo to the computer", and Jarvis answered that it had no access to a standard file system and could not receive or send files between devices. That denial was false about documents and, for photos, it was describing a real gap: the Settings row "Send a document" carried only the eight document kinds, and a picture in chat deliberately takes the separate `ChatPicture` path, which runs vision and covers secrets with black boxes before a model sees it. The owner's capability is "put this photo in a folder on my PC", which is neither of those. So the SAME upload route (`/api/upload/begin|chunk|finish`, purpose "document") and the SAME `receive_uploaded_document` card now also accept `.jpg .jpeg .png .webp .heic .heif .gif .bmp`, and a photo is written into `<a listed folder>\From my phone\` byte for byte unchanged. It is a plain file copy: `jarvis_upload.py` performs only a header check on the first 64 bytes, and nothing opens, converts, indexes, OCRs or shows the picture to a model. WHAT MAKES IT SAFE, AND WHY IT IS NOT THE CHAT PICTURE PATH: the chat picture path is an image path on purpose - it decodes the picture, OCRs it and gives it to the vision model, with secrets black-boxed first - while this path is the same pipe a document takes, so the two must not merge in either direction. `jarvis_attached_file.KINDS` is NOT widened (a photo is still refused as a chat document, `WHY_PICTURE`), and a landed photo stays unreadable to the documents feature: `jarvis_documents.read` accepts only TEXT_KINDS/DOC_KINDS, the index's default kind set is TEXT_KINDS, and the word scan opens TEXT_KINDS only - pinned by `backend/test_upload.t_a_photo_lands_as_a_plain_file`, which lands a real PNG and then proves both readers refuse it. WHAT WAS NOT BUILT AND STAYS NOT BUILT: no new route, no new purpose, no preview, no share target, no second picking surface; the phone's chat "Attach a file" row and `goesToPicture`/`ChatPicture` are untouched, and the 2026-11-05 decision that pictures are refused by the upload allowlist is replaced for photos as plain files only. The phone's row now says "Send a document or a photo" so the owner can tell the two doors apart, and the feature list entry `document-from-phone` says what really happens: documents AND photos go into "From my phone", and nothing is sent to the cloud.
