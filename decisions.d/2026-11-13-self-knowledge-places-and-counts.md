- **2026-11-13 — A "planned" note, a "where" and a self-stated count are only true if the row or the code says so, so the directory and the counts derive them:** three rules came out of the self-knowledge review's places, labels and counts half. First, the Settings directory's planned note may only be emitted for a row whose OWN contract status is `planned` and whose label is Switchable/Adjustable - the class that claims both a Settings control and a typed path; a `known_gaps` row or a multi-field board is evidence about an older state, not permission to stamp "Still being wired" on a row that is no longer planned, and a Command-Only, Always-On, Settings-Only or PC-Only row must never be told its "typed path" is being wired because its own label says there is no such path. Second, a row's `where` must name the place the owner really taps today (including "there is no switch for this yet" when that is the truth), and a place name that has been renamed in both apps ("First-time setup" -> "Personalize Jarvis") is a wrong place, not a stylistic difference. Third, a count of what the program has is read from the registry that owns it at the moment it is said or checked - `jarvis_agent.TOOLS` for the tool list, `tool_targets()` for the switch rows, `features.json`/the catalogue for feature rows - and never typed into prose, a failure message or a test; a count typed into a page has no owner and goes stale silently, which is how the page came to say 49 settings, 61 tools and 181 features. A recorded gap is cleared only after today's code proves it closed, not because a note elsewhere says so. Nothing about approval cards, permissions or routes changed.
