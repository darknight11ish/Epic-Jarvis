- **2026-11-14 — A second kind of app the model may build: its own screens, from a validated spec, with the model still writing no code:** The owner asked for *"a real app with its own screens, written by Jarvis"* - not the fixed WebView shape the Android builder shipped on 2026-10-30. Decided: keep the model's pen out of the code and widen what it may DESCRIBE instead. A task's copy may carry `app.json`, one JSON object with six keys and at most eight screens of three fixed kinds (text, list, form); a second FIXED Kotlin activity in the same module reads it from `assets/app.json` at run time and draws it with ordinary Android views, so the generated app still declares no permission, cannot reach the internet, the phone's files or Jarvis, and needs no dependency. The model writes DATA, never code: every key is checked against a closed set, every screen id against a closed pattern, every button against the screens that exist, all of it before a byte of the project is written and before any card is raised. A form saves its values to SharedPreferences on the phone and nothing else; a button opens another screen or shows one short line. The task's own files pick the kind - `app.json` present means native, absent means the WebView app - so no flag can drift out of step with what is there, and a request that passes `assets` or a `title` beside a spec is refused, because the spec is the only source of the app's name, colours and words. The decision worth recording is what is deliberately still out: no navigation stack, no data source, no script, no Compose, no permissions, and no way to RUN it from either app - the four routes have no caller, which this branch records as DEF-066 rather than leaving it to a reader to notice.
