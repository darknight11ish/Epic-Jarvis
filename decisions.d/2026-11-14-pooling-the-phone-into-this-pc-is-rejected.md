- **2026-11-14 — Pooling the phone into this PC's model is rejected:** the owner asked whether the phone's chip could add its computing power to the model on this PC, and the answer is no. Four routes were considered — Exo, Petals, llama.cpp's own RPC backend, and the "tightwad" patterns that put a small model beside a big one — and each fails on a measured fact rather than a preference. This PC has **28 GiB** of graphics memory (RTX 2060 12 GB plus 2 x RTX 2080 SUPER 8 GB, measured with `nvidia-smi` on 2026-11-14), and the everyday 8B model already fits on one card, so there is no shortfall for a phone to fill. A phone-sized drafter runs at single-digit tokens per second, slower than the card it would be helping, and a mesh adds a round trip per batch, so the latency would rise rather than fall. None of those projects supports Android as a node at all. The phone's own Local AI screen also has **no network path and no link to this PC** on purpose, so pooling would be the first thing to break that rule. Shapes C (draft-and-finish) and D (memory digest on the phone) are therefore deferred, not built. The only next shape is **B, automatic labelled fallback**, and only if the owner wants offline continuity: it must fire only when Local AI is on and a model is already loaded, and every answer it gives must carry a fixed label so it can never be mistaken for the PC's model.
