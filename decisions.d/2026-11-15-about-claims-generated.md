- **2026-11-15 — The About page's claims totals are generated from the register, not typed (owner's ruling Q4):** `docs/ABOUT-JARVIS.md` quotes the totals in `docs/CLAIMS.tsv` in six places, so every claim change broke that page and every pull request that moved a claim hand-edited the same six spots — `b24634c77`, `f75b34e1f` and `9d70ec02b` are three in a row, and the last exists only because `backend/test_claims.py` caught the page stale at 268 rows / 256 built against a register of 269 / 257. The ruling is that the six numbers are generated, in the shape this repository already uses for the two figures in `docs/README.md`: `tools/gen_about_claims.py` reads `docs/CLAIMS.tsv` and rewrites only the digits inside those six statements (idempotent; `--check` writes nothing, exits 1 and prints every number that differs), `backend/test_about_claims.py` proves the page matches the register and that a hand-edited number in any one of the six is caught, and the page's numbers are the generator's to own. **One definition, not two:** the tool imports `backend/test_claims.py`'s `ABOUT_COUNT_SPOTS` — the table the required `backend` job already uses to fail a stale page — and `tools/check_claims.py`'s register reader, so a second copy of the spots or of the counting cannot drift away from the check that judges them. **What it does not do:** it adds no step to `.github/workflows/ci.yml`, because the check lives in `backend/test_about_claims.py`, which the required `backend` job already runs, and a workflow step would be a second place deciding when the page is checked; it adds no `docs/CLAIMS.tsv` row, so the register's totals (269 rows, 257 built, 7 open, 5 unverifiable) do not move here; and it changes no sentence of the page, only the digits inside the six statements it already had.
