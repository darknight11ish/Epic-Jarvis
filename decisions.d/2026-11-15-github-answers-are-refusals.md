- **2026-11-15 — The GitHub layer's answers are refusals, not guesses: a shape before a cap, a check before a green, and the model's own text is refused if it can draw as another line:** An adversarial pass over `backend/jarvis_github.py` on 2026-11-15 (the owner's standing "every feature gets its own audit" rule) wrote `backend/test_github_robustness.py` first and fixed what it proved: 94 failing assertions across eleven defects, plus three proven against real GitHub the same day by a live read verification. Four shapes are what the module now keeps. FIRST, a refusal is one plain sentence and it happens before a request exists - a repository named `owner/..` is a path step in the URL rather than a repository, a number of `"0"` is not a GitHub number (it was accepted as a string and refused as an integer, so the same nonsense had two different answers), and `refs/heads/main`, `HEAD`, `main/`, `main.`, `feature/.secret` and `main.lock` are not the branch a card can name, because a runs filter of one matches nothing and reads as "no CI run". SECOND, the SHAPE of an answer is decided before the read cap: a directory listing over 200,000 characters is still a directory (a 320,215-character `docs/` listing used to answer "the answer was longer than Jarvis reads"), and a cut `pulls/{n}/files` list now says what was left out and how many files GitHub says there are instead of "Changed files (0)", which was a false statement about a 481-file pull request. THIRD, "passed" is a claim that needs every check on the head commit: two workflows run on one commit and GitHub lists them in its own order, so the old `workflow_runs[0]` answer said passed on PR #1263 while `audit` and `backend-shard (3/4)` were red - the pull request form now reads the head commit's check runs, names each one that is not a success, and does not use that word otherwise. FOURTH, text the MODEL supplies is refused rather than sanitised when it carries a character that can make one line draw as another: fetched text is cleaned because somebody else's words must survive, but the card is what a person consents to, so silently rewriting it would post something they never saw. Two deliberate non-changes belong on the record: an absolute-looking file path is still re-rooted inside the repository (`/etc/passwd` asks GitHub for the repository's own `etc/passwd`) rather than refused, and a sha whose only fault is a copy-paste newline is still pinned as the sha. And one limit is stated rather than hidden: `Retry-After` is read only when the transport supplies headers, which the real `_default_fetch_full` now does and which every test fake may do, so no test had to pretend a header existed.
