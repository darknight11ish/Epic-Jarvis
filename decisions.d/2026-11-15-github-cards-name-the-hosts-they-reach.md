- **2026-11-15 — A GitHub card names the two hosts the saved key reaches, and a fix-flow card refuses a target it cannot prove before it spends anything:** the owner's Q6 ruling on 2026-11-15 was to codify the closed two-host set - `api.github.com` for the REST calls, `github.com` for the git clone, fetch and push - and to make every card state only the hosts it actually uses. This is that, read off the code rather than typed by hand: the write, prepare and push lines are built from one helper so a card cannot name a host the call does not reach. Two refusals move forward, which is the cheaper half of the same idea: a merged or closed pull request is refused before the clone, and a branch that is not a valid ref is refused before a push card is raised, because a card is a promise that the action behind it can still be done. The 900 s git timeout is evidence, not caution - three measured clones took 257-297 s and the old ceiling stopped the flow preparing this very repository. And a check that has not finished is now said as unfinished: a card that reads "no failing checks" while three are still running is the exact sentence this project treats as a lie, whether the code meant it or not.
