- **2026-11-15 — The pooled lane's turn names its window on Ollama's native endpoint, because `/v1` would not carry it:** The live measurement of the Coding preset on 2026-11-15 left two shapes to choose between, and the measurement itself decides. Shape (b) - keep the OpenAI-compatible call and make the runner it reuses already carry the right window - is already implemented in this repository: `pooled_preload()` sends a native `/api/generate` load at 49,152 before every pooled round, and a 49,152 runner really was resident when the measured turn began (`GET /api/ps` before it). The turn still unloaded that runner and re-created it at 8,192, then refused the 9,794-token prompt with HTTP 400. So (b) is not a new shape to try; it is the code that failed, and no test could honestly promise `/v1` reuses a resident runner when the live counter-example exists. Shape (a) is therefore chosen: on the ONE lane a preset gives a window to (the pooled port, `jarvis_presets.is_pooled_lane`), the turn is translated by `native_chat_body()` and sent to Ollama's NATIVE `/api/chat`, which honours `options.num_ctx` when it loads or reuses a runner - the same field `/api/generate` honours, measured at 49,152 tokens and zero spill on this PC. The number is the window the PRESET names (`jarvis_presets.lane_num_ctx`: 49,152 for Coding, 32,768 for Medical), never a number read back from `/api/ps`: `jarvis_power_switch.lane_context()` can only answer "loaded now", "last seen" or the model's own Modelfile default (`backend/jarvis_power_switch.py:378-388`), so after a failed turn it answers the 8,192 that failure created, and it cannot know how a lane was started. Every other lane keeps its `/v1` request byte for byte, a picture turn keeps it too (its OpenAI content parts are not translated), and a lane whose window really is small names that small window rather than the big one. Nothing about this is silent: a prompt bigger than the window it is about to name is said before the request (`WINDOW_OVERFLOW_LINE`), a window nothing can establish is said instead of guessed (`POOLED_WINDOW_UNKNOWN_LINE`, following the `NoKnownContext` precedent), and the native reply's `prompt_eval_count` is carried into `usage.prompt_tokens` so the existing after-the-fact guard still measures what the model really read. `backend/test_chat_window.py` pins all of it with fakes only, no socket, and fails on origin/main.
