- **2026-11-15 — The recent-changes module is regenerated on main, not carried by a pull request:** The generated `jarvis_recent_changes.py` was the last file every fragment-adding pull request rewrote, so two such PRs always conflicted, and each conflict costs a full CI round because a conflicted PR gets no run at all. Ruling Q1 had already taken the self-code map out of pull requests for the same measured reason; Q2 takes this file with it, in the same main-only workflow, right after the map is settled. What replaces the freshness demand on a PR is a weaker question that a PR can actually answer - is every bullet the module carries a real bullet of the record, in the record's own order - asserted by `backend/test_self_knowledge_honesty.py`, with byte-exact freshness kept for main behind `JARVIS_RECENT_CHANGES_STRICT=1`. The trade is stated rather than hidden: between a merge and the small refresh PR, the owner's PC answers "what changed" from a module up to one merge old, which the workflow reports on main and the answer never disguises as newer than it is.
