- **2026-11-15 — The self-code map leaves feature pull requests, and main carries a snapshot checked after every merge:** the owner's ruling Q1, reached from a measured night rather than from taste. The map records every tracked file, so every pull request - and every pull request owes a changelog fragment and a decisions fragment - rewrote the same 330 KB file, and two pull requests always wrote it in the same place; six landed one night and the map forced a full conflict plus a fresh CI round on every one, turning eight merges into about nine hours. What replaced the old rule (regenerate the map last) is a split with two gates. A pull request keeps the tree COHERENT - every tracked file owned by exactly one subsystem, and every key module, suite and document the generator's table names present - which `backend/test_self_code.py` proves in the required `backend` job and `py -3 tools/gen_self_code_map.py --coherence` runs at the desk; it reads no map and regenerates nothing, and a PR that adds a module edits the `SUBSYSTEMS` table instead of the JSON. `main` carries the map: `.github/workflows/self-code-map.yml` runs `py -3 tools/gen_self_code_map.py --check` after every merge and fails, naming the one command, when the committed map is not exactly what main's tree produces. The snapshot is then one small pull request with only the two map files, because main is protected by required status checks and there is no bot token - a push from a workflow would be an unreviewed change to main, which is the thing the protection exists to stop. The generator now also refuses to WRITE on a dirty tree: its file lists come from the index while the commit it records comes from HEAD, and a map generated during an in-progress merge was measured on main recording a commit that never had the files it listed. What this deliberately does not do: it does not stop checking completeness - the same `assign()` call still refuses a file nobody owns or one that two subsystems claim, and its synthetic proofs are unchanged - it does not weaken the twin rule (one run still writes both copies, and `--check` still refuses when they differ), and it does not let a stale map pass silently: main goes red until the snapshot is re-taken, and `docs/SELF-CODE-MAP.md`, `docs/ARCHITECTURE.md` section 20 and `CLAUDE.md` now state the new rule in place of the old one.
