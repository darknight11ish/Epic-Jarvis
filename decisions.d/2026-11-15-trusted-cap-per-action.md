- **2026-11-15 — Trusted mode's cap counts uses per action, not action names:** the design document's `MAX_TRUSTED_ACTIONS = 20` is written as one number against the whole window, and with an eleven-name allowlist a cap of 20 *action names* can never be reached, so in that reading the number would never bind. The engine therefore enforces 20 USES PER ACTION PER SESSION, with a hard ceiling of 30 and a larger request clamped rather than honoured; `TrustedSession.max_actions` is that per-action number, `actions_taken` is the total across all actions, and the twenty-first use of any one action is refused. The owner confirmed the reading on 2026-11-16 ("20 used of each kind") and asked that the default be changeable in Settings, by chat or in Jarvis Live, so the number one window gets is resolved when it OPENS: the caller's own number for that session first, else the owner's `[grants].max_actions` setting (declared once as `jarvis_limits.LIMITS["trusted_actions"]`, 1..30, shipped at 20), else 20 - clamped at every level. The engine only READS the setting; changing it stays the existing limits route's gate action, and the chat and Jarvis Live sentences that name it arrive with the wiring PR. What it deliberately does not do: it does not raise the cap, it does not give a plan grant a cap (a plan's bound is the exact list it names), and it does not make a spent window reopenable - the cap is per session, so a new window needs a new card.
