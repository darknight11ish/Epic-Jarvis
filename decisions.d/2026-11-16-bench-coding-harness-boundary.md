- **2026-11-16 — The coding benchmark asks for files and applies them itself:** `tools/bench_coding/` is a measurement tool, and it needs a decision written down because the obvious road is closed: this PC's chat lane has no file-write tool (`shell_exec` is hard-refused as `run_shell_on_host`, and `file_write`/`apply_patch` map to `delete_file`), so Jarvis cannot edit a repository itself. The harness therefore sends the failing file and test as text, asks for the complete file in one fenced block, applies that block inside a disposable `git init` repository that has no remote, and judges the row from the exact pytest command's exit code. It **declines** (never approves) a card that appears during one of its own turns: measured the hard way on 2026-11-16, when a local bug-fix prompt made the model call `github_fix_and_push` with an invented `owner/repo` and PR #1 and then wait 600 s on the card - a no executes nothing, and every declined card's id and action is recorded. It never switches a preset unless `--apply-preset` is passed, and a BLOCKED row is never scored as a pass. It is separate from `backend/jarvis_bench.py` on purpose - that module measures a model's token speed, RAM/GPU placement and context sizes; this measures task outcomes through the whole product (which lane answered, whether the tests passed, what the cloud cost, what was touched) and reads none of `bench.jsonl`.
