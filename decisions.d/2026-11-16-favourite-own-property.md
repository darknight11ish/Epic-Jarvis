- **2026-11-16 — Favourite is its own note property, never an alias of pin:** the owner's sentence `favourite my workout log note` (and `favorite …`) returned no intent at all, and the owner chose a separate property rather than aliasing `pinned`. So "favourite" writes and removes `favorite: true` in the note's front matter through the same one `edit_vault_note` card, File Guardian copy and Undo that pinning an existing note already uses - one route, no new card, no new permission - and a new note can be created with it ("make a note called X and favourite it", card-free exactly as every new note is). The `pinned` property's behaviour is untouched, so a note can be pinned, favourited, both or neither, and the read-back ("is my workout log note pinned / favourited?") answers each from the note's own front matter. It deliberately does not add a favourite list, a sort, a filter or a new setting: those would be their own decision. Both spellings are accepted in a sentence; the YAML key is always the US `favorite`, and the read-back also accepts a hand-written `favourite:`.
