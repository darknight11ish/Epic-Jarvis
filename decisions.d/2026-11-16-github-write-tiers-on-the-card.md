- **2026-11-16 — Every GitHub write declares its tier where the card can name it:** Gemini's ruling Q5, Layer 1 — *"Every write/destructive tool and intent MUST explicitly declare its tier (`ask` or `refuse`) rather than falling through to `unknown`"* — is recorded in `backend/jarvis_github.py` (`WRITE_TIERS`, read by `write_tier()` and `describe()`), **not** in `jarvis_gate.py`'s three tables and not in `[autonomy.tiers]`. The reason is the defect the 2026-11-16 write-card audit measured: the gate already resolved every one of the twelve write tools to `ask` through both shipped settings copies, and all thirteen write actions already had their `_RISK` and `_TOOL_ACTIONS` rows — what was missing was the card, which said nothing about the tier, so 0 of 12 named it. A declaration in the gate would have been true and still invisible. `refuse` is a standing ban and is refused BEFORE a card exists, so its sentence is carried by the refusal answer (the APPROVE review, a workflow dispatch, a banned push flag), never by an approvable card; `ask` is printed on the card itself. A `[autonomy.tiers]` row is deliberately **not** added for a banned verb: `backend/test_github_tools.py` refuses a tier line that names one, and a `never` line for a verb that is not a gate action would be a second, drifting truth.
