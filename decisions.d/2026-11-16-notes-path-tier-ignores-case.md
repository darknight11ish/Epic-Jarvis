- **2026-11-16 — The note resolver's path tier compares without case, and refuses when two notes differ only by case:** `jarvis_notes.resolve_note()` is the one resolver every note tool routes through, and its first tier is the vault path the owner named. It compared that name to the real vault path with `==`, but the chat path lowercases the sentence before the note-read grammar runs - `jarvis_quick.normalise()` ends `t = t.lower().strip()`, and `_norm_name` itself preserves case - so a note in a capitalised folder (`Private & Shared/Workout/Workout Log`) could never be named by the folder the app's own refusal asks for, and the refusal then could not be obeyed. The tier now compares `casefold()` on both sides, in the same style as `_basename_key`. It is still tried first and still answers `tier: "path"`. When two different notes' paths differ only by case, the answer is `ambiguous_section` with both named and nothing chosen: a Windows folder cannot hold both, a synced or Linux vault can, so the resolver decides instead of leaving it to the filesystem. This changes no existing sentence, not `_norm_name`, not `_looks_like_a_path`, and not the chat layer's lowercasing.
