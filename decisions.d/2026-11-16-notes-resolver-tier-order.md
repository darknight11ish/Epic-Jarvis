- **2026-11-16 — A note name is resolved in a fixed tier order, in ONE place, and never falls back to the daily note:** The architect's Wave 1 ruling. `jarvis_notes_edit.py` stays the only vault writer; resolution lives in `jarvis_notes.resolve_note()` and every note tool routes through it, so no two doors can disagree about what a name means. The order is: (1) the exact vault path the owner named (a slash or a `.md`/`.txt` ending is what makes a name a path; case matters there); (2) the file name alone, matched case-insensitively, which is the tier that has to answer on Windows where `Gym.md` and `gym.md` are one file; (3) an exact value of the note's own YAML `aliases:` list, compared case-insensitively and with a leading my/the/a/an and a trailing "note" ignored; (4) refusal, with any near candidates listed. Two matches at one tier are `ambiguous_section` with both candidates named, never a guess. NO TIER TOUCHES THE DAILY NOTE: a name that matches nothing is a refusal, because the measured bug was exactly that fallback (a create request's tail was filed into `2026-11-15.md`). The order is adapted, as a pattern not code, from Vinzent03/obsidian-advanced-uri (MIT), whose `filename` parameter first asks Obsidian's `getFirstLinkpathDest` and only then scans aliases; the refusal vocabulary and the two create options (`create_target_if_missing`, `reject_if_content_preexists`) are adapted, as patterns, from cyanheads/obsidian-mcp-server (Apache-2.0) and coddingtonbear/obsidian-local-rest-api (MIT). The two options are booleans on `create_target()`/`POST /api/notes/create`, not a second HTTP surface, and `reject_if_content_preexists=False` only allows filling an EMPTY note because Epic Jarvis never overwrites. `find_name()` survives only as a compatibility shape over `resolve_note()`. The vault's `.obsidian/daily-notes.json` is also honoured now - folder, format and template, with the template applied only to a new daily note (a pattern from liamcain/obsidian-daily-notes-interface, MIT) - and a vault without that file behaves exactly as it did before.
