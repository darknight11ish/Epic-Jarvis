- **2026-11-16 — One egress gate, and closed means refused:** Whether a request may leave this PC is now decided in ONE place, `backend/jarvis_egress_gate.py`'s `check_egress(...)`, instead of by each sender for itself. The order is fixed: a loopback address is this PC talking to itself, so it is always allowed and needs no setting; then `local_only=True` refuses, which is how rule 1 - email, files, credentials and stored memory stay on the local model - is carried by a sender that already knows its words must stay here; then Lockdown; then the standing cloud switch (`escalate-cloud.json`, absent or unreadable reads as OFF); then the service's monthly money cap in `chatbot/api-money.json`. "Closed" means REFUSED, not "ask again later": a missing switch file is off, a damaged Lockdown file is on, an unreadable money file refuses, and a host that names no service this PC has settings for refuses, because a cap that cannot be read cannot be a yes. The chatbot's API adapter and the quiz's cloud send ask it about the exact address their socket is about to open, and report an `egress_blocked` refusal in the gate's own words with nothing sent. The two remaining senders - the web search in `jarvis_search.py` and the HUD - are deliberately NOT wired in this change and belong to a second lane. `tools/check_egress_gate.py` lists the web-search sender (both copies) with that reason so the lane cannot miss it; the HUD spells no cloud host at all - it posts to an address the lane data hands it at runtime - which is the limit the checker's own docstring states a text check cannot see, so that one is recorded here rather than in the list. Review found one real bug in the first version of the gate: `_money_refusal` was called with `target` twice, the `TypeError` was caught by the gate's own never-raise belt, and every non-loopback request refused as `config_unreadable` - a gate that refuses everything is exactly as wrong as one that allows everything, and two suites now prove both directions (a refusal sends nothing, and a loopback send really goes). The published-base twin had been left at the pre-fix version too; it is byte-identical again. What this deliberately does not do: it opens no socket and sends nothing itself, it reads no payload word (only its length), and it does not replace the senders' own existing checks - the card, the key pinning and the money check still run where they always did; this is the one question asked immediately before the socket, and the last word on the answer.
