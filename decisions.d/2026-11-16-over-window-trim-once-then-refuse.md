This replaces the 2026-11-15 `WINDOW_OVERFLOW_LINE`, which announced that the prompt did not fit and sent it anyway; Ollama then dropped the FRONT of the prompt (Jarvis's rules and the earliest turns) and answered, so the warning described the loss instead of preventing it. The reasons for REFUSE rather than trim-again-and-send: the ordinary trimmer has already run by the time this check is reached, so what remains is the rules, the current turn and the offered tool schemas — trimming any of those would delete the exact thing the fix protects; and the estimator under-counts dense text (measured on this PC, 2026-11-16: 8,000 characters of code estimated at 2,672 tokens against Ollama's real 6,013, 2.25×), so a prompt that fits only on the estimate cannot be promised to fit in the model. A refusal is loud, names what to do, and never silently loses a rule; the one trim first is kept because a long chat that can still answer should, and refusing before trying would lose turns that fit after dropping old turns. The same branch clamps `max_tokens` to `min(client value, n_ctx // 4, 8192)`, because `budget()` subtracts it from the window and a huge client value could leave only the 512-token prompt floor.
