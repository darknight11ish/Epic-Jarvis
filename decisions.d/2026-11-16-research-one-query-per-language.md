- **2026-11-16 — One GitHub repository search per language, not one query trying to cover both:** `github_search`'s plan now sends one request per (capability x language) — Kotlin and Java — instead of one query ending `language:kotlin OR language:java`. Decided because GitHub's repository search does not support `OR`: the old form answered `total_count` 0 for every idea (measured 2026-11-16: 0 for the `OR` form, 1,592 for `jarvis language:kotlin`, 1,283 for `jarvis language:java`), so the whole redundancy audit was silently empty. What it cost: one extra outbound request per capability and an approval card one line longer per capability. That is accepted on purpose — the card prints both URLs in full and says "2 request(s)", so the owner is told exactly what will leave the machine, and a shorter card would be a less honest one. One limit that follows from doubling the requests, and is recorded rather than measured: GitHub documents 10 search requests a minute without a token, so an unauthenticated plan with more than five capabilities can now reach that limit; the module already puts a failed request in its `errors` and leaves that capability "unaudited, not clear" rather than reporting it as a clear result, and that unauthenticated path is not measured here because this PC has a token configured. What it deliberately does not change: the search words are still derived locally by `terms()` and are the only payload, the `sort=stars&order=desc&per_page=10` shape and the URL quoting stay as they were, no new service or credential is involved, and the local-only rule is untouched.
