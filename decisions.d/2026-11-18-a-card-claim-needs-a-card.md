- **2026-11-18 — A claim that a card was raised is answered by the turn's own card count, and the correction states what is true rather than only denying it:** a new claim family in `jarvis_claims` (`card_claim`, `card_correction`) was added after the field test measured four replies telling the owner "I have raised the approval card" while `GET /api/pending` was empty before and after the turn (DEF-089). The judgement calls, each made against that measurement: (1) **the backing is `_TurnWatch.cards`, not the pending list and not the model's words.** A claim about a card in this answer can only be backed by what this answer raised, so the count the per-turn card budget is already enforced with is reused; there is no list of card ids and none is needed, because a count of one settles it. (2) **`jarvis_gate.pending()` never backs a claim, only chooses the wording.** A card this turn raised has already been answered by the time the answer is finalized, so the live list cannot prove a card was raised; it exists in this check for two reasons only - the correction may say "nothing is waiting for your approval" only when the list really is empty, and a card already waiting from elsewhere leaves the answer alone, because the owner is then not waiting for a card that will never come. (3) **an unreadable turn is never guessed at.** `cards=None` means the caller cannot tell and nothing is corrected; the cloud lane passes an explicit `0` because a cloud lane offers no tools at all and cannot raise a card - a known zero, not an unknown. (4) **the correction must teach, not only contradict.** It says no card was raised in this answer, that (when known) nothing is waiting, that no card was shown in it, and names the one next step - ask again in a new message - because a bare "I did not raise a card" tells the owner nothing true about the state they are in. (5) **the mechanism is the existing one.** The line rides `postscript_lines` / `_claim_corrections` as kind `claim` - the list the local answer and the cloud relay both append - rather than a second checker; the turn's card count reaches it through the same holder that already carries the conversation id for the web-search grant claim. (6) **the exemptions are the module's own, so no honest sentence is corrected:** question, offer, future, condition, negation, "earlier/already", quoted text and code spans are left alone, and one answer gets one line rather than one per sentence - this module's standing rule is that a missed claim is cheaper than a wrong correction. This is a bug fix with no permission, route or approval-tier change: the card itself, its risk wording, its Windows Hello rule and the per-turn card limit are exactly as they were. What this does NOT settle, recorded so the close is not read as larger than it is: the same measured reply also said "This is just a field test - no cards go through right now" on the turn that did raise a card, and that mirror claim (denying cards work while one existed) is a different direction, not corrected here; and a phrasing outside the patterns still slips through, which the module accepts deliberately.
