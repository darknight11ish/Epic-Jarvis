- **2026-11-18 — The audit job installs the backend job's Python test dependencies:** Decided 2026-11-18, after PR #1366's `audit` job went red on a real check that the required `backend` job runs. `tools/check_claims.py` lives in `audit` and runs every suite a `test:` row names, so its Python must be the `backend` job's Python: a missing package makes a suite skip, and a skip is never a pass, so the claim reads as a broken BUILD even though nothing regressed. The `audit` job's pip line is therefore now the same package list at the same pinned versions as `backend-shard`'s, and the two are updated together. This is an environment fix, not a relaxation: `tools/check_claims.py` is unchanged, a skipped check still withholds proof, and the Windows-only checks that genuinely cannot run on the Linux runner stay skipped and stay named on every run. Cost was measured before deciding: the install takes 5.6 s on the runner, and the claims step grows only by the checks the packages unlock.
