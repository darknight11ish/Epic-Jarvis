- **2026-11-18 — A capability question is answered from the catalogue, and a "shown, opened or sent" claim has to be backed by the turn that made it:** the owner's own phone ask, *"Can you send a file for me to my PC?"*, was answered *"I can't send files directly"* while the catalogue row `document-from-phone` held the steps and the alias "send a file from my phone to my pc". The judgement calls, each kept narrow on purpose: (1) **"Can you ..." is still not a general capability lead.** It is how the owner asks Jarvis to DO things, and `backend/test_chat_honesty.py` pins that "can you write a nice email for my boss?" and "can you help me create a plan" keep their own paths. The ONE shape this matcher takes is a file transfer toward THIS PC — the measured sentence, and the only direction no tool of ours can start (the phone's own Settings picks the file), so claiming it takes no action away from the model. "Can you send a file to my phone" stays with the model, because `send_file_to_phone` is a real tool that raises its one card. (2) **Direction is evidence, not a veto.** `_cap_resolve` used to return None when the highest-scoring row was the opposite direction; that was right while the catalogue had one file row, and wrong once 2026-11-15 added the phone→PC aliases: `file-from-pc` still wins the score because its id says "file from pc", and it must LOSE to the direction-correct row, never silence it. When no row has the question's direction there is still no honest catalogue answer and the question falls through as before. A question that says "to my PC" now also rejects a row whose own words send "to your phone"; before, only "from my phone" did. (3) **The owner's measured words belong in the catalogue, not in the matcher.** "send a file for me to my pc" was added to `features/features.json` and the generated catalogue was regenerated; an exact match of the question's content words against one of a row's own aliases names that row (function words and order ignored), which is deterministic and is the same route PR #1208 used for earlier measured sentences. (4) **A "shown/opened/sent" claim is corrected in the existing postscript shape, not by a second mechanism.** `jarvis_claims.surface_correction` reads the model's words plus THIS turn's tool steps — the same contract as `unbacked_claim` and `schedule_correction` — and returns ONE line for `backend/jarvis_agent.postscript_lines`, which the local answer and the cloud relay already share. It is backed only by tools that really show/open something (`retirement_whatif` writes its table on the owner's screen by code, `product_check` opens a page in his browser, `conversation_open` opens a kept conversation, and the acting tools that click or type in a real window/app) or really send something (email, a text, the one file to the phone, a GitHub write — a draft is not a send). A question, an offer, a future sentence and anything "already"/"earlier" are exempt, and "I've sent it"/"The file has been sent." stay with the checks that already read them, so one sentence never gets two correction lines. (5) **Nothing gated changed.** No route, no card, no auto-approval, no state read: reading a catalogue is not a gated action, and both fixes answer only a turn no action path had already claimed. The honest limit is written here rather than implied: the catalogue is answered deterministically, but any capability sentence that still resolves to no row keeps the model, and the claim guard corrects words AFTER they were streamed — it does not stop the model from writing them.
