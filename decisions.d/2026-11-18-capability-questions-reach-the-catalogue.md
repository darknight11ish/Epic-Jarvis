- **2026-11-18 — A capability question is claimed by the last lane, in the question's own words, and "can you" is never a generic lead:** The CHAT-GAPS audit measured two numbers that decide this: 74 of 183 catalogue rows are reachable only by quoting an exact name, and "Can you ...?" reaches the catalogue for only 18 of 183 rows - while the local model, which answers what the deterministic layer does not claim, has been measured denying real features ("I can't send files directly"). Two changes follow. **First, the "and" short-circuit in `_explicit_feature_question` is removed.** It returned None before `_FEAT_EXPLICIT` was tried, so every feature question whose subject contains "and" went to the model - 49 catalogue rows, and all six measured owner questions that still fell through. It protected nothing: `_cap_multi_question` already ran earlier inside `_cap_question`, and this lane runs last in `match()` after every action matcher, so a sentence another path owned was never reachable there. The same function now also takes the speaker's frame ("a feature that lets you ...") off the subject, because without that the two of the six that start "lets you/lets Jarvis" became a deterministic "I do not have that one" - still wrong about a row that exists. **Second, three measured false-denial questions are answered from their row, and the mechanism is deliberately narrow.** "Can you send a file from my PC to my phone?" (`file-from-pc`, the mirror of the one-way `_CAP_CAN_YOU_TO_PC`), "Can you read my phone notifications?" (`phone-notifications`, with its off-by-default state) and "Can you add up my spending?" / "Can you check my bank export?" (`spending`) each get a named lead, checked only in `_explicit_feature_question` - the lane that runs after every action matcher - so it cannot take an action path. **A generic "can you ..." capability lead was rejected, and the audit measured why:** it would newly reach 131 rows but would also claim "Can you write a nice email for my boss?" as `email-send`, a sentence `backend/test_chat_honesty.py` pins to the writer's own path. Each lead therefore is only the words of the ONE question it serves, and every widened lead ships with a negative control that must keep the path it had before. **What is deliberately not fixed, and why:** 14 of the 21 measured misses remain. Each is either claimed by another deterministic lane before this one (the reminder family, `read_link`, `goal_capability`, `stop-everything`) or resolves through a neighbouring row inside `_cap_resolve` (attention-budget, also-on-phone/phone-apps, restart-the-model-lane). Those live in functions this PR must not touch - `backend/jarvis_quick.py` is in another lane's diff and the collision rule keeps this change to `_explicit_feature_question` and the `_CAP_*` leads - so they are recorded as the next fix, never claimed as closed. Measured with the real matcher: the six fall-throughs now reach their rows, 7 of 21 measured misses close, and a 4,488-sentence before/after sweep shows 80 newly resolved sentences, two wrong-row fixes (`phone-notifications` -> `phone-apps`) and no action path changed.
