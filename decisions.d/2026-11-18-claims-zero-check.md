- **2026-11-18 — A claimed suite that exits 0 having passed no check withholds proof from its claim, unless its whole body is a documented environment skip:** the external review's ruling, and the last place a skip could hide. `tools/check_claims.py` read only the skips a suite prints, so a suite that exited 0 having run nothing printed no skip and read as proof - the exact shape the register exists to prevent. The checker now applies `backend/run_suites.py`'s zero-check rule (`passed == 0` is a failure, no allowlist, 2026-10-27) to the one caller that did not run it (`audit` runs the register, and the runner's rule does not run in `audit`), and it takes the counts from the runner's own parser (`run_suites.counts`) rather than a second parser that could drift; this is one mechanism reaching one more caller, not a new one. The ruling's other half is kept: a suite whose whole body is skipped for a documented limit of this machine is the `ENVIRONMENT_SKIPS` case, not a hole, but it must show both halves - the suite's path keyed in `ENVIRONMENT_SKIPS` AND a skip it really printed that the allow-list accepts. An entry records why a skip happened; it cannot document a skip that never happened, so it must not turn a silent suite back into proof. The skip rule itself is unchanged (a printed skip is never a pass), a skip beside checks that really ran is unchanged, and the run now prints how many checks the `test:` rows reported so a green register says what it watched.
