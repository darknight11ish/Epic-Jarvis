- **2026-11-18 — A local record is answered from its file, or refused:** when the owner asks a question whose answer is a record on his own PC ("how many open defects are in the register", "what is open", "what is DEF-089"), chat answers from that record's file, deterministically, naming the file and the date it was read. The count is the checker's own count - `jarvis_quick` loads `tools/check_defect_register.py` and calls its `parse_tsv()` rather than writing a second parser - so a wrong count is never smoothed over: a missing file, a missing checker, a malformed header or a malformed row is refused in plain words. The answer is read-only: no card, no write, no model. The file is found through `JARVIS_DEFECT_REGISTER`, then the review gates' `JARVIS_REVIEW_REPO`, then the checkout the backend runs from - never by scanning the owner's folders - so an installed copy with no checkout beside it says the register is not there instead of denying the register exists. This is the first instance of the shape, not a general file-reading tool: it does not make the model read arbitrary files, and no other record is answered this way yet.
