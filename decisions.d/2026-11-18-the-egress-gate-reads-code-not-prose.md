- **2026-11-18 — The egress gate reads code, not prose:** An external review ruled on the egress gate's census: **a docstring or a `#` comment is writing, not egress, and must not be counted as an outbound host mention.** The measured cause: a new module's docstring showed `api.deepseek.com` as an example, `tools/check_egress_gate.py` flagged it, that failed `backend/test_chatbot_api.py` ("every outbound host mention is accounted for") and the whole `audit` job, and the lane's fix was to DELETE the hostname from the docstring - the gate trained an author to remove documentation instead of thinking about egress. So the checker walks `ast` now: a mention is a HOSTS name in a string literal that is code; docstrings (`ast.get_docstring`), any other bare string expression statement, and `#` comments (which never enter the AST) are ignored and counted only in the run's ignored line. The gate is not weakened: a real code string naming a host still fails unless the file names `check_egress` in code or is on the allow-list with a reason, f-strings and literal `+`/adjacent concatenations are folded so a split host is caught where the raw-text scan missed it, and the wiring half is code too - a docstring saying "this asks check_egress" is no longer wiring. The census lost 13 entries whose host lived only in prose (their files are simply not outbound mentions any more), and seven reasons that claimed "comment" or "docstring" while the mention was really code were corrected rather than left as a false account; the material one is `backend/jarvis_model_recommendations.py`, whose entry said "docstring" while its code builds and compares the Hugging Face URL fed to `jarvis_hf_inspect.py`'s fetch. Run on this tree the walk reports 134 files (6 wired + 128 allow-listed over 95 exact paths), 586 code mentions and 213 ignored documentation mentions; `backend/test_egress_gate_checker.py` holds every case on fixture trees plus the real tree's census line.
