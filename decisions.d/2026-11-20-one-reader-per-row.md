- **2026-11-20 — One reader per row, and a client never claims a state it cannot read:** The two settings state-drift audits (`DESKTOP-STATE-DRIFT.md`, `PHONE-STATE-DRIFT.md`, 2026-11-19) proved a class, not a bug: a screen can paint a control from one store while its sentence comes from another, or paint both once and never ask again while a chat sentence, a second window or a late approval card moves the real value. The rule this PR records is the one the fixes implement. (1) ONE READER PER ROW: the tick/selected mark and the sentence beside it come from the same read, and a row backed by TWO ANDed stores (desktop "Say One moment": this window's localStorage AND the PC's `voice-flow.json`) paints from a reader of both, never from one of them. (2) A ROW WITH A SECOND WRITER KEEPS ASKING: the desktop's `settings-live.js` is the ONE refresh rule - re-read on the approval queue, on the state's own PC event kind, when the window comes back into view and on a bounded steady poll while visible - and every PC-owned or chat-writable row that needed it now uses it (hands-free, read-aloud, the Wi-Fi reconnect, Picture mode, Making pictures, chat history, the big coder, the HUD layout, autostart); a carded ON whose Rust call gives up before its card does (20 s against the gate's 900 s) is drawn UNCONFIRMED, never as the old value, and is never given the bridge's unrelated "restart Ollama" sentence. A failed save repaints the control from the store, exactly as the autostart row already did. (3) A CLIENT NEVER CLAIMS A STATE IT CANNOT READ: the phone draws no switch at all for a state the PC has not answered (`checked = null` + "Couldn't tell", the rule `VoiceSwitchesPlate` already carried for unknown states), never draws an unread hands-free read as "Hands-free is off", derives the focus-preset apply sentence without naming a preset, marks "Current" only while the PC's own live lane agrees with the saved pick, and no longer tells the owner that a PC-only setting is at its shipped default as if that were its value now. The sentence in the phone's generated feature directory is kept honest by the generator, so the contract stays the one source. Deliberately NOT in this decision: a client is not allowed to read `/api/ps` or a loaded-model field to second-guess the PC's lane, and the desktop focus-preset "Current" row stays with DEF-088 (a backend state-truth defect verified by a live lane read, not a client re-wording).
