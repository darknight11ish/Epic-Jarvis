- **2026-11-20 — The plan store's execution and brief bridges: the link and the projection are built, the Run Step dispatch is deliberately deferred:** The owner-approved PM3 slice links the plan store to the surfaces that already exist — a project's `linked_repo` and a work item's `linked_pr_number` are read through `jarvis_github.py` (two GETs, no card, no GitHub write, stored as a projection; a merged PR is an OFFER and the move to done is the existing status path with its normal receipt and Undo), and a work item can be linked to a real `jarvis_tasks.py` job whose own state moves it through that same status path (`in_progress` / `waiting_approval` / `in_review`, never straight to done). The morning digest gains one additive `projects` key (due within 48 hours, top 3 ready across active projects, `in_progress` untouched for more than 7 days, offers) and the daily to-do list gains read-only rows for work items due today or earlier with the scheduler's own carry-over tags. The executor route was chosen on evidence, as the architecture review asked: **`jarvis_tasks.py` is the durable engine** (Ruling Q4 says to keep it and link work items to it) and `jarvis_jobs.py` is not — its ticker only runs its own closed handler registry (`watch_github`, `watch_repos`, `watch_ci`) with a frozen capability set and has no generic "run this work item" handler. But `jarvis_tasks.JobList.tick()` has **no production caller and no background step executor** by its own 2026-10-18 audit (the only real executor is built inside a chat turn), nothing in the program creates a job-list job (the plan card that would is closed by measurement — 12.5% against a 90% bar), and giving `tick()` a stand-in runner would move rows while nothing ran. So PM3 ships the LINK and the read-only status projection — the half that can be built honestly today, and what PM4's Run Step button would write — and defers the dispatch itself rather than shipping a half-built runner; `docs/ARCHITECTURE.md` section 8, `docs/PROJECTS-DESIGN.md`'s PM3 build note and `docs/JARVIS-API.md` section 88.9 record it, and `backend/test_projects.py` proves every bridge, the taint rule, the no-invented-date rule and the read-out cap.
