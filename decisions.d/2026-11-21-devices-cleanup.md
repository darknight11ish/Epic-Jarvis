Offer an owner-card-approved, dry-run-first 'Clean up duplicate/inactive devices' button in Settings → Devices (preserving devices active within 30 days) — never auto-prune pairing data."* The owner adopted it, and this pull request is the backend and card half: `POST /api/devices/cleanup` with `{"dry_run": true}` answers 200 with the plan and writes nothing / raises no card, and `{"dry_run": false}` raises ONE `devices_cleanup` card (tier `ask`) and removes nothing until the owner approves it; the dry run and the real run share one plan function, so the list the owner is shown is the list an approved run removes. Three promises are in that one function: a device used in the last 30 days is kept, the newest device is kept so a cleanup can never empty the list or lock a phone out, and the device making the request is kept. A copy of the registry is written as `registry.json.before-cleanup-<stamp>` before anything changes, a removed row is removed the way Remove removes one (so it pairs again with the QR code), and a denial answers that one run rather than becoming a standing rule. Nothing is automatic, and the desktop Settings, Devices button that calls it is a separate lane; the route is recorded as `planned` in `tools/check_parity.py` and documented in `docs/JARVIS-API.md` section 231.
