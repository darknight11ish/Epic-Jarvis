- **2026-11-22 — The GitHub capability family answers only sentences that name no target: a narrow target guard on the two action-answering shapes:** a live battery on the local coding lane proved the family was claiming commands. "Merge pull request 1472 in darknight11ish/Epic-Jarvis with a merge commit. All seven required checks are green. Use github_merge_pr.", its "now," variant, and "Merge #1472 in darknight11ish/Epic-Jarvis with a merge commit." each produced `quick: github_self` and the canned merge paragraph in 0.1 seconds - no model, no tool, no card - while the same battery's "Post this comment on pull request 1471: <text>" reached the model, called `github_comment` and raised the card the owner approved. The difference is a target, so the decision is a NARROW, EXPLAINABLE GUARD rather than a rewritten family: the two shapes that answer an EXECUTABLE action (`merge` and `action`) claim a sentence only when it names no pull request or issue number ("#1472", "PR 1471", "pull request 1472", "issue 5"), no repository ("owner/repo" slug, or "the <name> repository") and no branch (the word "branch", or main/master named after a to/into/onto). A sentence that names one keeps its old path to the model and its tool. Rejected, with the reason recorded: a "no imperative lead" rule, because `normalise()` strips "can you" and "please", so the pinned capability questions ARRIVE as bare imperatives ("merge a pull request", "comment on an issue") and refusing imperative leads would delete answers the existing suites pin - the target is what separates the measured command from the pinned question, and a guard that takes sentences away without changing any remaining answer is the only one that keeps them green (measured: none of the 816 string literals the existing suites feed the matcher changes intent). The permanent refusals (`approve`, `destroy`, `bulk_close`, `close_pr`) are deliberately NOT narrowed: each answers a permanently impossible action with a "No", so none can be read as the action having been taken and there is no tool behind them for the model to reach, and `test_chat_wrong_answers.py` pins each. Accepted costs, written beside the guard rather than hidden: a repository or branch named without one of those signals ("merge the one I showed you"), and a spoken number ("merge pull request one", which `normalise()` does not turn into a digit), still cannot be told from a capability question by a regular expression, and this change does not claim otherwise.
