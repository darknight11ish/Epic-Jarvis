- **2026-11-22 — The fix-and-push prepare fetch takes the clone's credential environment, from the one builder:** the external review's ruling 5.3 named it after the 2026-11-21 live GitHub proof: `github_fix_and_push` could not work at all on a PRIVATE repository, because `_run_prepare` cloned with the token (in git's own `GIT_CONFIG_*` environment, the measured Basic `http.extraheader`) and then fetched `pull/<n>/head` with no `env` argument at all - so on a private repository that one read was anonymous, GitHub answered 401, git fell back to its interactive credential prompt, and the owner saw `could not read Username for 'https://github.com'`. A public repository hides the gap completely, because an anonymous fetch works there, which is why the hermetic suites never saw it. The fetch now gets its environment from the same `_git_auth_env` the clone and both pushes use - no second builder, no copy of the header, and the token stays in the environment and out of `argv`. The alternative considered and rejected was putting the token in the fetch's remote URL: it would work, and it would put the secret in a command line that `Get-CimInstance Win32_Process` can read and in the scratch folder's own git config, which is exactly what the 2026-11-13 decision took it out of. The test is behavioural rather than a source pin: a `PrivateGit` fake refuses every network git command whose environment lacks the Basic header, in git's own words, so `t_a_private_repository_fix_and_push_carries_the_token_on_the_head_fetch` proves the whole prepare -> write -> push flow on a "private" repository, and `t_a_private_repository_fetch_that_is_refused_is_one_plain_sentence` proves the failure the fix removes is still said in plain words, with no token and no half folder left behind. Nothing about the cards, the gate, `NEEDS_A_PERSON`, the token store, the protected-branch refusal or the force-push ban changed, and the tool still refuses outright without a saved token. The doc at `docs/JARVIS-API.md` §190.10 already claimed the clone, the fetch and the push all take the token in the environment, so that sentence needed no edit - it needed the code to catch up with it.
