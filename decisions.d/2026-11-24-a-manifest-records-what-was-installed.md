- **2026-11-24 — A deploy manifest records what was installed, and refuses rather than blessing what it finds:** the manifest exists so a later update can tell a correct live folder from a stale one. It was rebuilt from the live folder's own bytes, so a file that drifted between the plan and the write had its stale bytes recorded as the truth about themselves - the exact failure the manifest is supposed to detect, written down as a pass. It was reproduced by replaying the module's own functions on a temporary folder: the stale hash was recorded, the apply reported success, and the manifest named a tree the source did not contain. The rule now: the manifest is derived from the SOURCE the deploy copies, a shipped file's hash comes from that source and never from a live re-read, and the live folder is READ to be compared with the record rather than used to build it. A file that does not match is named as not installed with its live size and modified time, and no manifest is written - an install that cannot prove its bytes claims nothing, which is the same rule the update half already follows. The format, the flags and the tool's own write path are untouched. The limit is recorded rather than papered over: a file with no other copy to compare against (the `VERSION` and `SOURCE-COMMIT` markers, a patched delta leaf) is still read from the live folder, and four live test suites on the owner's PC still differ from the commit the install claims while all 281 live modules match it.
