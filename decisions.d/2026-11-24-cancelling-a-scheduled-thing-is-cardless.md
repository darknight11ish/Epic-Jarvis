- **2026-11-24 — Cancelling a scheduled thing is cardless, and it is one job at most:** the model could set timers, alarms, reminders and to-do items but had no way to take one back, so the scheduling review asked for one tool that calls the EXISTING `jarvis_schedule.Scheduler.act(jid, "delete")` path. The rule this records is the shape that keeps it safe: a delete only makes things quieter, so it needs no approval card and no new route - the same reasoning that made `todo_done` cardless - and the tool deletes exactly ONE job. `id` is the preferred argument because `coming_up` already hands it out; `text` exists for when the model has only the job's own words, and it is matched case-insensitively against the live list `coming_up` shows. A words match that picks out nothing, or more than one job, deletes NOTHING and asks which one was meant, because a guess between two reminders is exactly the failure this rule exists to prevent. The gate row is `auto`, in an `_TOOL_ACTIONS.update` block at the end of the published base, and it reaches the owner's own install through `tools/repair_live_backend_gaps.py`. One honest limit is written into the module: a to-do row is not in `listed()`, so a to-do can be cancelled by an id the model already holds but not yet by its words.
