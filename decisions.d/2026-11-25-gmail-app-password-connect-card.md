- **2026-11-25 — Gmail is connected with an App Password over IMAP, and that is the whole of Phase 1:** the owner said *"i would like to connect you to my gmail"* and no card could be raised, because `jarvis_connect_account.SERVICES` held only the calendar and GitHub (DEF-096). The architect's ruling, recorded here because it decides what is NOT built: for a non-commercial, local-only personal app, Google's restricted Gmail scopes either expire every 7 days in "Testing" mode or need an external CASA Tier 2 audit for "Production" mode, so **no Google OAuth is built for mail** - an App Password (with 2-Step Verification on) is durable, needs no cloud redirect and no audit, fits one setup card plus one IMAP read test, and keeps the credential strictly inside Windows Credential Manager. The row writes `jarvis_email`'s own two entries, so the card configures the mailbox the rest of Jarvis reads; the one test is a COUNT - login, mailbox opened read-only, the number of messages - and fetches no message at all. **Read-only first: no send path is added**, because an outbound email already has its own per-email approval card (`send_email`) and this card must not become a second way to send. It has its own ask-tier action, `connect_mail`, with its card words in the published base `_RISK` table and a row in `tools/repair_live_backend_gaps.py` - base plus repair tool, never a new patch, per the owner's ruling of 2026-11-14 - and `raise_card` refuses to raise the card at any tier but "ask", because the card IS the ask and "auto"/"notify" would store a mail password with nobody asked. One recorded sentence moves with it: a chat sentence that NAMES Gmail ("connect my gmail", "how do I connect a Gmail account to you?") now raises the card rather than the email answer, which supersedes the letter of the 2026-11-15 entry for exactly the sentences that name a provider - the email answer keeps the sentences that name none ("connect my email", "what about gmail?"), and its own first line now names the card. What is deliberately unchanged: the Gmail host is still the mail server saved in Settings, Accounts (with `imap.gmail.com` used only for a Gmail address when none is saved), a non-Gmail address with no saved server is refused in words rather than guessed at, and the mail connector switch on the live install is untouched - connecting an account is not the same act as switching a connector on.
