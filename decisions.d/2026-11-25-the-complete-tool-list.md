- **2026-11-25 — "List all" is the complete list; "what tools" stays a summary, and one group can be asked for on its own:** The owner asked Atlas "can you list all of your tools?" and got "90 tools built in. 47 of them are switched on …: Calculator, Reading your calendar, … and 17 more." The cap that produced that (`_self_list(..., cap=30)` in the count answer) is deliberate and correct for "what tools do you have?" / "how many tools", where the question wants a count and a flavour and a settings file naming every tool must not become a dump - so that answer keeps it, unchanged. A question that says ALL is a different request, and it gets a different shape: `tools_list_all` lists every registered tool, one `- ` bullet per line (the chat pane keeps line breaks), grouped under plain area headings, each marked "— on" or "— off" against the live settings file, with the count line at the top and no "and N more". The names come from the registry (`jarvis_self_portrait.tool_inventory()`, extended with `all_names`) and the areas from `jarvis_agent.TOOL_GROUPS` and `CORE_TOOLS`, so there is no second list to drift; anything ungrouped still appears under "Other", because the one outcome a "list all" answer must never produce is a silent omission - so where a part genuinely cannot be read, the answer says which part and why instead of printing a shorter list. The same decision covers the group questions the owner then measured falling to the model ("which github tools do you have", "what note tools are there", "show me the email tools", "which tools work on notes"): a group is answered from the SAME partition and the SAME bullet renderer, so a group answer and the full list cannot disagree, and an alias table (`_TOOL_CATEGORY_WORDS`) only supplies the owner's words - never a tool or a category. The asks-first page's own `TOOL_GROUPS` was checked first and rejected as this map: its eight switch panels put 43 tools under "Jarvis's own tools" and six tools in no panel, so "which github tools" would have listed forty-three unrelated ones; `jarvis_tool_profiles.FAMILIES` is a real partition but keeps GitHub inside "coding" (24 tools, shell_exec and the Android builder included). "Which tools are switched off" is the complement of the same enabled read, because that is the question asked when something is missing; "what tools can change my settings" splits the settings group by each tool's own label, because the gate's `risk_for` has no read-only tier and a gate-based split would need a hand-written action list; and a word that names no group (pictures, photos, audio) answers "no built-in tool" with the nearest real file tool rather than a guess. Enabling or disabling a drop-in plug-in by chat is NOT part of this: its ON path is a `modify_own_code` card and its OFF path writes an off marker, both implemented as the model tool `plugin_switch` inside the agent's card pipeline, and a deterministic chat lane would have to reproduce that pipeline - so it is left out and recorded here rather than half-built.
