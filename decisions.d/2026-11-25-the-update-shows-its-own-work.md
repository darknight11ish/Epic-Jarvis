- **2026-11-25 — The update shows its own work:** the owner asked for "a pop up with a progress bar" when Atlas updates (2026-11-24, DEF-098), and the honest version of that is one small window opened by `update_both` itself - so the Settings button, the tray row and an approved `desktop_update` card all reach the same window - that draws only numbers the updater already produces: the Python tool's own `fraction`, or its done/total counts when a run gives no fraction, and the desktop package's bytes. It deliberately does not draw a guessed percentage: before the first real event the bar is empty and the page says nothing has been measured yet, 100% belongs to the tool's clean verdict and never to a timer or a fraction event, and a run with problems never reaches it. The installer's own progress is the one phase it cannot show, because on Windows the installer ends the process that owns the window; so the window says what is about to happen (Atlas closes and starts again) and stops the bar, and the truth of that phase stays on the pending record the next launch already reconciles and reports. The window only reports: it holds no command, adds no way to start an update, does not change the App lock on the tray or chat doors, keeps Settings' existing bar working, and says in words that closing it does not stop the run. Nothing of the owner's - no note text, no file path from their own data - can reach it or a log line; it shows fixed words, counts, byte totals and the tool's failing file names and reasons, the same words Settings already shows.
