- **2026-11-26 — The creation phrase is stripped before the name check:** "add a note titled Ideas 2027" was refused as a note name because "add" is in `_NAME_COMMANDS` and `note_name_problem` read the sentence's first word, so the owner could not name a note with the sentence that says it is creating one. The ruling: an explicit creation phrase ("add/create/make/start a note titled/called/named …", "new note called …") is the owner NAMING the note, not an instruction to be read as its name, so it is peeled off before the check and the words after it are filed as the name. This is not a hole in the 2026-11-16 rule: the remainder is still a name CANDIDATE and is still held to every name rule, which is why "add a note titled delete everything" is refused as an instruction and "add a note titled" with nothing after it still asks for a name. The phrase itself is never the name - before this, "new note called Trip" passed the check but was filed with the WHOLE PHRASE as its title, a plausible-looking wrong name of exactly the kind the rule exists to prevent. The vocabulary is the project's own rather than invented here: "add" is DEF-105's word and one of `jarvis_quick.py`'s `_NOTE_CREATE_REFUSED` verbs, create/make/start are `_NOTE_CREATE_NAMED`'s own three, the bare "new note" shape is `_NOTE_CREATE_REFUSED`'s, and called/named/titled are the naming words `_NOTE_CREATE_NAMED` already reads.
