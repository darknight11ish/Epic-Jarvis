- **2026-11-26 — Hey Atlas accepts the old spoken name, one way:** The owner ruled that a PC configured `[voice] wake_phrase = "hey_atlas"` must accept "Hey Jarvis" as a legacy alias, with NO expiry and NO switch, and that a PC configured `hey_jarvis` must not accept "Hey Atlas". The gap was in the transcript second opinion, not the spotter: the PC re-reads every wake clip and refuses one whose transcript does not start with its own configured phrase, so once the shipped phrase moved to Atlas a clip transcribed "Hey Jarvis" - the name the owner had been saying - was refused. `jarvis_wakeword._NAMES` now maps `hey_atlas` to BOTH names (its own `atlas`, plus the old `jarvis` spellings) and `hey_jarvis` to its own name only, so the alias is deliberately ONE WAY: a PC still on `hey_jarvis` runs the old acoustic model, a transcript saying "Atlas" is not a hearing it has, and accepting those words would claim one. An unknown phrase still maps to the never-matching `_NO_NAME`, so a typo in the config still wakes on nothing. The alias is not a configuration: it is the product's name staying reachable to the owner's old words, so there is no setting, no expiry and nothing to turn off. It changes nothing a surface SAYS - the reported phrase and title remain the PC's own configured phrase, and no copy, chip, API field or `jarvis-desktop/tests/wake-copy.mjs` was touched. What it does not do, stated so nobody over-reads it: it widens only the transcript check, never the spotter (the wake path asks for the words only after its own spotter said the clip sounded like the configured phrase, and the `hey_atlas` model's response to a recording of "Hey Jarvis" is unmeasured here), and it does not add an Atlas word to a `hey_jarvis` PC.
