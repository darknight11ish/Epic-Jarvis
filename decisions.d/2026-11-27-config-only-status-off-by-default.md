- **2026-11-27 — A config-file-only feature says so in its Status line, and is never called "No Switch Needed":** the owner's ruling Q3 of 2026-11-27. A feature that exists in code but is off by default with no switch of its own is not a Command-Only ability that "runs when you ask": the price radar ships `[price_radar] enabled = false`, and turning it on is a hand edit of `jarvis-framework.toml`, so the derived Status line was false in the one place the owner reads a feature's kind. The Status line for such a row is now a display override, "Off by default (config file only — no in-app switch yet)", exactly the shape the phone-only and App-lock rewords already use; `label_for()`, the five owner-approved label strings, both apps' directory data and the counts `tools/check_feature_controls.py` pins do not move. A row qualifies only from its own catalogue words — its `where`/`asks` names a `[section] key = value` settings-file line AND says there is no in-app switch or screen — so no row id is hardcoded, and the rule covered four rows on the day it landed (price radar, product check, call recording, vault organizer). A row that also names an in-app switch keeps the old label on purpose: reverse-engineering needs `rea_investigate` in Settings as well as `[rea] enabled = true`, and phone-apps needs `control_phone`, so "config file only — no in-app switch yet" would be a new lie for either. The separate switch and catalogue work that gives the price radar an in-app switch belongs to its own lane and is not part of this ruling.
