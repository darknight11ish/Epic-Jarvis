- **2026-11-27 — DEF-110 — the voice-upgrades suite owns its config instead of inheriting one:** measured on this PC, `backend/test_voice_upgrades.py` was **325 passed, 1 skipped, 1 failed** at the desk and **326 passed, 0 failed** with `JARVIS_CONFIG_DIR` and `OPENJARVIS_CONFIG_DIR` pointed at a temp folder — which is exactly what `.github/workflows/ci.yml` does for the required `backend-windows` job. The failing check was *"one sentence reads the built-in voice once, so a face change halfway cannot mix two animals"*, and it failed because the desk run let the modules read the owner's real config while the runner handed them an empty one. **The fix is in the suite, not the check:** it now creates its own throwaway folder and sets both variables **before** importing `jarvis_voices`, `jarvis_speech`, `jarvis_wakeword`, `jarvis_bakeoff` and `jarvis_voice_flow`, so the check runs against the same empty config on both machines. **Why this is a defect and not a flake:** a green CI result that cannot be reproduced at the desk is the same false confidence as a test that cannot fail, and this project has been bitten by environment-shaped greens before. The rule it restates: a suite owns everything it depends on, including the environment it reads.
