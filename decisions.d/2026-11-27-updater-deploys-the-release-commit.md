- **2026-11-27 — The updater deploys the release's own commit, not the checkout:** the owner's ruling Q5 of 2026-11-27, written after DEF-099 measured the failure: launching desktop 0.2.519 auto-ran `tools/update_backend.py` and it deployed the program folder's own `HEAD` — the stale local checkout `cac8a8824` — while the desktop half was the published release `e719ccbf4`. The updater now resolves the commit first: `latest.json`'s `commit` (the desktop's own release feed, whose URL is read from `tauri.conf.json` so no second host and no second copy of it exists), else `origin/main` after a read-only `git fetch origin`, else nothing is deployed and a plain sentence says what could not be read. The bytes come from a clean detached worktree at that commit, shared with this repository's object store, removed on every exit path, and the whole run reads it — patcher, deploy, live-file check, the proof, the look spec and the tool defaults — so no two steps can read two trees. The owner's checkout is never read as the source of truth and never modified (`git fetch` writes no working-tree file). `--ref HEAD` / `--ref <branch>` is deliberately reserved for a developer's own CLI run and the app-triggered path cannot pass it: the desktop's `tool_args` has no `--ref` and no field that could add one. A deploy-managed install that cannot be pinned refuses rather than falling back, because that silent fallback is the defect itself; a patch-only install that could NOT be pinned keeps today's behaviour and says out loud that it is using the folder it always used. When a pin succeeds the patch route reads the clean copy too - not through a repo-path parameter it does not have, but because `scripts/apply-patches.ps1` takes its own scripts, its patch list and the desktop's `Cargo.lock` from the folder it sits in, so the pinned copy's own patcher is the one that runs. The desktop-side half of DEF-099 (comparing the two commits in `backend_self.rs`, so two halves on different commits cannot read IN SYNC) is not part of this and stays open.
