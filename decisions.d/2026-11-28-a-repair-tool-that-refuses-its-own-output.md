- **2026-11-28 — a repair tool that refuses the gate it just wrote, and why the fix is a measurement and not a looser check:** the Price Radar switch added two repairs to `tools/repair_live_backend_gaps.py` (`price-radar-risk`, `price-radar-no-rule`), which grew the owner's live gate by 1,043 bytes to 244,331 B. The tool applied both, reported `ok … already present` for the other fourteen, and then **refused its own output** — `REFUSED: … this is a live-lineage gate this repair does not recognise (sha256 eef45cf4…), nothing was written and the hash is not guessed at`, exit 2. This is **DEF-110 exactly**, one repair later: that row exists because the same tool refused the same way after the previous nine-row repair, and its fix was to measure the new bytes and list their hash. **The choice on the table was to relax the guard so an unrecognised gate is merely warned about, and that was refused:** the guard is the reason this tool cannot quietly edit a gate lineage it does not understand, and a warning would trade a two-line pin for the exact failure the guard exists to prevent. Instead the new hash is listed beside the previous one, with the byte count, the measurement time and the observation that every other repair had already said `already present` — so the next reader can see that this is the tool's own output and not an unknown install. **The lesson is structural, not local:** any tool that pins the hash of its own output must be updated by whoever adds a repair, and the pin's own test should fail when a new repair lands without it. Until then the exit code lies to every caller, including the app's update button.
