## How this audit was done

Five passes, each with the previous bug audits in hand
(`BUG-AUDIT-2026-09-26-*`, `BUG-AUDIT-2026-09-27-*`, `AUDIT-2026-09-28-*`,
`docs/audit-reports-2026-09-29-30/`, and the two 2026-10-04 handoffs):

1. **Backend Python** - logic, crash and error paths, Windows traps, concurrency,
   patch-stack integrity, security-relevant code.
2. **Desktop front end** - state, DOM, event stream, number formatting, layout,
   accessibility, and whether the 143 test suites have teeth.
3. **Desktop Rust** - panic paths, blocking on the async runtime, Windows-only
   code, resource lifetimes, command/ACL correctness.
4. **Android Kotlin** - lifecycle, recomposition, threading, services and
   notifications, networking, crash paths.
5. **Cross-cutting, run by hand** - a static sweep of all 514 Python files, a
   patch-coverage check against the owner's live backend, DOM-id and
   accessibility checks on the ten desktop pages, a review of every silent
   `except` in the eighteen safety-critical modules, and a "can this suite
   actually fail?" check.

Findings are marked **Confirmed** (traced or reproduced), **Likely**, or
**Suspicion**, and rated Critical / High / Medium / Low by what they cost the
owner. The five passes' results follow in Part 2.

### 1.2 Finding: two docstrings carry unescaped backslashes, so every compile warns

- **Where:** `backend/eval_quiz_grader.py:4` (`--backend-dir C:\path`) and
  `backend/jarvis_secret_rules.py:14` (the note "4 `\z` -> `\Z`").
- **What happens:** importing or compiling either file prints
  `SyntaxWarning: invalid escape sequence '\p'` / `'\z'`. On Python 3.12 this is a
  warning; it is scheduled to become an error in a future release, at which
  point **the module stops importing** - and `jarvis_secret_rules.py` is the rule
  table behind the screen-secret blackout, so that is a safety path failing to
  load, not a cosmetic one.
- **Confidence:** Confirmed (reproduced by compiling both files).
- **Fix:** make both docstrings raw (`r"""`) or double the backslashes. Two
  characters each.
- **Severity: Low today, Medium on the day Python enforces it** - and it is the
  cheapest fix in this audit.

### 1.3 Finding: a desktop build leaves three files modified in git

- **Where:** `jarvis-desktop/src-tauri/permissions/autogenerated/{get_faq,get_tutorials,mark_tutorial}.toml`
  are modified in the working tree right now.
- **What happens:** the only difference is a **trailing newline** - `git diff`
  shows "\ No newline at end of file" on the committed side. `build.rs`
  regenerates these files without the final newline, so after any desktop build
  the tree is dirty and the owner sees three "changes" that are not changes.
- **Why it matters:** this project's whole workflow is "check `git status`, then
  commit deliberately". Three phantom modified files every build is the kind of
  noise that trains someone to ignore `git status` - and worse, a real change
  could be committed inside the noise.
- **Confidence:** Confirmed (`git diff`).
- **Fix:** have `build.rs` write the trailing newline, then commit the three
  files once.
- **Severity: Low**, but it is a two-line fix with a disproportionate payoff.

### 1.4 Observation, not a bug: 499 silent `except` sites across 147 modules

The count is high (`except Exception: pass`), concentrated in `jarvis_agent.py`
