## 2. The rules that gate a merge

- **SIX required checks**: `rust`, `frontend`, `backend`, `backend-windows`,
  `credential-manager`, `powershell-5`. **`audit` and `python-advisories` are
  INFORMATIONAL** — a red `audit` is a signal to fix main's own state, never a
  reason to hold a PR.
- **Editing anything under `backend/` is a TWO-FILE change** — the repo copy and
  its `jarvis-backend/` twin. `backend/test_base_matches_repo.py` proves it
  (20 passed, 0 failed).
- **`.github/workflows/ci.yml` belongs to the Lead.** Ask; do not edit it.
- **`backend/run_suites.py` must never be run by hand.** It is what CI's Ubuntu
  `backend` job runs; it takes ~40 minutes and hammers the machine.
- **The Python backend lives outside this repo** (`docs/ARCHITECTURE.md` §9);
  `backend/*.patch` are applied with `scripts/apply-patches.ps1`.
- **`cargo test` OOMs.** Use `cargo check --offline`.
- **BLOCKED and NOT-TESTABLE are never passes.** A feature that could not be
  reached is never counted as one that worked.

## 3. Traps — each cost real time tonight

**Every one of these was found by comparing against a second source. Not one was
found by careful reading.**

1. **THREE dots.** `git diff --stat origin/main...HEAD`. Two dots shows main's
   newer work as *your* deletions (measured: 18 files/−1644 vs 5 files/−9 on the
   same branch).
2. **`git grep` reads the working tree.** Use
   `git grep <pat> origin/main -- <path>`.
3. **A push to an EXISTING PR's branch cancels its run; a NEW branch cancels
   nobody's.** Before pushing over a `pending` run:
   `gh run list --branch <b> --json headSha,status` — **if it is testing the head
   you are replacing, the push is free.** (One branch on the board collected four
   cancelled runs from ignoring this.)
4. **"It passes here" is not evidence about CI** when the checker inspects this
   PC. `check_lanes.py` reads the Task Scheduler and `127.0.0.1`; it can only
   ever skip on a runner — **so it skips, with a printed reason.**
5. **Four counting traps, all the same failure — counting mentions when the
   question was execution:**
   - a name in a workflow is not a run (discriminate on the line);
   - `--log-failed` collapses `::group::` blocks — read the **check-run
     annotations** and the job's **step list** instead;
   - a name in a **skip list** reads exactly like a name in a run list;
   - a job that calls a runner naming everything **names almost nothing** — so a
     name-based census reports all of its suites as unrun.
6. **Every bucket returning 0 is the instrument failing, not a clean tree.**
   A census is a checker: **a check that cannot fail is not a check.**
7. **A closed fold is invisible to a string enumeration.** "The words are absent
   from 2,067 strings" is a claim about the enumeration until the fold is opened.
8. **A field name is not a location.** `can_change` lives in
   `backend/jarvis_chatbot_limits.py`, not in the routes file where the *words*
   live. Cost: two people grepped the wrong file in one night.
9. **A control that expects the same verdict from both controls cannot express
   the failure it exists to catch.** Two different expected verdicts, or it
   proves nothing.
10. **A claim about a tree is only valid against the base it was measured on.**
    A union proof, a count, a diff — re-derive it against the new base or say it
    was measured against the old one.
11. **`NODE_PATH` does nothing for ESM `import`.** This repo is `"type":
    "module"` throughout.
12. **A mutation that does not apply produces a green that means nothing.**
    Check the pattern matched before believing the result.
13. **PowerShell:** `$pid` and `$job:` break (automatic variables, and `:` after a
    variable name); a script header that is prose **runs the prose as commands**.
