# Jarvis Android app: UI audit, 2026-09-23

All file paths below are inside `jarvis-client/app/src/main/java/com/jarvis/client/` unless they say otherwise. `build.gradle.kts` means `jarvis-client/app/build.gradle.kts`. Every finding in this report was checked by a second reviewer against the code as it is today. Screen sizes quoted in dp (Android's screen-size unit, about 1/160 of an inch) are worked out from the code. Nobody measured them on a phone.

---

## 1. The short version

- **The latest Home change (commit 395a526) doesn't do what it set out to do.** The face's area grew to 3/4 of the screen, but the face itself is still a fixed 260dp square. On the light theme (Daylight) it shows as a hard black box. Nobody saw this on a phone before it shipped.
- **Home no longer shows whether Jarvis is connected.** The words "Offline" and "Stale — reconnecting" were in the bar that 395a526 now hides. The approval card still blocks you from acting (rule 4 holds), but the main screen is now showing old data without saying so.
- **Some things can no longer be reached, and some are hard to act on.** The hidden bar opens only with a swipe on a faint 20dp strip, and screen readers can't find it at all. Once the phone is paired, there is no way to pair it again. An approval opened from a notification appears with its Approve/Deny buttons below the bottom of a very small window.
- **The app sometimes says things that aren't true.** Mind says "Not available on this backend" when a request simply failed. That includes the rush-latch check (the server's "slow down, something is urgent" lock), so its banner can disappear while the screen says "Live." Appearance says "Nothing here is sent anywhere", but your face and colours are synced to your desktop. Two FAQ answers are wrong.
- **The plan:** one look called *Instrument Deck*. It has an always-on status line, the face set into a dark gauge, visible panel edges and one typewriter-style font for readouts. It comes with four one-tap presets and about ten fine controls that change only how the phone looks. Phase 1 fixes the honesty and reachability problems and can ship as one update.

## 2. What is broken or risky right now

### 2.1 The face didn't get bigger, and on Daylight it's a black box (visual-1, high)
- **Evidence:** `ui/screens/HomeScreen.kt:311` `modifier = Modifier.weight(faceFraction).fillMaxWidth(),` against `HomeScreen.kt:476` `modifier = Modifier.size(260.dp),` (the same line appears on the removed side of the 395a526 diff). `face/FaceView.kt:703` `drawRect(background, size = Size(size.width, size.height))`. Daylight colours are at `ui/theme/Themes.kt:170,174`.
- **What happens:** The face's area (the "pane") is now about 500–580dp tall, but the face inside it is still 260dp, so you mostly get empty space. The pane has no background of its own. The dark "well" colour (`Chrome.well`, the near-black ground the face is drawn on) is painted only inside the 260dp square. On Daylight that makes a sharp-cornered `#04070C` square on a light `#EEF1F6` background, which looks like a rendering bug. Drag the pane shorter than about 310dp and the square gets squashed into a letterbox, which squeezes the chip showing where the request runs (the "lane chip") and the caption underneath.
- **Fix:** Paint the whole pane as the well: clip it, fill it with `chrome.well`, and give it a 1dp border. Let FaceView fill the pane. It already scales itself to the smaller side (`FaceView.kt:692`). Keep a cap on the face's size, because a bigger face costs frame time. Make the GL faces (Tokamak, Membrane) clear to `well` as well. `FaceView.kt:83-86` says they "still clear to [Spec.BACKGROUND]".

### 2.2 Home hides the connection status (visual-2, high)
- **Evidence:** `HomeScreen.kt:245` `var topBarVisible by remember { mutableStateOf(false) }`. `HomeScreen.kt:621` `state.stale -> chrome.warnMark to "Stale — reconnecting"`. `JarvisRuntime.kt:1383-1385` `the face holds whatever it was doing; the link bar already says "Reconnecting" in words, which is the honest place for that news.`
- **What happens:** The app's own design counts on that bar to report link trouble in words. The face deliberately doesn't change for the first 12 seconds of an outage. After 180 seconds it switches to BANKED, which means "nothing is wrong". A stale stream on a live connection never changes the face at all. With the bar hidden, Home now shows no words at all about Offline, Stale or Retry. That goes against the rule written in `ui/parts/Parts.kt:196-199`: "a screen that shows last-known data and does not say so is the one thing that rule cannot tolerate."
- **Fix:** A thin status line (28–32dp) that is always shown above the face, for example `LINKED · LOCAL · <model> · 2 WAITING`. It turns amber for `STALE — RECONNECTING` and red for `OFFLINE`, with a Retry button. Only the navigation row stays hidden. The code that picks the dot colour and the words already exists (`HomeScreen.kt:619-634`), so this is mostly moving code.

### 2.3 The top strip and the resize handle can only be swiped, are hard to see, and screen readers can't find them (visual-3, high)
- **Evidence:** `HomeScreen.kt:407-409` `.pointerInput(visible) { ... detectVerticalDragGestures(`. `HomeScreen.kt:433` `Box(modifier.height(20.dp), contentAlignment = Alignment.Center)`. `HomeScreen.kt:423` `Grabber(color = chrome.textLo, alpha = if (visible) 0.25f else 0.55f)`. `ui/theme/Chrome.kt:75-77` `WCAG 1.4.11 wants 3:1`.
- **What happens:** From Home, Inbox, Appearance, Help and Checks can only be opened by dragging a 20dp strip. Tapping it does nothing. TalkBack (Android's screen reader) can't find it because it has no label. The small grab bar ("pill") on it measures 1.32:1 to 2.27:1 against the background. The app's own rule asks for at least 3:1 (WCAG, the web accessibility standard) when something is the only sign that a control exists. The resize handle has the same problems.
- **Fix:** Make both handles open or close on a tap as well as a swipe. Give them a screen-reader label ("Navigation", shown or hidden) and make them 48dp tall. Draw the pill in `chrome.hairlineFocus`, which measures 4.15:1. Give the resize handle two screen-reader actions, "Bigger face" and "Smaller face", and let a double-tap reset it.

### 2.4 An approval opened from a notification appears with Approve/Deny off-screen (home-3, high)
- **Evidence:** `HomeScreen.kt:96` `private const val DEFAULT_FACE_FRACTION = 0.75f`. `HomeScreen.kt:323-324` `modifier = Modifier.weight(1f - faceFraction)... vertical = 14.dp`. `HomeScreen.kt:289` `listState.animateScrollToItem(leading + index)`. `ui/approval/ApprovalCard.kt:390-399` puts the buttons at the bottom of a tall card.
- **What happens:** With the face at 75%, the conversation list gets roughly 130dp (worked out, not measured). An approval card is several hundred dp tall. Tapping "Open the approval" scrolls the top of the card into view, so Approve/Deny sit below the bottom edge. The 8-second highlight (`MainActivity.kt:1137` `FOCUS_HOLD_MS = 8_000L`) can run out while the owner is still scrolling.
- **Fix:** When an approval is opened, or the first one arrives, shrink the face to its minimum (20%) and restore your own layout once no approvals are waiting. This only moves the layout. It never decides anything.

### 2.5 Once paired, the phone can never be re-paired (screens-1, high)
- **Evidence:** `MainActivity.kt:282` `var paired by rememberSaveable { mutableStateOf(JarvisRuntime.isPaired()) }`. `MainActivity.kt:597` `paired = true` is the only place that sets it. `JarvisRuntime.kt:429-430` `"The desktop refused that token. Check it in the HUD's settings and paste it again."`
- **What happens:** If the desktop's token changes, or you move to NordVPN Meshnet (which gives the desktop a new name), the app tells you to "paste it again" but gives you nowhere to paste it. The only way out is Android Settings → Apps → Clear storage, which also wipes your theme, face and colours.
- **Fix:** Add a "Connection" card at the top of Platform checks with a "Change desktop or token" button that opens the Pairing screen again with the host already filled in. Keep the old token until the new one works. When the desktop rejects the token, go straight back to Pairing.

### 2.6 "Loading", "failed" and "not supported" all look the same, so the rush-latch banner can silently disappear (screens-3, high)
- **Evidence:** `JarvisRuntime.kt:1070` `private fun <T> ApiResult<T>.orNull(): T? = (this as? ApiResult.Ok)?.value` (every failure becomes "nothing"). `ui/screens/BrainScreen.kt:722-724` `"Not available on this backend."`. `BrainScreen.kt:150` `rushOf(brain.contentRisk)?.let { rush ->`. `ui/screens/InboxScreen.kt:88` `Freshness(link, stale)` with `Parts.kt:202` `fetchedAtMs: Long = 1L`, which makes it read "Live." `InboxScreen.kt:252` `"Nothing waiting."`
- **What happens:** If the rush-latch check times out, the banner just isn't drawn, and the line above it says "Live." You are told nothing is raising the approval level when the phone actually doesn't know. Inbox says "Live. Nothing waiting." before its first read finishes, and again after a failed read.
- **Fix:** Give every section four clearly different states: "Reading…", "Could not read this: <reason>" with a Retry button, "Not on this backend", or the data. For the rush latch, keep showing the last one seen along with its age. If the check fails, show an amber "Could not check for a rush latch". It must never show nothing.

## 3. The design direction: *Instrument Deck*

**The idea:** the app is a precision instrument panel. The face is the main gauge, set into a dark recess. Around it sit machined panels with thin visible edges, readouts in a small uppercase typewriter-style font (a "mono" font, where every letter is the same width), and one accent colour. It looks futuristic because it is precise and always honest about its state. It gets none of that from glow, blur or particle effects, which the frame-time price list rules out (perf-14: live blur costs about 8–20ms a frame, and the visual spec bans full-screen overlays and film grain on the phone).

**Four rules for the whole look:**
1. **Status is always visible.** Link, where the request runs (local or cloud), model and the waiting count are always on screen, in words, never shown by colour alone.
2. **Edges, not shadows.** Every panel ("plate") gets a 1dp line around it. Optionally it also gets a 1dp highlight along its top edge.
3. **Two fonts with clear jobs.** A normal font for reading, and a mono font for readouts: numbers, counts, model names, countdowns.
4. **One moving thing at a time.** The face is the only thing that animates all the time. Everything else moves only when something happens, like a screen change or a countdown tick, and every animation follows the Motion setting.

**Screen by screen:**

| Screen | What changes |
|---|---|
| **Home** | Status line always at the top. Face pane becomes a full "well" with a rim, plus an optional still ring of tick marks around the face (drawn once, costs nothing per frame). The face shrinks on its own when the keyboard is open or an approval is showing. Your question appears as a "You" line above the reply, and the list follows the reply as it streams in. Handles are tappable and 48dp tall. |
| **Approval card** | Moved onto the shared building blocks: no Material ripple effect, the shared shapes, and drawn icons in place of the ✋ emoji. The countdown becomes a mono `00:43` with a thin bar along the top edge that shrinks each second. Swiping shows APPROVE or DENY behind the card. The gates (stale block, fingerprint) stay exactly as they are. |
| **Mind** | The status line splits into "Link live · board read 2 min ago". Every section shows loading, failed, absent or data clearly. One large number per plate (for example "3 / 5"). Keep and Discard dim when the stream is stale. After a model switch, a "Waiting for your approval → Open the card" line appears. |
| **Inbox** | Error messages show on this screen. Section titles use the shared style. The mute switch becomes the new Toggle part. |
| **Appearance** | The Switch becomes the Toggle part. The theme list gets a drawn check mark. The face picker shows small still pictures of each face instead of 20 name-only chips. Settings split into "On this phone" and "Shared with your desktop". |
| **Checks** | A "Connection" card comes first. Cards with warnings come before OK cards. Each card starts with one plain sentence, and "Technical detail" is hidden behind a tap. Each fix button sits inside its own card. |
| **Pairing** | The wordmark uses the app's own display style. The host you typed survives a visit to Checks. Help can be opened before pairing. |
| **All sub-screens** | Titles match the nav labels ("Mind", "Help"). A drawn back chevron replaces "← Back". Screen changes fade and slide, and the back swipe previews on phones that support it. |

## 4. Make it yours

Everything here changes only how the phone looks. Nothing changes the desktop's settings. It is stored as one "look" record next to the theme in `AppearanceStore`, separately on each phone. The face and state colours remain the part that syncs with the desktop, and Appearance will now say so honestly.

**Presets (one tap each).** Changing any fine control switches the label to "Custom (from Focus)" and shows a "Back to Focus" button.

| Preset | What it sets |
|---|---|
| **Focus** (default) | Face 75%, nav row hidden until swiped, the theme's own glow, motion follows the phone, Comfortable spacing |
| **Conversation** | Face 35%, nav row always shown, Compact spacing |
| **Night** | Ember Dusk theme, glow 0.6, Calm motion |
| **Outdoor** | Daylight theme, nav row always shown, text 110% |

**Fine controls ("Adjust" section):**

| Control | Options | Default |
|---|---|---|
| Face share of Home | slider 20–85%, remembered across launches | 75% |
| Face size | Standard 260dp / Fill the pane | Standard (see decision 1) |
| Navigation row | Hidden until swiped / Always shown | Hidden until swiped |
| Glow | 0.25–1.0 (can only go down from the theme's level) | 1.0 (the theme's own) |
| Motion | Follow phone / Calm / Full | Follow phone |
| Density | Comfortable / Compact | Comfortable |
| Shape | Rounded / Sharp | Rounded |
| Text size | Follow phone / 90–130% | Follow phone |
| Panel edges | Hairline / Bevel / None | Hairline |
| Readouts | Mono / Sans | Mono |
| Screen transitions | Standard / Off (forced Off if the phone asks for less motion) | Standard |

**Behaviour switches (all default On unless noted):** Make room for approvals · Shrink face while typing · Follow the reply as it streams · Tap the face to: Open Mind / Do nothing (default Open Mind) · Theme for dark mode: the last dark theme you picked (default Reactor) · Smooth motion: Off / Auto / Always max (default Auto) · Refresh Mind while open: Off / 30s / 60s (default Off).

**Not a setting, on purpose:** the status line. It is how rule 4 shows on screen, so it cannot be turned off. Glow and Calm motion can only *reduce* brightness and speed, so the flash limits in `face/Spec.kt` are never put at risk.

**Face editor (added later the same day, at the owner's request).** The reactor kit's own controls, in one dropdown on Appearance that starts closed: State (preview only), Pattern and Colour (these edit the shared state colours), Auto adjust, Quality (Low / Medium / High / Max), Frame rate (Auto / 60 / 120 / Max), All speeds (¼× to 2×), Battery saver, Randomise and Reset. Quality, frame rate, speed and the two switches are phone-only. Two notes against the paragraph above: All speeds *can* speed the face up, to at most 2× (the kit goes to 3–6×); the state colours' flash limits still apply, and Calm motion and Battery saver still cap it at 1×. And High, the default, is exactly the detail the phone drew before; Auto adjust (on by default) steps down to Medium or Low when frames run late. The rules are in `face/FaceBudget.kt`.

## 6. Decisions for you

**1. How big should the face be by default?**
- **Keep it at today's size until your phone proves it can handle more** (recommended): the pane still turns into the dark gauge, and "Fill the pane" becomes the default once Checks shows the frame rate holding.
- **Fill the pane now**: it looks bigger straight away, but each frame costs about 2.4 times as much to draw, and that has not been tested on your phone.

**2. Which font should the app use?**
- **Bundle IBM Plex Sans and Plex Mono** (recommended): a consistent, technical look. You download the free font files and put them in `res/font/`, because this environment can't download them.
- **Keep the phone's built-in fonts**: nothing for you to do, but the app looks more like a stock Android app.
