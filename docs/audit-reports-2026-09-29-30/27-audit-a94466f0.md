FINDINGS, worst first

1. BUG: the email-reading switch does nothing.
   - `jarvis_asks_first.py:272` lists `TOOLS_SWITCHABLE = ("calendar_read", "email_read", ...)`. `email_read` is the gate action name, but the tool's real name is `email_check` (`jarvis_agent.py:1322`).
   - The route writes "email_read" into `[tools].enabled` (`set_tools_enabled`, `:1125`). `offered_tools` (`jarvis_agent.py:3915`) only keeps names that are keys of `TOOLS`, so it drops "email_read" and the model is never offered email.
   - The app page shows the switch as On, because `"on": tool in enabled` at `:1313` finds the name it just wrote. Meanwhile "What Jarvis can reach" looks up `email_check` and still says Off.
   - Because `_tool_switchable("email_check")` is false, that Off line says "file-only - it cannot be switched on from either app" (`jarvis_reach.py:411`). That is wrong.
   - The voice and chat route ("turn on my email") calls the same function, so it fails the same way.
   - Suggested fix: map action name to tool name in `TOOLS_SWITCHABLE`.

2. GAP: web search has no off switch anywhere in the apps. CLAUDE.md says it ships switched on. The only way to turn it off is to edit the toml, and I found no reason for that written down. The best in-app control is "Ask before every search".
   - `never` can only be set in the settings file (`jarvis_asks_first.py:187`: "switched off in your PC's settings file"). So an owner cannot fully stop shell, computer control, GitHub, note writing or search from an app, only make them ask. That may be fine, since a card is required anyway, but it is not written down as a decision.

3. WORDING: a beginner-facing screen shows config jargon. The reach rows say things like `"add \"web_search\" to [tools].enabled in jarvis-framework.toml by hand"` (`jarvis_reach.py:397-415`). Most tools have no in-app path, so this is what the owner sees. Better wording: "This one can only be switched on in the settings file on your PC. Open it from Settings -> More options" (if such a button exists; not checked).

4. GAP: there is no "what can I turn on or off and where" overview for the non-reading tools. The reach page says "file-only" but does not say why, or that the choice was deliberate.

5. Things that look fine:
   - Picture mode reads its switch at use time (`jarvis_screen_picture.py:1139`, `1213`), and turning it off also stops the reader (`:406-416`).
   - Phone notifications and smartwatch use the same on-by-card, off-instantly shape. Server-side enforcement is not checked; the phone service is meant to read the switch.
   - No two-switch disagreements found, apart from finding 1's On/Off mismatch.
   - The `check_parity.py` run was not done in this pass.
