### 3.3 The style probe (what "response style probes" means here)

One question, asked the same way after every row, so the answers are comparable:
**"In two sentences, what would you check first if my PC felt slow?"** Then a
second, preset-specific one:

- `coding` → "Write a Python function that returns the second-largest number in
  a list, then explain the one edge case you handled."
- `agentic_vision` / `browser` → "What would you need from me before you opened a
  web page and filled in a form?"
- `pictures` → attach one screenshot, "What is on this screen?"
- `documents` → paste ~2,000 words, "Summarise this in five bullets."
- `reflect` → "I keep putting off a decision I have already made."
- `fast` → "Name three uses for a paperclip."

## 4. Run order, tripwire, and what a verdict may say

### 4.1 Order (owner clicks; nothing is scripted; one preset at a time)

1. **E1–E6 pre-flight, read-only** (§5). Stop if `tripwire` shows anything, if a
   lane is down, or if the recorded state differs from §2's.
2. **Row 1 `general` as the control.** Click `Use this preset` with General
   already chosen. Expect **no card**, `chosen: general` unchanged. This proves
   the cardless path is not silently carding.
3. **The five cardless capability rows**, one at a time, each reverted to
   General before the next: `agentic_vision` → `reflect` → `pictures` →
   `documents` → `browser`. Expect **0 cards each**. After each: E2 (chosen +
   `presets-active-lane.json` + `model-state.json` unchanged) and the style
   probe.
4. **`general_uncensored`** — expect **1 card** naming that HF ref. If it is not
   installed, mark the row BLOCKED and skip; do not download.
5. **`fast`** — expect **1 card**; `model-state.current` becomes `qwen3.5:4b`,
   lane `coding/11435`. Revert to General afterwards (**1 card** back).
6. **`coding` last** — expect **1 card**, the heavy one, whose text names pausing
   `qwen3.5:9b` on the 2060 and `qwen3:8b` on the 2080 SUPER. Wait for the load
   (~32 s cold), take the style probe, then **revert to General** (1 card) and
   confirm both lanes are back (E5). Coding is last because it holds both cards.
7. **The ten personalities**, in the order of §3.2, one sentence each, one style
   probe each, no cards. Revert to `warm_peer` at the end.
8. **Restore and verify** (§6.3): preset General, model `qwen3.5:9b`, lane
   11436, personality `warm_peer`, manner `warm`, humour **on**, dials as
   recorded, voice as recorded, no pooled lane running, `jarvis-framework.toml`
   hash unchanged.

**Revert between presets.** For every row, "revert" means re-applying the
preset recorded in §2 — today `general` — from the same UI. It costs **1 card**
whenever the model differs from General's, and **0** when it does not. Do not
skip the revert to save a card; a row measured from a dirty baseline is not a
row.

### 4.2 The revert commands, stated exactly

- **The tidy revert (one card, restores everything):** click `Use this preset` on
  the owner's own preset → `POST /api/work/apply {"preset": "general"}`. It stops
  the pooled lane, points chat back at 11436, switches the model, and rewrites
  `presets-choice.json` (`backend/jarvis_presets.py:1137-1263`).
- **The emergency stop (no card, model only):** `jarvis_models.rollback()` —
  tier `auto` by design, "undoing a change you approved is not a new decision"
  (`jarvis-backend/jarvis_models.py:1198-1204`). **It does not restore
  `presets-choice.json` or the lane pointer**, so after using it, still do the
  tidy revert. Use it when a card is stuck or the model is wrong, not as the
  normal path.
- **The heavy-mode escape:** if the pooled lane must be stopped by hand,
  `stop_pooled_lane()` unloads the 30B, stops the server it started and puts both
  lane models back — and raises no card (`backend/jarvis_model_lanes.py:533-560`).
  Prefer the tidy revert; this is for a wedged lane.

### 4.3 The tripwire, and the stop rule

Every model switch writes two audit lines and one file: `tripwire.baseline` for
the **outgoing** model, `tripwire.after_swap` for the **incoming** one with
`broke`, and `tripwire.json` (`jarvis-backend/jarvis_models.py:1150-1175`).

**Stop rule: if any `tripwire.after_swap` in this run reports `broke` greater
than 0, the run stops there** — the current row is **PARTIAL**, the next row is
not started, and the live state is reverted with the tidy revert before anything
else is written down. The module itself says two or three probes is its noise
floor (`backend/jarvis_tripwire.py:313-315`), so a single probe is not proof the
model is broken — but it is proof the row is not a clean PASS, and §1.4 shows a
real 5-of-8 on this PC tonight. Record the number; do not explain it away.

### 4.4 What a row may say

- **PASS** — every link was observed *on this run*: the card count and its text
  matched §3.1; `chosen` equals the id (E2); `model-state.current` equals the
  preset's model; `presets-active-lane.json` equals the preset's lane URL; the
  **served** window was measured (E3), not quoted; the style probe was recorded
  and shows the preset's own policy; `tripwire.after_swap.broke == 0`; the revert
  was observed and verified.
- **PARTIAL** — driven, but one link was not observed or did not match: a window
  that could not be read, a style probe that was inconclusive, `broke > 0`, a
  card that appeared but whose text did not name what §3.1 predicted. **A PARTIAL
  row must say which link failed**, in one sentence, and name the file/line that
  shows it.
- **BLOCKED** — the row could not be reached at all: `#1129` not deployed, the
  model not installed, a lane that would not start, a card that never appeared, a
  settings file that could not be read. **BLOCKED is never PASS**, and it is not
  a failure of the machine until the sentence says why.
- **NOT-TESTABLE** — reserved for the one row this build cannot express at all:
  Coding at 32,768 before #1129. Say "not testable on this build", not "failed".
- **REFUSED / REPEAT** — the owner declined a card by accident. Not a verdict;
  say so, re-apply, and keep that card's id in the notes so the audit log reads
  honestly.

A row is **never** written from the repo's claims. The two failures this project
has paid for before are a claim read as a measurement and two people confirming
the same wrong instrument; §5 is built so the row points at a file and a line.

## 7. Plain-language summary — read this before saying go

**What we are testing.** Jarvis has nine "focus presets" (General, General
Uncensored, Coding, Agentic + Vision, Fast, Reflective Coach, Pictures & Screens,
Documents & Notes, Browser & Forms) and ten personalities. A preset changes
*which model runs and on which graphics card*; a personality changes only *how
Jarvis words things*. Both lists have been in the app for weeks. **No live test
of applying one has ever been written down.** The hardware plate has been read,
and one document checked the persona settings in the files; neither is the same
thing as driving it and hearing the answer.

**What tonight already showed us, for free.** This afternoon, at 14:04–14:10
your time, the Coding preset really ran on your PC and was then reverted to
General. The log proves it: it paused both cards, loaded the 30B model, kept it
for about three minutes, and put General's model back. Two useful things came
out of it. First, **the Coding apply cost two approval cards, not one**, because
the first attempt did not take and the second did. Second, when the switch went
back to General's model, Jarvis's own sanity check reported **5 of its 8 probes
broken** — the Coding model had passed all 8 a moment earlier. We do not know
why, and this plan does not guess; it makes the test measure that number on every
row and stop if it is not zero.

**Two things that will confuse you if nobody says them.**

1. **Five of the nine presets raise no card at all** when you apply them from
   General, because they use the model that is already loaded. Only Coding,
   Fast and General Uncensored change the model and ask you. A preset that
   changes nothing visible except its name has worked.
2. **The file that records your choice can disagree with the model that is
   actually answering.** At 22:09:40Z the choice said `coding` while the model
   answering was General's. The test records both every time, and a row where
   they disagree is not a pass.

**What is not ready yet.** The Coding preset's 32,768-token window is in PR
#1129, which is **open, not merged**. Until it is merged, deployed, and the
backend restarted, that row is marked NOT-TESTABLE — not failed. Everything else
in the plan can run tonight, including Coding at its current 16,384.

**What it costs you.** Roughly 45–60 minutes at the keyboard. You click one card
at a time — three cards for the three presets that change the model, plus one
each time we revert to General, and **none at all** for the five cardless presets
or the ten personalities, which are just chat sentences. We ask one short
question after each row so there is a quoted answer, not a feeling. Then
everything is put back exactly as it is now, and the write-up becomes one
document and one new matrix row — honestly marked, with anything we could not
reach written as BLOCKED.

**The one thing that would make me say stop.** If a card appears that the plan
did not predict, or the sanity-check number is not zero, the run stops there and
we revert. A half-finished evening with three honest rows is worth more than
eight rows that were written from what the code is supposed to do.
