# Hyperframes composition brief: Jarvis v4

## Output

- `composition/index.html` → `jarvis-launch-v4.mp4`: 1920×1080, 30 fps, 30 s.
- `composition/vertical.html` → `jarvis-launch-v4-vertical.mp4`: 1080×1920, 30 fps, 15 s. Render it with `npx hyperframes render -c vertical.html`.
- `jarvis-launch-v4.jpg`: the poster.

## Creative contract

`brag-plan.md` holds the storyboard and the evidence table. That table ties
every claim on screen to the code on the feature branch, with a status for
each (today or ready).

## How to make it again

1. `python3 tools/build_html.py` writes both HTML files from one template.
2. `python3 tools/score.py` writes the music and the glow data from the
   timing tables.
3. Render both cuts. Then remux the score into each file (see the README
   in `videos/`: the renderer once lowered the music), and keep each file
   under 100 MB.

## Implementation

- **One engine for both cuts** (`assets/film.js`). It has v3's structure:
  - One paused GSAP timeline drives a clock, and `render(t)` sets every
    visible value as a pure function of t.
  - Scenes and captions key off `assets/timing.json` and
    `timing-vertical.json`, which are the same tables the score is written
    from.
- **v2's look, rebuilt inside that engine:**
  - slammed capitals with a red and cyan glitch copy;
  - camera punches, a white flash, an RGB split and a two-frame shake on
    the hits;
  - HUD brackets, a scrambled context line, a state dot, the beat index and
    a timecode;
  - scanlines, animated grain and a vignette;
  - the registry's `vfx-anamorphic-flare` block for the outro.
- **The reactor** is the app's own code: `jarvis-desktop/src/faces.html`,
  extracted by `tools/extract-reactor.mjs` from the feature branch. It was
  unchanged since v3.
- **Real screens** (`assets/ui/`): the desktop app's own windows, rendered
  headless from the feature branch's `jarvis-desktop/src`. The data in them
  was generated by running the backend's own functions:
  - `jarvis_focus.Engine` for the focus session and its report;
  - `jarvis_tellme` and the scheduler for the "Tell me when" card;
  - `jarvis_email_send.describe()` for the email card;
  - `jarvis_quick.answer_turn` for the timer answer;
  - `jarvis_sensitive` for the health proposal.
- **Drawn, not captured**, because they are Windows' or Android's own
  screens: the Windows Hello prompt, the Windows notification, and the
  phone with its notification, fingerprint sheet and Stop button. Their
  words come from the code cited in `brag-plan.md`.
- **Captions** show every spoken line, labelled YOU ▸ / JARVIS ▸.
- **Score** (`tools/score.py`): D minor at 120 BPM.
  - Four-on-the-floor kick, a sidechained bass and a plucked arp.
  - Braams and risers into the three big lines.
  - Every sound is synthesised, and placed on the timing table.
  - On ALT+SHIFT+X, one key slam is followed by real silence until the beat
    comes back in.
